# 内容初稿流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 内容初稿流程 --phase start
```

## 1. 总流程说明

1. 接收并校验内容定位
   - 使用内容定位确认后返回的协调器回执，进入 `2.1`；
2. 一次生成框架和完整初稿
   - 使用冻结输入调用初稿提示词，生成框架与正文，并按合同保存为同一版本，进入 `2.2`；
3. 展示并等待决定
   - 展示已保存的当前版本；用户修改时进入 `2.4`，确认并继续时进入 `2.5`；
4. 讨论和修改方案
   - 用户提出修改意见后，进入 `2.4 讨论和修改方案`；
   - 只改框架或正文时，按 `revise_current` 重新准备、生成并保存，再回到 `2.2`；
   - 用户明确要求修改内容定位或媒介形式、内容目标时，按对应上游流程重新生成；
5. 确认并交接下一阶段
   - 用户确认后进入 `2.5 确认并交接下一阶段`，交给内容终稿流程。

### 协调器使用规则

内容定位流程在确认后已经完成 `save` 和 `decide --decision confirm`，并返回内容初稿阶段的冻结输入。正常进入本流程不重复调用 `prepare`。

本流程只使用当前回执中的：

- `current_stage.flow_file`：必须是 `执行流程/内容初稿流程.md`；
- `state_file`：后续 `save`、`decide` 和 `transition` 使用同一个值；
- `inputs`：已确认的内容定位、当前初稿和参考输入；
- `action_contract`：候选文件精确路径、输出要求和 `save` 提交参数；
- `decision_contract`：等待确认、修改或回退时允许提交的决定。

回执为 `ok = false`、当前阶段或流程文件不符、当前步骤所需合同缺失，或 `status = blocked` 时，说明回执中的真实原因并停止。流程不扫描正式资料、不从聊天上下文补齐、不自行拼接路径，也不直接调用底层状态执行器。若输入只有 `snapshot` 引用，必须按引用校验快照路径、SHA-256、状态文件、内容ID、阶段名和阶段版本后再读取。

只有恢复、重新进入、用户要求修改已保存初稿，或协调器明确要求重新准备时，才使用最新 `state_file` 调用 `prepare`。

### 协调器命令

```bash
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action prepare --state-file "<state_file>"
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action save --state-file "<state_file>" --stage-candidate-file "<stage_candidate_file>"
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action decide --state-file "<state_file>" --decision confirm
```

## 2. 具体流程说明

### 2.1 接收并校验内容定位

正常进入时直接使用内容定位确认后返回的回执。

- 当前阶段为“内容初稿”，且 `current_stage.flow_file` 指向本文件；
- `inputs` 中存在已确认的内容定位；
- `status = ready` 时同时存在本轮 `action_contract`，才能生成新初稿；
- `status = waiting_for_user` 时已有可展示的已保存版本和 `decision_contract`，直接进入 `2.3` 展示，不重新生成或保存；
- 其他状态、阶段或输入不完整时停止，不从旧候选、内容记录或聊天摘要补齐。

### 2.2 生成并保存初稿

保存与确认使用协调器：

```bash
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action save --state-file "<state_file>" --stage-candidate-file "<stage_candidate_file>"
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action decide --state-file "<state_file>" --decision confirm
```

#### 生成

收到本轮新的 `status = ready` 回执时执行。用户修改初稿后，协调器返回新的 `ready` 回执，再按本节重新生成。

1. 读取当前回执冻结的以下资料：
   - 已确认的定位；
   - 有对标内容时的借鉴判断（取自内容分析的「借鉴判断」表），以及其他本阶段已冻结的生产资料和参考输入；
2. 读取 `分析框架/内容生产方法论.md` 的 `### 5.2 内容框架` 和 `### 5.3 内容初稿`；
3. 调用 `提示词/内容生产-内容初稿提示词.md`，一次生成框架和完整初稿；
4. 核验：框架与正文一致，正文按框架顺序展开，标题、封面与开头承接同一进入策略。

框架是初稿的一部分，不单独成阶段，也不单独确认。

#### 保存

按 `action_contract.required_outputs` 生成并提交：

1. `stage_candidate_file`：只包含一个 `## 内容初稿` 区块，其中包含内容框架和完整初稿，不写版本标题或其他二级区块；

提交候选后，只有协调器保存成功，才作为当前正式初稿展示给用户；保存失败时，上一版正式初稿保持有效。

### 2.3 展示

保存成功后，固定展示：

```text
## 内容初稿候选

- 内容名称：<内容名称>
- 内容ID：<内容ID>
- 媒介形式：<视频 / 图文 / 文章 / 其他>
- 内容目标：<流量 / 涨粉 / 交易>

### 工作台查看
- 内容生产：<dashboard_base_url>/index.html#creation-board

### 当前版本
<本轮刚保存的完整内容初稿>

### 下一步
如果还需要修改，请直接告诉我；
如果当前初稿已经明确，请回复“继续”，进入内容终稿。
```

展示字段来源：

- `内容名称`、`内容ID`、`媒介形式`、`内容目标`：使用保存或更新成功回执中的 `display_identity`；
- `当前版本`：使用本轮刚保存的正式初稿版本；
- `dashboard_base_url` 只能使用工作台启动后返回的本地基础地址，取址方式固定按 `执行单元/工作台地址获取.md` 执行；取不到地址时写“工作台未打开”，不阻断正式结果反馈。

必须展示本轮刚保存的完整内容初稿；不得用变化点、摘要或“其余保持不变”替代当前版本。

展示后：

- 用户提出讨论或修改意见：进入 `2.4`；
- 用户明确确认当前初稿并要求继续（如“继续”“按当前初稿进入下一步”“初稿可以了”）：进入 `2.5` 确认并交接；
- 用户要求内容审查：按 `执行流程/内容审查流程.md` 手动发起，审查完成后仍回到本节；
- 用户没有明确选择：停在本节，等待用户决定。

### 2.4 讨论和修改方案

用户在 `2.3` 看到当前版本后，在本节讨论问题或提出修改意见。

- 用户没有明确修改范围：继续讨论，不生成或保存新版本；
- 用户明确要修改的问题：记录具体调整要求；这句话本身就是本轮修改指令，不再单独请求“修改授权”，未提出修改的部分保持不变。

按修改内容分两种情况处理：

1. 只修改框架或正文：如修改段落职责、顺序、标题、开头、表述、衔接或结尾，提交当前 `decision_contract` 允许的 `decision = revise_current`。只有协调器返回新的 `status = ready`、冻结 `inputs` 和 `action_contract` 后，才按 `2.2` 重新生成、核验、保存并展示新版本。
2. 修改内容定位、媒介形式或内容目标：说明需要回到内容定位。用户确认后提交 `decision = rework_upstream`，目标阶段为“内容定位”。协调器返回新回执后交给内容定位流程；该流程确认后再按本流程 `2.2` 生成新的初稿。

不能用多个并列版本掩盖定位冲突。信息不足但仍能形成有边界的内容时先给出暂定判断；只有无法形成可执行初稿时才补问一个问题。

### 2.5 确认并交接内容终稿

用户在 `2.3` 明确确认当前初稿并要求继续后，直接使用当前 `decision_contract` 提交 `decision = confirm`，不重复 `save`。

只有确认回执同时满足以下条件，才交给内容终稿流程：

1. `ok = true`；
2. `completed_stage = 内容初稿`；
3. `status = ready`；
4. `current_stage.name = 内容终稿`；
5. 回执包含内容终稿所需的冻结输入。

确认失败时，说明真实原因并停止，已保存初稿保持有效。
