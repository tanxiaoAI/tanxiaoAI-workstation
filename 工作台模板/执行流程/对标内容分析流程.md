# 对标内容分析流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 对标内容分析流程 --phase start
```

## 1. 总流程说明

1. 判断入口
   - 进入 `2.1 接收分析入口`，只接受一条对标内容链接；先规范化链接并按平台 + 平台原生内容ID 判重。
   - 已有正式报告的，直接返回已有结果卡片，不进入分析；只有资料没有报告的，复用资料直接分析；完全没有记录的，先走数据获取再自动回来。
2. 检查并冻结资料
   - 进入 `2.2 检查资料与异常处理`。
   - 检查通过后生成本次运行的输入快照；只有内容身份和内容目录缺失才停止，正文、封面、评论缺失都按有限报告继续。
3. 生成分析
   - 进入 `2.3 生成内容分析`。
   - 不生成内部初判，不生成最小机器候选。
4. 返回结果
   - 进入 `2.4 反馈结果`，反馈正式文件路径、资料告警和真实错误。

每次运行使用独立临时目录，避免并发任务使用同名临时文件。临时目录只保存当前运行需要传给下一步的文件，不是可恢复状态。正式文件和 CSV 提交时才使用短锁、锁内重新读取、冲突检查和原子替换写入；网络、素材读取和模型生成不持有正式数据锁。

内容库是整表重写的，所以「冲突检查」必须按**目标行**判定，不能按整张表判定：只要本次分析的目标行没有被改动，同一张表里其他内容的变化不得中断本流程。目标行的判定依据是分析提交时记录的行指纹，以及输入快照里的冻结行字段。

## 2. 具体流程说明

### 2.1 接收分析入口

本流程只有一条主入口：用户提交一条对标内容链接。不再提供“重新分析”入口，也不在流程中途询问用户是否换源、是否付费、是否继续。

入口只接受以下机器信息：

```yaml
source_url: <对外页面链接，必填>
content_id: <内容ID，可为空；自动交接时使用>
platform: <平台，可为空；自动交接时使用>
title: <标题，可为空；自动交接时使用>
analysis_handoff: <数据流程提交回执中的对象；直接分析时省略>
```

先规范化链接（去掉分享参数、统一短链、补齐协议），再按「平台 + 平台原生内容ID」判重，不使用原始链接字符串直接比较。

```bash
python3 "<工作区根目录>/执行单元/对标内容数据建档执行器.py" \
  --phase inspect \
  --workspace-root "<工作区根目录>" \
  --source-url "<用户提交的链接>" \
  --output-json ".meiling/staging/benchmark-content-diagnose/<本次查重目录>/内容查重结果.json"
```

`<本次查重目录>` 自拟一个不与已有分析运行重名的子目录。`status` 取值决定后续分支：`analyzed` 表示已有正式报告，`matched` 表示已建档但还没有报告，`not_found` 表示新内容，`duplicate_conflict` 表示内容库命中多条。

判重后按下面四种情况处理：

1. **已有正式报告**：内容目录里存在可读的 `内容分析.md`，说明这条内容已经分析过。停止，直接返回已有报告和内容卡片链接，不重新取数、不重新分析、不覆盖正式文件。
2. **已有资料、没有正式报告**：资料够分析（正文可读，或明确标记“确认无正文”）时，直接进入 `2.2` 完成分析，不重复取数；资料不够分析时，按数据获取流程自动补齐，补齐后回到本流程继续。
3. **没有任何记录**：进入数据获取流程取数；数据提交成功后自动回到本流程 `2.1`，使用交接身份继续，不再询问用户下一步。
4. **链接无法唯一对应一条内容**：平台不支持、不是单条内容、明显是账号主页，或内容库里命中多条记录时，停止并报告真实原因；只追问定位唯一内容所必需的信息，不得替用户选择目标。

自动交接时使用 `analysis_handoff.status = ready` 的身份；直接分析时由 `inspect` 返回的身份进入，两者最终都走同一套正式资料检查。

### 2.2 检查资料与异常处理

#### 执行

```bash
python3 "<工作区根目录>/执行单元/对标内容分析前置检查.py" \
  --workspace-root "<工作区根目录>" \
  --content-id "<内容ID>" \
  --platform "<平台>"
```

脚本检查：

- 内容是否唯一匹配；
- `内容ID`、平台、标题、媒介形式和内容目录是否可用；
- 正文是否可读，或是否明确标记“确认无正文”；
- 封面是否存在；
- 点赞、收藏、分享、评论和数据水平是否存在；
- 已存档评论是否可读、样本条数与平台声明是否一致。

#### 成功条件与输出

只有返回 `status = checked`、`analysis_ready = true`、`objective_checks_passed = true`，并提供 `run_id`、`staging_dir` 和 `analysis_input_path`，才进入 2.3。输入快照至少绑定内容库当前行、正文/封面/评论路径、互动数据、缺口和词典文件指纹。

#### 异常处理

- 内容目录不存在、词典缺失或词典字段损坏：停止；
- 正文不可读、没有正文或视频文案未取到：继续，按现有资料出有限报告，正文结构、表达、价值兑现等结论写“信息不足”；
- 评论不可读或没有评论存档：继续，第 5 节写“本次没有可用的评论样本”，不阻断正式报告；
- 封面缺失：继续，后续视觉结论写“信息不足”；
- 互动数据缺失：继续，只限制数据校正结论，不得伪造数据；
- 执行器失败或输出字段不完整：停止，不手工生成替代快照。

### 2.3 生成内容分析

#### 输入

- `分析框架/内容分析方法论.md`；
- 2.2 返回的 `analysis_input_path` 所指向的文件内容；
- 快照 `paths.comments` 非空时，读取该评论存档，作为第 5 节「评论主要在说什么」的唯一证据来源；为空时不读别的文件补造评论。

#### 生成

调用 `提示词/内容分析-生成用户版提示词.md`，一次生成完整的 `内容分析.md` 正文。

模型输出可先写入本次 `staging_dir` 的临时文件 `内容分析.md`，该文件只是提交输入，不是正式结果。

#### 提交

```bash
python3 "<工作区根目录>/执行单元/对标内容分析正式化执行器.py" \
  --workspace-root "<工作区根目录>" \
  --content-id "<内容ID>" \
  --platform "<平台>" \
  --stage analysis \
  --analysis-input-file "<analysis_input_path>" \
  --analysis-candidate "<staging_dir>/内容分析.md" \
  --receipt-file "<staging_dir>/内容分析保存回执.json"
```

提交器只做身份与安全检查：内容身份和**正式目标行的并发版本**。正式目标行的并发版本按行指纹判定：分析提交时把目标行的行指纹写进回执，再次分析同一条内容时重新计算并比对。同一张内容库里其他内容的增删改不影响本步，只有目标行自身变化才算冲突。校验通过后，以短事务原子写入内容目录的 `内容分析.md`，并同步内容库的正式路径。

#### 成功条件与结果传递

只有返回 `status = analysis_committed`、`analysis_path`、`analysis_sha256` 和分析提交回执，才算正式分析完成。

内容身份不符、输入快照过期、正式文件冲突或内容库同步失败时，停止并报告真实错误；不得把暂存文件说成正式分析。

### 2.4 反馈结果

如果 `2.1` 判定这条内容已有正式报告，不进入分析和写入，直接按下面格式反馈，不再展示「本轮状态」：

```text
## 这条内容已经分析过

- 内容标题：<已有报告的标题>

### 工作台查看
- 对标内容详情：<dashboard_base_url>/content?kind=benchmark&id=<账号ID>::<内容ID>

### 正式文件
- 内容分析：<已有正式 内容分析.md 路径>
```

这种情况不重新取数、不重新分析、不覆盖正式文件。用户要求补数据时，按资料缺口走数据获取流程自动补齐；补齐成功后系统自动更新这份报告，不需要用户再决定是否重新分析。

正常完成本轮分析后，使用固定顺序反馈。

```text
## 对标内容分析结果

- 内容标题：<本轮分析内容的标题>

### 工作台查看
- 对标内容列表：<dashboard_base_url>/index.html#benchmark-contents
- 对标内容详情：<dashboard_base_url>/content?kind=benchmark&id=<账号ID>::<内容ID>

### 资料说明
- 封面：<状态及影响>
- 正文：<状态及影响>
- 互动数据：<状态及影响>
- 评论：<一共有 N 条一级评论 / 已获取 x 条，未获取 x 条>

### 本轮状态
- <已完成 / 部分完成 / 未完成>
- 错误：<真实错误；无错误时不展示>
```

Dashboard 链接固定定位到对标内容列表页和当前内容详情页两处，不得改成其他页面。列表页路径为 `index.html#benchmark-contents`；详情页路径为 `content?kind=benchmark&id=<账号ID>::<内容ID>`，其中 `<账号ID>` 和 `<内容ID>` 取本轮分析目标行在 `对标资料/对标内容库.csv` 的 `账号ID`、`内容ID` 原值，中间用 `::` 连接，不加空格、不做手写 URL 编码（内容 ID 为中文时按原值写入）。`<dashboard_base_url>` 只替换为工作台启动后返回的本地基础地址（取址方式固定按 `执行单元/工作台地址获取.md` 执行），例如：

```text
http://localhost:64847/index.html#benchmark-contents
http://localhost:64847/content?kind=benchmark&id=65e548a3000000000500f076::内容108
```

不得把 Dashboard 首页、账号列表、账号档案或其他无关页面当作本流程链接；详情页只能指向本轮分析的那一条内容。占位符只能替换为真实执行结果，不得猜测端口、基础地址、内容身份或正式文件路径。Dashboard 启动失败时两个链接均固定写 `工作台未打开`，不阻断正式分析结果反馈。

本步骤需要的执行器实际结果包括：

- 本轮分析内容的标题；
- 正式 `内容分析.md` 路径（不展示，用于判断是否存在，以及后续选题交接）；
- 封面、正文、互动数据和评论的告警及其影响范围；
- 该内容的一级评论条数：一共有多少条、已获取多少条、未获取多少条；
- 任一步骤的真实错误。

不得把暂存候选或临时文件报告为全链路成功。正式路径只能使用执行器返回值，不由模型拼接或猜测。

同一工作区可能有其他会话在并行运行，最终状态以最后一次成功写入为准；不要把本会话看到的状态  
描述成「工作区当前状态」。若本会话的写入发生在其他会话之后，正常报告；若发生在之前，说明本会话  
看到的是当时的快照。

本轮如果由选题分析流程的参考内容分支触发，不展示下面的“接下来你可以”选择。保留选题分析交来的原 `context_file` 和本轮选题参数，把正式 `reference_analysis_path`、`content_id` 以及已有的 `transcript_path` 交回原上下文，重新执行选题分析协调器的 `prepare`，自动继续选题分析，不等待用户选择下一步。

独立进入本流程且`内容分析.md`存在时，在结果末尾增加固定展示：

```text
接下来你可以：

**做选题分析**
参考这次对标分析，继续判断这个选题值不值得做，以及适合从哪个角度切入。

**直接做内容**
参考这次对标分析，跳过选题分析，直接开始生产内容
```

- 用户选择“做选题分析”：
  - 由公开入口接收用户选择；
  - 公开入口新启动一轮独立的 `topic-evaluate`；
  - 先调用 `执行单元/选题分析流程协调器.py` 的 `prepare`，只传入本次对标流程已经正式保存的参考结果：
    - `reference_url`：对标内容对外链接；
    - `reference_analysis_path`：正式 `内容分析.md` 路径（借鉴判断改从它的「借鉴判断」表读取，不再传特征卡路径）。
  - 选题名称、选题 ID 和本轮问题不由本流程确认；进入 `topic-evaluate` 后，由选题分析流程自己的 `2.1` 负责收集和确认。
  - 如果 `prepare` 返回 `needs_topic_input`，公开入口把返回的 `context_file` 原样交给下一次 `prepare`，用户补充选题名称或 ID 后继续使用同一轮 `run_id`；不得重新创建参考结果或重新调用对标流程。
  - 选题对象确认后，协调器在同一 `context_file` 上完成参考文件检查并返回 `stage_ready`。
  - 不恢复旧的选题任务，不创建父子任务，不向对标内容流程传递选题任务 ID。
- 用户选择“直接做内容”：
  - 由公开入口接收用户选择；
  - 直接调用 `create-content` Skill，并将本次已经正式保存的结果作为当前上下文传入；本流程到此结束，不在本流程调用内容生产阶段协调器。
  - 生产模式由 `create-content` Skill 按自身入口规则确认；如果用户尚未明确选择逐步生产或快速生产，必须先向用户询问，不能在本流程静默指定。
  - 传入的参考内容不得把对标内容 ID 当作我方内容 ID 或选题 ID：
    - `reference_content_id`：对标内容 ID，只用于校验正式参考资料；
    - `reference_analysis_path`：正式 `内容分析.md` 路径，必填；借鉴判断从它的「借鉴判断」表读取，不再传特征卡路径；

---

**本流程结束后执行一次使用统计上报**（静默脚本，失败不影响任何流程）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 对标内容分析流程 --phase end --status ok
```

正常走完用 `--status ok`；按阻断分支收尾用 `--status blocked`。**没走到这一步就不用补报** ——  
缺少结束记录本身就是「卡在这一步」的信号，补报反而会把卡点抹掉。
