# 内容审查流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 内容审查流程 --phase start
```

## 1. 总流程说明

内容审查是挂在内容初稿／内容终稿旁边的可选检查环节，不是必经阶段：

- 只有用户明确要求检查时才执行；
- 只出报告，不改稿、不生成新版本、不改变生产状态；
- 审查发现风险只提醒，不阻断用户确认终稿；
- 报告按轮次保存为 `审查报告-vN.md`，并标明审查对象与平台。

## 2. 具体流程说明

### 2.1 确认审查对象

1. 读取当前正式状态 `当前阶段状态.json`，确认当前阶段是“内容初稿”或“内容终稿”，且该阶段版本大于 0；
2. 读取 `内容生产记录.md`，取当前阶段下的 `### vN` 正文作为审查对象；
3. 当前阶段没有可审查版本时停止，说明“当前还没有可审查的稿件”。

### 2.2 确认审查平台

- 用户已经指定平台时，按指定平台执行；
- 用户没有指定时，只做通用审查，不擅自补平台；
- 首版支持的平台：小红书、抖音、视频号、B站。

### 2.3 执行审查

读取 `提示词/内容生产-内容审查提示词.md`，按提示词要求生成审查报告候选。

平台规范审查必须先检索对应平台的官方政策或官方规则原文：

- 保留政策名称、官方链接、检索时间、相关原文要点；
- 检索不到足够官方依据时写“未查到足够官方依据”；
- 检索失败或无法访问时写“审查未完成”；
- 不得凭模型记忆编造条款，也不得承诺“平台审核通过”。

把报告候选写入本轮独立暂存目录（例如 `.meiling/staging/create-content/内容审查-<时间>-<随机>/审查候选.md`）。候选必须包含 `## 通用审查`；平台规范审查按 `## 平台规范审查` + `### 平台：<名称>` 组织。

### 2.4 保存报告

```bash
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
  --action save-review \
  --state-file "<当前阶段状态文件>" \
  --review-candidate-file "<本轮审查候选文件>" \
  --review-platforms "<逗号分隔的平台，未指定则留空>"
```

协调器会把报告保存到 `过程记录/内容审查/审查报告-vN.md`，并写入审查对象阶段、版本、平台、稿件指纹和审查时间。该动作不改变生产状态。

### 2.5 反馈结果

```text
## 内容审查结果

- 审查对象：<内容初稿 / 内容终稿> v<版本>
- 审查平台：<平台列表或“仅通用审查”>
- 报告版本：v<N>
- 正式文件：<report_path>

### 关键发现
- <最高优先级问题；没有则写“未发现明显问题”>
- <平台规范风险；没有则写“未发现明显风险”，检索失败则如实写“审查未完成”>
```

最后说明：审查结果仅供参考，是否采纳由用户决定；不审查也可以直接确认终稿。
