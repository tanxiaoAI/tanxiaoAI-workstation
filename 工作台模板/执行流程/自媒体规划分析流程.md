# 账号方向分析流程

## 0. 运行约束

本流程开始前先执行一次使用统计上报，结束时再执行一次结束上报。统计脚本失败不影响业务流程，也不得上传账号方向正文或调查问卷内容：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 自媒体规划分析流程 --phase start
```

## 1. 总流程说明

1. 前置步骤
   - 先进入 `2.1 判断入口`；
   - 再进入 `2.2 读取资料`，读取调查问卷、已有账号方向和本轮参考资料；
   - 再进入 `2.3 确定本轮讨论重点`。
2. 对话循环
   - `2.3 确定本轮讨论重点` 选出讨论重点后，先按固定格式向用户说明，再等待用户回应；
   - 用户回应后进入 `2.4 对话讨论`，一次只推进一个主要问题；
   - `2.4` 完成当前讨论后，由 AI 判断是否满足 `2.5 确认是否成稿` 的条件；满足时主动发起成稿确认，不满足时回到 `2.3`；
   - 账号方向中的商业问题在 `产品与变现` 栏目内部讨论，不再调用独立商业模式子流程。
3. 成稿步骤
   - 只有 `2.5` 判断可以成稿且用户明确确认后，才进入 `2.6 成稿并保存结果`；
   - 先生成一份完整账号方向正文，再以该正文为唯一输入重新生成 `我方当前概要.md`；两份内容校验通过后一起保存；
   - 保存器失败时保持原正式文件不变，不报告部分完成。
4. 成稿后分流
   - 保存完成后进入 `2.7 反馈结果`；
   - 反馈正式结果后结束本轮；
   - 用户保存后提出新补充或修改时，作为新一轮回到 `2.3`。

## 2. 具体流程说明

### 2.1 判断入口

先判断本轮属于下面哪一类入口：

- **普通账号方向入口（`normal`）**：用户要首次建立、整体梳理或局部修改自己的账号方向。使用当前对话中用户已经明确的目标和修改范围；首次建立优先依赖固定问卷。
- **对标启发入口（`benchmark_inspiration`）**：用户明确要基于某个已分析对标账号，讨论如何改进自己的账号方向。除本轮目标和修改范围外，保留来源账号、正式分析报告路径、报告类型（概要或详细）和用户想讨论的启发问题，作为本轮对标依据；来源报告只提供外部参考，不等于我方规划结论。
- **自我诊断启发入口（`self_diagnosis_inspiration`）**：用户明确要基于自己账号的最新正式诊断，讨论接下来怎么调整自己的规划。除本轮目标和修改范围外，保留我方账号 `账号ID`、平台、正式诊断文档路径和用户想讨论的启发问题；诊断文档只提供本轮账号实际表现与目标差距的参考，不等于我方规划结论。
- **问卷直出入口（`questionnaire_direct`）**：用户明确要求「按已经填好的问卷直接写出一版方向、不用再问问题」，且本轮没有指定任何诊断文档。这类请求跳过 `2.3`、`2.4`、`2.5` 三道讨论环节：读完 `2.2` 的资料后直接进 `2.6 成稿并保存结果`，问卷没覆盖的地方写「未定」，不推测、不追问、不出讨论重点。`2.7` 按「未经过讨论」那档反馈，只回一行。
- **问卷与诊断直出入口（`questionnaire_diagnosis_direct`）**：用户明确要求「按已填好的问卷和刚跑出来的正式诊断直接写出一版方向、中途不要问他」（例如「绑定并诊断我的账号」那条指令里的第 2 步）。除本轮目标和修改范围外，保留入口带入的我方账号 `账号ID`、平台和正式诊断文档路径（可以有一份或多份）。这类请求和问卷直出入口一样跳过 `2.3`、`2.4`、`2.5`：读完 `2.2` 的资料后直接进 `2.6 成稿并保存结果`，问卷和诊断都没覆盖的地方写「未定」，不推测、不追问、不出讨论重点。`2.7` 按「未经过讨论」那档反馈，只回一行。

用户只是查看、询问或比较对标账号本身时，不进入本流程，直接在当前对话中回答。目标不足以判断是首次建立、整体梳理还是局部修改时，只确认本轮目标，不提前询问方法论中的全部问题。对标启发入口中，用户尚未明确想融合的具体做法时，只确认最想讨论的一个启发问题，不提前询问方法论中的全部问题。自我诊断启发入口中，用户尚未明确想讨论的启发问题时，同样只确认最想讨论的一个启发问题，不提前询问方法论中的全部问题。

### 2.2 读取资料

读取：

- `分析框架/自媒体规划方法论.md`；
- `提示词/自媒体规划成稿提示词.md`（仅在成稿阶段读取）；
- `我方资料/调查问卷.md`（首次建立时读取，作为用户原始回答）；
- 正式方向文件 `我方资料/我方自媒体规划.md`（存在时读取）；
- 派生概要 `我方资料/我方当前概要.md`（存在时读取，用于下游兼容和一致性检查）。

对标启发入口另外读取当前入口已经确定的对标账号正式概要分析或详细分析文档。该文档只作为本轮外部参考，不创建额外交接文件，也不直接当作我方规划结论。

自我诊断启发入口另外读取当前入口已经确定的最新正式诊断文档（`<当前账号目录>/<日期>账号详细诊断.md`，其中账号目录由入口传入的正式诊断路径或我方账号库当前行推导）。该文档只作为本轮外部参考，不创建额外交接文件，也不直接当作我方规划结论。

问卷与诊断直出入口另外读取入口指定的全部正式诊断文档（`<当前账号目录>/<日期>账号详细诊断.md`，可以有一份或多份；账号目录同样由入口传入的正式诊断路径或我方账号库当前行推导）。每份文档只提供对应账号实际表现和已有内容的事实，用来补实 `自身条件` 和 `账号与内容` 两栏；多份诊断之间差异明显时，按账号分别写清，不合并成一个人群；不写成长期目标，也不替用户决定 `用户与需求`、`产品与变现` 两栏的诊断没覆盖的内容。

处理规则：

- 调查问卷不存在、为空或不可读，且完整方向不存在：停止并引导用户先填写问卷；不得按聊天记忆或模型推测生成正式方向。
- 问卷直出入口、问卷与诊断直出入口：新问卷与旧版方向冲突时，以新问卷为准；旧版方向只补问卷没覆盖的细节，不得把旧方向写回去；问卷和旧版方向都没覆盖的内容写「未定」。
- 问卷存在且完整方向不存在：以问卷原文作为首次输入，生成四栏方向初稿；问卷未覆盖的内容保留未知。
- 完整方向不存在但问卷已提交：允许进入讨论，不要求用户一次补齐所有栏目。
- 正式方向存在且可读：作为本轮旧版输入；缺失问卷不阻止已有方向的局部修改。
- 正式方向存在但内容为空：按首次建立处理，但仍必须读取问卷；没有问卷则停止。
- 正式方向存在但不可读：停止在本步，说明无法读取的正式文件；不得把它当成空文件，也不得改用缓存、候选或历史副本。
- 当前概要是根据完整方向重新生成的独立摘要，缺失时可以在下一轮成稿中根据完整方向补齐；不能把概要当作完整方向替代品。
- 对标启发入口的指定正式分析文档缺失、为空、不可读或无法确认属于当前来源账号时：停止本轮，说明对标依据不可用；不得凭聊天记忆继续讨论或成稿。
- 自我诊断启发入口的指定正式诊断文档缺失、为空、不可读或无法确认属于当前我方账号时：停止本轮，说明诊断依据不可用；不得凭聊天记忆继续讨论或成稿。存在多份同日或不同日的正式诊断时，只使用入口已确定的那一份；入口未确定时使用最新一份并向用户说明所选版本。
- 问卷与诊断直出入口的指定正式诊断文档中，任一份缺失、为空、不可读或无法确认属于当前我方账号时：停止本轮并说明是哪一份诊断依据不可用，不得退化成只按问卷成稿，也不得凭聊天记忆补写诊断信息。同一天有多份时，按入口指定的账号和诊断逐一取用。

### 2.3 确定本轮讨论重点

这一步的目标是确定下一轮对话从哪里开始，不检查整份规划是否完整，也不按固定优先级替用户决定先补哪一部分。讨论顺序首先服从用户当前的兴趣点。

按以下顺序确定本轮讨论重点：

1. 用户已经明确提出问题、修改意见或启发来源时，优先围绕该问题开始。
2. 对标启发入口中，用户已经指出想融合的具体做法时，优先讨论该做法对我方规划的影响。
3. 自我诊断启发入口中，用户已经指出想调整的部分时，优先讨论该部分对我方规划的影响。
4. 用户没有明确重点时，根据已读取的我方规划和对标分析或自我诊断材料，提出 `1` 个当前最值得讨论的推荐方向，并可附 `2 至 4` 个有明显区别的备选方向。
5. 每个方向用大白话说明主要要讨论什么、可能影响规划的哪一部分，以及当前最需要确认的取舍；用户可以选择、组合、修改或提出新的方向，也可以暂不决定。

本步骤只确定一个下一轮讨论重点，不把候选方向当成用户已经确认的规划结论，也不在此步骤扫描并补齐所有未知字段。用户明确要求直接生成或修改规划时，进入 `2.5` 判断是否满足成稿条件。

#### 给用户的固定回复

进入 `2.4` 对话讨论前，必须先向用户交代本轮从哪聊起，不允许直接抛出结论或抽象措辞。整段回复都必须说人话，面向普通内容创作者，不得使用"认知一致性""观点层""结构复用""机制并置""差异化来源"等分析术语，除非先用一句大白话解释清楚。按下方固定格式输出，占位符替换为真实内容；小节可按需要补充（例如给用户的候选回答另起一个小节），已有小节不要删改：

用户已有明确重点（本条 1、2、3 项）时，固定格式如下：

```text
## 本轮讨论重点

### 聊什么
- <本轮重点，一句人话>

### 为什么
- <一句人话>

### 影响规划的哪部分
- <受影响部分>

### 要你拍板什么
- <要确认的取舍；可补充任何想法>
```

用户没有明确重点、需要推荐方向（本条 4 项，主方向 + 2 至 4 个备选）时，必须使用以下固定格式，每个方向都用大白话写清"做什么、影响哪部分、关键取舍在哪"：

```text
## 本轮主方向与备选

### 当前建议
- 你还没指定从哪聊起。建议先定 1 个主方向，再附几个明显不同的备选。

### 主方向
- 做什么：<...>
- 影响规划哪部分：<...>
- 要你拍板什么：<关键取舍>

### 备选
- 备选一：<做什么 · 影响哪部分 · 关键取舍>
- 备选二：<...>
- （按实际数量列 2 至 4 个）

### 下一步
- 你可以直接选、组合或改动，也可以说"先不定"。选好后先从选中的一个开始，一次只聊一个。
```

上面这段固定回复是 `2.3` 的完整产出：先发给用户，**等用户回应之后**才进入 `2.4 对话讨论`。不得在同一条回复里既交代讨论重点、又替用户往下推进。

### 2.4 对话讨论

`2.4` 不重新决定路由，只执行 `2.3` 已选定的一个讨论重点：

- 调查问卷中的原话或明确选择属于用户输入；AI 根据它整理出的用户需求、产品建议、定位候选和内容主线必须标为“AI 提议”，不能直接当成用户确认。
- 对标启发讨论必须区分：对标账号实际做法、可以迁移的机制、依赖对方的条件、我方适配判断，以及采用、改造采用、先验证或不采用的结论；对标事实不能直接改写成我方方向结论。
- 自我诊断启发讨论必须区分：账号实际表现、当前账号方向、两者差距，以及哪些属于执行问题、哪些属于方向需要调整；诊断事实不能直接改写成长期方向结论，涉及长期目标必须取得用户确认。
- 产品与变现问题属于本流程的一般讨论重点：可以讨论不变现、暂不变现、尚未决定、产品、服务、广告或其他收入方式，不默认用户必须卖产品，也不因信息不完整单独启动另一个流程。
- 补缺时只问对当前方向影响最大的一个问题，用户已经给出足够信息时不重复追问。
- 用户表示暂时未定时，保留“暂未确认”边界，不为填满目录而推测。
- 每次向用户提出问题时，同时提供 4 个基于当前已知信息的轻量候选回答；普通问题的候选用于帮助用户表达，不限制用户只能按编号选择。
- 需要形成账号定位或内容主线候选时，一次提供 4 个完整候选方向；候选必须明显不同、基于已知信息，并标出推荐项、适用情况和主要取舍。
- 只有存在一个可能改变整体方向的关键事实时，才追问一个关键问题；用大白话说明为什么重要，不使用未解释的分析术语。
- 修改范围以外的部分只在存在直接冲突时同步处理。
- 不预测剩余问题数量，不使用“最后一个问题”“还差一个”等无法保证的进度承诺。

本节只负责完成当前讨论；完成后由流程按 `2.5` 判断是否主动发起成稿确认，未满足时回到 `2.3`。

### 2.5 确认是否成稿

每轮讨论后，AI 主动判断当前讨论目标是否已经可以形成一个可保存的规划版本；不要求用户必须先提出成稿请求，也不要求整份规划所有内容都已确定。

只有同时满足以下条件，才主动向用户发起成稿确认：

1. 本轮准备新增、修改或保留的内容已经明确；
2. 已经形成可以直接写入规划的结论；
3. 这项变化直接影响的其他部分已经处理，或用户明确确认暂不调整；
4. 不存在会让当前规划自相矛盾的未解决冲突。

本流程中的“可写结论”是指：

- 可以直接写成当前规划中的确定陈述
- 来自用户明确确认的内容，或用户明确同意继续保留的旧结论
- 不是多个方案并列，也不是 AI 自行推测
- 用户明确保留为未知的内容不属于可写结论，但可以作为未确认边界记录

与本轮无关的未知内容不阻止成稿。对应条件不足时，继续停留在 `2.3 确定本轮讨论重点` 和 `2.4 对话讨论`，处理当前最关键的问题；退回 `2.3` 重新交代讨论重点时，仍按 `2.3` 的固定格式输出，不要直接抛结论或改用自由措辞。

条件满足后，先向用户概括：

- 本轮准备写入或修改什么
- 哪些旧结论继续保留
- 哪些关联部分需要同步调整
- 哪些内容仍未确认

再询问用户是否现在生成或修改 `我方资料/我方自媒体规划.md`。只有用户明确表示“可以生成”“按这个修改”“先出一版”“可以进入成稿”或其他等价确认时，才进入下一步。

### 2.6 成稿并保存结果

#### 读取

- `提示词/自媒体规划成稿提示词.md`；
- `2.2` 读取的旧版完整账号方向，首次建立时为空；
- 调查问卷原文和本轮已经确认的用户回答；
- 直出入口下，新问卷与旧版方向冲突时以新问卷为准；旧版方向只补问卷没覆盖的细节，不得把旧方向写回去；
- 对标启发入口指定的正式对标分析文档（如有），只作为参考依据，不重新分析对标账号；
- 自我诊断启发入口指定的正式诊断文档（如有），只作为参考依据，不重新诊断账号；
- 问卷与诊断直出入口指定的全部正式诊断文档（如有，可以有多份），只作为参考依据，不重新诊断账号；
- 用户在 `2.5` 明确确认的本轮任务、修改范围、当前结论、保留结论、必要关联调整和未确认边界（直出入口没有这一步，按本轮指令和已有资料）。

不得把整段聊天记录直接交给保存器。先生成唯一完整正文，再以该正文为唯一输入重新生成四栏概要；概要只压缩正文已有信息，不得新增判断，也不得反过来要求正文增加概括段或提取字段。

#### 生成待提交正文

使用成稿提示词生成唯一的完整方向正文，即唯一的完整 `我方资料/我方自媒体规划.md` 正文，严格包含：

- `# 我方账号方向`；
- `## 方向总览`；
- `## 1. 自身条件`；
- `## 2. 用户与需求`；
- `## 3. 产品与变现`；
- `## 4. 账号与内容`；
- 成稿提示词规定的固定字段，以及按实际情况组织的其他内容；
- 有已确认排除项时，使用 `### 哪些内容不做` 记录。

标题和栏目缺失、四栏内容为空、正文混入未经确认的 AI 提议或逐项状态标签，或本轮输入无法支撑结论时，不进入正式保存，应回到 `2.3` 补充讨论并重新经过 `2.5`。正文不得设置“当前结论”“选择理由”等固定过程栏目，也不得在末尾重复“方向总结”。

#### 生成待提交概要

完整正文形成后，只读取这份正文，重新生成 `我方资料/我方当前概要.md`，严格包含：

- `# 我方当前概要`；
- `## 自身条件概要`；
- `## 用户与需求概要`；
- `## 产品与变现概要`；
- `## 账号与内容概要`。

每栏用简洁的大白话概括正式正文中的对应内容，保留会影响下游执行的重要限制和未定事项。不得读取聊天过程补入正文没有的信息，不得增加新建议，也不要求正文为了概要重复内容。

#### 正式提交

将完整正文和重新生成的概要作为 UTF-8 JSON 标准输入传给保存执行单元：

```json
{
  "plan_text": "<完整账号方向正文>",
  "overview_text": "<根据完整正文重新生成的四栏概要>"
}
```

执行：

```bash
python3 "<当前工作区根目录绝对路径>/执行单元/自媒体规划正式保存.py" \
  --workspace-root "<当前工作区根目录绝对路径>"
```

#### 保存结果

只有执行单元返回 `ok = true`、`status = committed`、`plan_path`、`overview_path`、`plan_sha256` 和 `overview_sha256`，才算完整方向与派生概要同时保存成功，进入 `2.7`。

- 正文结构校验失败：停在本步；如果修正会改变用户已确认结论，返回 `2.3` 重新讨论并再次经过 `2.5`。
- 正式写入、概要派生或回读失败：停在本步并说明真实错误；原正式方向和概要保持不变，不得报告部分完成，也不得由 AI 直接覆盖正式文件。
- 原因修正后，用户可以重新发起本流程；再次生成时必须重新生成唯一正文并执行同一条保存命令。

### 2.7 反馈结果

直接使用 `2.6` 的正式保存回执反馈，不重新读取或猜测结果。回报形式按本轮**是否经过 `2.3` 和 `2.4`** 分两种，不看入口叫什么名字。

#### 未经过讨论

本轮没有经过 `2.3` 和 `2.4` —— 用户只是让你按已经填好的问卷、或按问卷加一份刚跑出来的正式诊断写出一版方向（`questionnaire_direct` 和 `questionnaire_diagnosis_direct` 两个入口），既没参与讨论，也没确认过成稿（例如「绑定并诊断我的账号」这条指令里附带的那一步）—— 不铺上面那五段，固定只回两行：


不列正式文件路径，不列更新内容、参考来源和未确认边界。正文已经写在 `我方资料/我方自媒体规划.md` 里，用户要看会自己打开。

`<dashboard_base_url>` 只能使用工作台启动后返回的本地基础地址（取址方式固定按 `执行单元/工作台地址获取.md` 执行），两种形式都固定定位到 `index.html#media-plan`。例如：
