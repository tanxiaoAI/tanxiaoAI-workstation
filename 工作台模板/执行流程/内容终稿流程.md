# 内容终稿流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 内容终稿流程 --phase start
```

## 1. 总流程说明

1. 接收已确认初稿
   - 使用内容初稿确认后返回的协调器回执，进入 `2.1`；
2. 生成唯一终稿
   - 调用终稿提示词，生成并保存唯一一份终稿，进入 `2.2`；
3. 展示并等待决定
   - 展示当前终稿；用户直接改稿进入 `2.3`，用户要求重新审查或大改进入 `2.4`，确认进入 `2.5`；
4. 终稿后再处理
   - 已完成的终稿可以直接修改并覆盖，也可以回到内容初稿重新走一遍。

终稿只有一份：每次修改都覆盖当前终稿，不保留终稿 v1、v2 版本链。

### 协调器使用规则

内容初稿流程在确认后已经完成 `save` 和 `decide --decision confirm`，并返回内容终稿阶段的冻结输入。正常进入本流程不重复调用 `prepare`。

本流程只使用当前回执中的：

- `current_stage.flow_file`：必须是 `执行流程/内容终稿流程.md`；
- `state_file`：后续 `save`、`decide` 和 `transition` 使用同一个值；
- `inputs`：已确认的内容定位、已确认的内容初稿和本轮参考资料；
- `action_contract`：候选文件精确路径、输出要求和 `save` 提交参数；
- `decision_contract`：等待确认、修改或回退时允许提交的决定。

回执为 `ok = false`、当前阶段或流程文件不符、当前步骤所需合同缺失，或 `status = blocked` 时，说明回执中的真实原因并停止。

### 协调器命令

```bash
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action prepare --state-file "<state_file>"
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action save --state-file "<state_file>" --stage-candidate-file "<stage_candidate_file>"
python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action decide --state-file "<state_file>" --decision confirm
```

## 2. 具体流程说明

### 2.1 接收并校验初稿

- 当前阶段为“内容终稿”，且 `current_stage.flow_file` 指向本文件；
- `inputs` 中存在已确认的内容定位和内容初稿；
- `status = ready` 时存在本轮 `action_contract`，才能生成终稿；
- `status = waiting_for_user` 时已有可展示的当前终稿和 `decision_contract`，直接进入 `2.2` 展示；
- `status = completed` 时说明流程已完成，按 `2.6` 处理终稿后修改。

### 2.2 生成并保存终稿

1. 读取已确认的内容定位和内容初稿，以及本轮允许使用的参考资料；
2. 读取 `分析框架/内容生产方法论.md` 的 `### 5.5 终稿优化`；
3. 调用 `提示词/内容生产-内容终稿提示词.md`，生成干净、完整、可拍摄的终稿；
4. 按 `action_contract.required_outputs` 生成 `stage_candidate_file`：只包含一个 `## 内容终稿` 区块，并包含唯一的 `最终内容标题：<标题>` 和完整正文；
5. 调用协调器 `save` 提交。只有保存成功，才作为当前终稿展示；保存失败时上一版终稿保持有效。

### 2.3 展示并等待决定

```text
## 内容终稿

- 内容名称：<内容名称>
- 内容ID：<内容ID>
- 媒介形式：<视频 / 图文 / 文章 / 其他>
- 内容目标：<流量 / 涨粉 / 交易>

### 工作台查看
- 内容生产：<dashboard_base_url>/index.html#creation-board

### 当前版本
<本轮刚保存的完整终稿>

### 下一步
如果还要改措辞、标题或局部表达，直接告诉我；
如果想重新检查或大改，告诉我“重新审查”；
如果当前终稿已经明确，请回复“确认终稿”。
```

展示后：

- 用户提出终稿范围内的修改：进入 `2.3` 的“直接改终稿”；
- 用户要求重新审查或改动命题、切口、核心承诺、整体结构：进入 `2.4`；
- 用户明确确认：进入 `2.5`；
- 用户没有明确选择：停在本节。

#### 直接改终稿

- 记录用户明确要改的位置和方向；
- 提交当前 `decision_contract` 允许的 `decision = revise_current`；
- 只有协调器返回新的 `status = ready` 和 `action_contract` 后，才按 `2.2` 重新生成并保存；
- 新版本整体覆盖当前终稿，不保留旧版本；修改后回到本节等待确认。

### 2.4 重新审查或回到初稿

- 用户要求重新审查，或修改范围已经超出终稿（改命题、切口、核心承诺、整体结构、新增关键事实）：说明需要回到内容初稿；
- 用户确认后提交 `decision = rework_upstream`，目标阶段为“内容初稿”；
- 协调器把内容终稿标为已失效并返回内容初稿的 `ready` 回执，交给 `执行流程/内容初稿流程.md`；
- 重新确认初稿后再次进入本流程，生成的新终稿覆盖旧终稿。

### 2.5 确认终稿并完成生产

用户明确确认当前终稿后，使用当前 `decision_contract` 提交 `decision = confirm`。

协调器会确认内容终稿、写入内容库标题与封面、把内容状态置为“已完成”，并把生产流程标记为完成。

只有回执满足 `ok = true`、`status = completed` 时，才向用户反馈完成。确认或收尾失败时说明真实原因并停止，已保存终稿保持有效。

### 2.6 已完成终稿的后续修改

已完成的终稿有两种改法，由用户意图决定：

1. **用户已经知道要改什么（改措辞、标题、局部表达）**：直接重新打开终稿：
   ```bash
   python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action reopen-final --state-file "<state_file>" --reason "<用户的修改原因>"
   ```
   回执为 `ready` 且当前阶段为“内容终稿”后，按 `2.2` 生成新终稿，再按 `2.3` 展示、`2.5` 确认。新终稿覆盖旧终稿。
2. **用户要求 AI 重新审查，或想整体再改**：回到内容初稿：
   ```bash
   python3 "<当前工作区根目录>/执行单元/内容生产阶段协调器.py" --workspace-root "<当前工作区根目录绝对路径>" --action transition --state-file "<state_file>" --transition-action rework-stage --target-stage "内容初稿" --reason "<用户的修改原因>"
   ```
   回执为 `ready` 且当前阶段为“内容初稿”后，交给 `执行流程/内容初稿流程.md`；需要检查时手动执行 `执行流程/内容审查流程.md`。

内容已发布或已复盘时，不重新打开终稿；复活旧内容由用户在内容库中明确处理。
