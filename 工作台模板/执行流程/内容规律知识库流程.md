# 内容规律知识库流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 内容规律知识库流程 --phase start
```

## 1. 总流程说明

1. 汇总现有特征
   - 进入 `2.1 汇总内容特征与规律`，算一次全量汇总，取「纳入内容数」和「规律数量」两个统计数字。
   - **本步只算统计、不落盘**：规律库 CSV 已于 2026-09-28 退役，这一步只为本流程 `2.3` 的反馈提供统计数字，不再产出任何文件。
2. 生成知识库
   - 进入 `2.2 合并生成内容规律知识库`，按账号切片现算标签效果、按做法归并分层，产出 `沉淀结论/内容规律知识库.md`。
3. 返回结果
   - 进入 `2.3 反馈结果`，反馈正式文件、本轮范围、知识库分层和真实错误。知识库就是本轮交付物，用户据此提问。

本流程只有一种进入方式：**用户想刷新规律分析时直接触发**。它不接收入库回执，也不触发入库流程，两段流程互不调用。

本流程只产出 `沉淀结论/内容规律知识库.md` 一份正式资产，**不写词典、不改实例**：它只读已经落表的正式资产。词典的维护由「内容特征入库流程」独立负责。

本轮开始前先创建独立暂存目录 `.meiling/staging/pattern-library/<run_id>/`，`run_id` 只用于隔离本轮文件，后续每一步的输入文件都必须来自这一个目录。该目录只保存本轮需要传给下一步的文件，不是可恢复状态。正式文件（知识库）只在提交时使用短事务原子替换；扫描实例表、现算标签效果不持有正式数据锁。

任何一步失败都不回滚已经提交的正式资产，只如实反馈哪一步没完成。

## 2. 具体流程说明

### 2.1 汇总内容特征与规律

#### 执行

本步**只算统计、不落盘**：规律库 CSV 已于 2026-09-28 退役，这一步的结果只供 `2.3` 反馈使用，不产出任何文件。

范围固定为「所有对标的内容」，不追加任何筛选项：

```bash
python3 "<工作区根目录>/执行单元/内容特征汇总执行器.py" \
  --workspace-root "<工作区根目录>" \
  > "<本轮暂存目录>/汇总结果.json"
```

#### 成功条件与结果传递

只有返回 `status = committed`，才把结果用于后续步骤。需要使用的字段：

- `scope`：本轮筛选范围，四项必须全空；**对不上就停止**，不要继续往下走；
- `active_sample_count`、`rule_count`：纳入内容数和规律数量，`2.3` 的反馈要用。

命令失败（退出码非 0，或 `status = failed`）时停止，不得使用旧规律或自行估算。

> 回执里还有 `generated_at`、`status_distribution`、`rules`、`source_fingerprints`，那是给排查和下游程序看的，本流程后续步骤不需要取用。

### 2.2 合并生成内容规律知识库

#### 执行

这一步由执行器直接产出，**不经过模型写正文**：它按账号切片现算每个账号的标签效果，再把所有账号的结论按做法归并、按证据强度分四层，整份文档按表格呈现（一个做法一行）。

```bash
python3 "<工作区根目录>/执行单元/内容规律知识库合并执行器.py" \
  --workspace-root "<工作区根目录>"
```

- 输入：`沉淀结论/内容特征实例.csv`、两张账号库指向的各账号 `内容列表.csv`（取 `核心互动数`）、`沉淀结论/内容特征词典.csv`；
- 产出：`沉淀结论/内容规律知识库.md`（每次覆盖同一份，不做历史留档）；
- 报告只写四层结论，不写新特征候选，也不读任何入库回执。新特征入库不在本流程范围内。

#### 分层口径（固定，不得自行改）

| 层                     | 判据                                       |
| ---------------------- | ------------------------------------------ |
| 我方效果验证过的       | 我方账号里判出结论                         |
| 多账号对标验证过的     | ≥2 个对标账号里判出结论                    |
| 单账号里成立的         | 恰好 1 个对标账号里判出结论                |
| 出现过、但判不出效果的 | 没判出结论，只有出现记录                   |

- **「判出结论」**＝该做法在这个账号的三档对比里判成「数据好的内容更常用」或「数据差的内容更常用」；判定词**逐字写进证据栏**，不另开一列、也不自造符号（例如 ↑）；
- 一个做法只进一层，取最高；
- 第 4 层收两类：① 在已建档账号里出现过、但三档判不出方向的，条目列出三档分布（高档 X／中档 Y／低档 Z）；② 只在没建档的内容里出现过的——结构上永远判不出，条目写「N 篇来自没建档的内容（分不了档）」；
- **第 4 层有一条整体门槛**：整个工作区去重后出现**不足 3 篇**的做法一律不进库（出现 1～2 篇既不是这个账号的习惯、也判不出效果）。常量是 `执行单元/内容规律知识库合并执行器.py` 的 `LEAD_MIN_OCCURRENCE`；
- 当前数据下「我方效果验证过的」和「多账号对标验证过的」两层很可能是空的，执行器会如实写「暂时没有」，不要解释成出错。

#### 成功条件

只有返回 `status = committed`、`output_path` 和 `sha256`，才算知识库已刷新。失败时停止，如实反馈真实错误。

### 2.3 反馈结果

直接使用 `2.1`、`2.2` 的执行器回执反馈，不重新读取或猜测结果。固定格式如下：

```text
## 内容规律知识库结果

- 分析范围：所有对标的内容

### 正式文件
- 内容规律知识库：沉淀结论/内容规律知识库.md

### 本轮范围
- 纳入内容数：<active_sample_count>
- 规律数量：<rule_count>

### 知识库分层
- 我方效果验证过的：<layer_counts.L1> 条
- 多账号对标验证过的：<layer_counts.L2> 条
- 单账号里成立的：<layer_counts.L3> 条
- 出现过、但判不出效果的：<layer_counts.L4> 条

### 本轮状态
- <已完成 / 未完成>
- 错误：<真实错误；无错误时不展示>
```

分层的四条数字取 `2.2` 回执的 `layer_counts`。某层为 0 时照实写 0，并补一句这一层为什么是空的（我方样本不够／还没有第二个对标账号能给出结论／暂时没有）。

固定文案只能用执行器实际返回值填充：

- 纳入内容数、规律数量取 `2.1` 回执；
- 分层条数取 `2.2` 回执的 `layer_counts`。

状态口径：

- 全链路成功写「已完成」；
- `2.1` 失败时写「未完成」，且不得展示任何规律结论；
- `2.2` 失败时写「未完成：汇总已完成，知识库未更新」。

在上面的固定结果反馈之后，追加下面这段，只写用户可以做的动作：

```text
你可以直接问我某条规律更细的来龙去脉，也可以看规律词典里哪些做法你认可、哪些不认可。要改词典，用「更新内容特征」处理，这个流程不改词典。
```

本流程不修改特征词典。用户要求改词典时，说明它属于「内容特征入库流程」，不在本流程里直接改。

报告只反映已经落表的内容特征实例。词典里新增的特征，要等后续内容分析把它们写成实例后，下一次刷新才会进入报告。

**本流程结束后执行一次使用统计上报**（静默脚本，失败不影响任何流程）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 内容规律知识库流程 --phase end --status ok
```

正常走完用 `--status ok`；按阻断分支收尾用 `--status blocked`。**没走到这一步就不用补报** ——

## 跑完回工作台（DS 版）

这一轮做完、结果已经保存后，把结果页告诉客户端（**执行命令，不是把命令贴进回答**）：

```bash
mkdir -p .meiling/dashboard && printf '%s' 'view=patterns' > .meiling/dashboard/goto.json
```

Windows（cmd）：

```bat
if not exist ".meiling\dashboard" mkdir ".meiling\dashboard"
echo view=patterns> ".meiling\dashboard\goto.json"
```

页面取走就会删掉，写一次就够；回答正文里不要出现这个文件，也不要说「给你留了个定位」。这轮没做完（在等用户确认、还要补东西）就别写。
