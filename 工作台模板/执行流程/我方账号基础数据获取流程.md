# 我方账号基础数据获取流程

**本流程开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind flow --name 我方账号基础数据获取流程 --phase start
```

## 1. 总流程说明

1. 前置确认
   - 进入 `2.1 检查创作者中心链接`
   - 进入 `2.2 检查数据源并等待用户选择`
2. 确认数据源
   - 进入 `2.2 检查数据源并等待用户选择`
   - 用户未明确选择可用数据源时停在本步；不得默认选择或静默换源
3. 获取基础资料并查重
   - 进入 `2.3 获取账号基础信息并立即落盘`
   - 再进入 `2.4 执行 --prepare-only 查重`
   - 发现疑似重复账号时停在 `2.4` 等待用户确认，确认后继续复用当前任务和暂存目录
4. 获取内容列表并正式建档
   - 进入 `2.5 获取账号内容原始列表并立即落盘`
   - 再进入 `2.6 正式建档并验证产物`
   - 首次结果要求重试时，保持同一账号、数据源和暂存目录返回 `2.5` 集中补抓一次；第二次仍失败时停止自动处理
5. 完成并返回结果
   - 正式建档成功后进入 `2.7 完成并返回结果`
   - 本流程只使用已经回读验证的建档结果，不询问详情范围；详情范围由详细数据流程负责确认和冻结
   - 完成后直接继续《我方账号详细数据获取流程》，由该流程在 `2.2` 的同一条消息里一并说明基础建档结果并确认内容范围

本流程直接读取本地流程、执行单元和提示词。每轮使用一个本地暂存目录；正式文件只由执行单元写入。

### 本轮运行合同

本流程使用入口已经确认的唯一账号和本轮 `run_id`；不重新选择账号，不从远程资源取得流程。

进入 `2.1` 之前，先调用本地执行单元分配本轮唯一批次身份：

```bash
python3 "<当前工作区根目录>/执行单元/账号分析本地批次初始化执行器.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
  --flow-type self_account
```

只使用返回的 `run_id` 和 `staging_dir`。本轮所有基础数据候选、Chrome 中转文件和后续详细数据、诊断都必须使用它；模型不得自行生成或改写 `run_id`。

- `平台 / 账号ID / 账号名 / 主页链接`：本轮唯一账号身份
- `<当前工作区根目录>`：当前工作区根目录
- `<本轮暂存目录>`：`当前工作区/.meiling/staging/self-account-diagnose/<run_id>/`
- `<账号基础信息JSON>`：`<本轮暂存目录>/账号基础信息.json`
- `<账号内容原始列表JSON>`：`<本轮暂存目录>/账号内容原始列表.json`
- `<本轮失败状态JSON>`：`<本轮暂存目录>/过程记录/` 下的失败报告（如有），仅供人工排查，不作为恢复依据

本轮暂存目录、候选 JSON、Chrome 中转文件和失败报告均使用本轮 `run_id` 派生的本地路径；正式 JSON/CSV、报告和阶段状态只能由 `执行单元/` 下的本地脚本写入。本流程不读取、不创建任何调度器任务状态；账号的正式阶段状态只写入 `<账号目录>/过程记录/当前阶段状态.json`。

`2.3` 至 `2.5` 失败时只保留本轮暂存文件，正式账号库、正式账号目录和正式内容列表保持不变；正式业务文件只可能由 `2.6` 的正式建档脚本改动。用户重新发起时重新执行本节的 `账号分析本地批次初始化执行器.py` 分配新的 `run_id`，创建新的本地暂存目录，不复用旧暂存文件。

## 2. 具体流程说明

### 2.1 检查创作者中心链接

#### 读取

检查用户消息中的平台名和链接。

- 用户消息中已有创作者中心链接：只使用消息中的链接，不再读取账号库；只有一条时直接使用，多条时让用户选择。
- 用户消息中只有平台名（小红书 / 抖音）：用该平台的固定入口链接，不再向用户索要链接，直接进入 `身份解析`。
- 两者都没有时，再读取 `我方资料/我方账号库.csv`：
  - 账号库没有记录：展示 `索要平台` 的固定文案后停止，等待用户选择平台；不得猜测账号、翻找其他目录或改用其他入口。
  - 账号库只有一条记录：展示该账号，请用户确认。
  - 账号库有多条记录：展示候选账号，让用户选择。

用户确认或选择一个已有账号后，直接以该记录的 `平台 / 账号ID / 账号名 / 主页链接` 作为本轮唯一账号身份，进入 `2.2`，不重新执行身份解析。

用户给出创作者中心链接或平台名时，进入 `身份解析`。

#### 索要平台

账号库没有记录时，必须向用户展示以下固定文案。本段不包含占位符，必须原样展示，不得改写、增删内容，也不得补充其他链接示例：

```text
账号库现在是空的，还没有任何账号记录，所以这轮需要你先选要诊断的平台。

你不用在自己平时用的浏览器里登录：我会把创作者中心登录页开在 AI 专用浏览器里——就是 AI 自己控制的那个 Chrome 窗口。你在那个窗口里登录，我这边检测到登录成功就直接往下跑，不用再回复我。

支持的平台：
- 小红书：https://creator.xiaohongshu.com/new/home
- 抖音：https://creator.douyin.com/creator-micro/home

告诉我要诊断小红书还是抖音就行。

选好之后我会按这个顺序往下走：
1. 在 AI 专用浏览器里打开这个平台的创作者中心；没登录就停在登录页边等边检测；
2. 读出这个窗口里当前登录的是哪个账号；
3. 确认这个账号有已经发布的内容；
4. 你的账号资料和已发布内容都从这个创作者中心取，不用再登录别的页面；
5. 建档完成后接着做账号诊断，最后给你一份「优势 + 问题」的结论。
```

展示后停在本步，等待用户选择平台；用户给出平台或链接后重新进入 `读取` 并继续后续步骤，不得在本步执行任何取数或正式写入。

#### 身份解析

严格复用 `执行单元/创作者中心链接识别与账号身份解析.md`，输入固定为：

- `原始输入 = <本轮唯一候选输入>`
- `本轮暂存目录 = <本轮暂存目录>`

只消费协议返回的状态和真实原因：

- `成功`：把返回的 `平台 / 账号ID / 账号名 / 主页链接` 冻结为本轮唯一账号身份，同时冻结本轮使用的 `创作者中心链接`（用户给了就用用户的，用固定入口的就用那个固定入口），进入 `2.2`；不要求用户再确认，也不再要求用户补主页链接。
- `创作者中心未登录`：按 `未登录` 小节边等边检测，登录成功后直接进入 `2.2`，不再要求用户回复「登录好了」。
- `没有已发布内容`：展示 `没有已发布内容` 的固定文案，取消当前任务并停止，不进入 `2.2`。
- 其余失败（`未识别到链接`、`识别到多条链接`、`链接不是创作者中心链接`、`chrome_devtools 不可用`、`未取得真实账号 ID`、`内容列表读取失败`）：展示协议返回的真实原因，需要时附上对应平台的正确入口，然后取消当前任务并停止，不进入 `2.2`。

#### 未登录

协议返回 `创作者中心未登录` 时，不得停在原地等用户回复「登录好了」，也不得提示用户去自己日常用的浏览器登录，按下面的方式等待并自动继续：

1. 保持创作者中心登录页开在 AI 专用浏览器里，并用一句话告诉用户：请在 AI 专用浏览器那个窗口里完成登录，登录成功后会自动往下跑。
2. 每轮等待 5 秒后重新判定一次登录态；等待期间出现扫码、滑块、短信验证等需要用户操作的环节，继续等，不自动处理、不重试到别的路径。
3. 最多等 60 轮（约 5 分钟）。登录成功且能读到真实账号身份后，不再询问用户是否继续，直接进入 `2.2`。
4. 超过上限仍未登录：停止本轮，说明「等了约 5 分钟仍未检测到登录」，让用户重新发起；不得改成索要主页链接。
5. 等待期间不重新读取账号库，不跳过身份解析；读到的登录账号与用户要诊断的账号不是同一个时，停止本轮并说明，不得继续。

#### 没有已发布内容

协议返回 `没有已发布内容` 时，必须向用户展示以下固定文案，不得改写，也不得改问主页链接：

```text
这个账号在创作者中心里没有任何已发布内容，没法做账号诊断。

账号诊断至少需要一条公开作品作为数据基础。等内容发布之后再来，我给你重新跑一遍。
```

#### 链接不合格

需要向用户说明正确形式时，展示两个平台的创作者中心入口：

- 小红书：`https://creator.xiaohongshu.com/new/home`
- 抖音：`https://creator.douyin.com/creator-micro/home`

需要取消当前任务时，向用户说明真实取消原因并停止；本轮已写入的暂存文件保持实际状态，不另写取消状态。

### 2.2 检查数据源并等待用户选择

#### 读取与检查

严格复用 `执行单元/公开数据获取环境检查与数据源选择.md`，输入固定为：

- `允许的数据源 = chrome_devtools, justoneapi`
- `是否涉及 ASR = 是`
- `当前工作区根目录 = <当前工作区根目录>`

协议只读检查 `mcp__chrome_devtools__list_pages` 和 `JUSTONEAPI_TOKEN`。协议只返回环境状态和真实失败原因；不返回用户选择、已尝试来源、标题、搜索摘要或正文，也不执行本轮业务取数。

#### 展示

进入本小节前，`2.1` 必须已经确定本轮唯一账号身份（`平台 / 账号ID / 账号名 / 主页链接`）；账号身份尚未确定时不得展示数据源文案。

用户点名 `justoneapi`、或主动要求比较数据源时，才向用户展示以下固定文案。只替换尖括号中的占位符，不得自行改写其他内容；默认路径（走 `chrome_devtools`）不展示本段：

```text
## 请选择基础数据来源

### chrome_devtools
- 当前状态：<chrome_devtools状态>
- 适合：日常使用，已在 AI 专用浏览器登录目标平台账号。
- 可获取：创作者中心里你本人账号的资料、内容列表和数据。不打开公开主页，不用额外登录第二个页面。
- 注意：免费，但不适合连续批量处理多个账号，可能触发平台风控。
```

占位符替换规则：

- `<chrome_devtools状态>`：填写 `可用`，或填写 `不可用，原因：<真实原因>`。工作区写权限的结果**不展示给用户**，只在内部判定时使用。
- `<JustOneAPI状态>`：填写 `已配置` 或 `未配置`。
- `<JustOneAPI配置提示>`：JustOneAPI 已配置时填写 `无需补充配置。`；未配置时填写两行：`配置指南：https://tanxiao.com.cn/docs/data-api/` 和 `官网地址：https://justoneapi.com/zh`。

#### 用户选择

- **默认数据源是 `chrome_devtools`。** 用户消息没有点名数据源时，检查通过后直接采用，不展示数据源选择题、不等用户确认。
- 用户消息点名 `justoneapi` 时改用 `justoneapi`；只认用户明确的选择，不得因为某一种不可用就暗中切换到另一种。
- 用户点名 `chrome_devtools` 但当前不可用：**不要停在“让他先去配”**，直接按 `执行单元/取数环境搭建.md` 把它装好配好（含工作区写权限），重跑本节检查，通过后继续，不要再问一遍。
- 用户点名 `justoneapi` 但未配置：停在本步说明真实原因，等他配置好或改选。
- 数据源确定后，把 `chrome_devtools` 或 `justoneapi` 写入本轮流程上下文的 `用户选定取数方式`，并将 `已尝试取数方式` 初始化为空。
- 后续只执行该已确认的数据源；来源失败时立即停止，不得自动换源。用户调整配置或改选来源后，必须重新发起一次新的运行。
- `2.1` 解析创作者中心身份时使用过 `chrome_devtools`，不等于本轮数据源已经确定；仍按本节规则定源。

### 2.3 Chrome 会话前提与账号基础信息

用户选择 `chrome_devtools` 后，本流程后续使用的 MCP 服务名固定为 `chrome_devtools`。具体工具、调用顺序和调用上限以当前执行单元合同为唯一依据；不得调用执行单元未授权的工具，也不得自行发现其他 MCP 或浏览器。

#### 会话前提：窗口在不在，自己负责

AI 专用浏览器是 `chrome-devtools-mcp` 进程的子进程。客户端回收或重载 MCP 连接时它会一起退出，下次调用工具时才重新拉起，起来的只有 `about:blank`。登录态存在磁盘上不会丢，**丢的是「开着的页面」**（2026-11-01 实测：窗口只剩 `about:blank` 时，打开创作者中心仍是已登录状态）。

`2.3` 到 `2.6` 全程按这四条走：

1. 动手前先 `list_pages`。目标页面还在就直接用，不刷新、不重开。
2. 页面不在就自己开一个（`new_page` 打对应地址），等加载完再用。**不要因为「页面没了」就回头让用户重新登录。**
3. 新开的页面仍是登录态就直接往下走；确实掉了登录，才按 `2.1` 的 `未登录` 处理。
4. 不许关窗口、不许关创作者中心页面 —— 取完数也留着，用户可能还要自己看。

#### `chrome_devtools`

在第一次写入候选前调用中转脚本创建 `<本轮暂存目录>` 和 Chrome 中转清单：

```bash
python3 "<当前工作区根目录>/执行单元/Chrome采集临时文件中转.py" prepare \
  --staging-dir "<本轮暂存目录>"
```

只接受 `ok = true` 的结果，并保存返回的 `manifest_json / stage1_json / screenshot_png`，供 `2.5` 继续使用。`prepare` 失败时保持同一账号、数据源和暂存目录原样重试一次；第二次仍失败时说明真实原因后停止，不得绕过中转脚本写入其他路径。

随后完整读取并执行 `<当前工作区根目录>/执行单元/创作者中心取账号基础信息.md`，输入 `2.1` 冻结的 `平台`、`创作者中心链接`、`账号ID`，本轮 `<本轮暂存目录>` 和本轮中转清单。

基础信息全部从**创作者中心**取，不打开账号主页 —— 用户在 AI 专用浏览器里只登录创作者中心一个页面。取完保持这个页面，供 `2.5` 继续用。

#### `justoneapi`

选择 `justoneapi` 后，必须使用 `2.1` 返回的 `<账号主页链接>`，不得把包含 `xsec_token`、`xsec_source` 或其他临时查询参数的原始链接传给 API。此分支的证据视角固定为 `公开视角（别人看到的主页）`；如果用户要求的是登录后本人视角，JustOneAPI 选择无效，必须停下并提示改用 `chrome_devtools`。

本轮 `<账号主页链接>` 来自 `2.1` 的创作者中心身份解析，已经是标准公开主页链接，不会出现 `user/self` 这类登录态占位地址；不得改用用户原始输入或创作者中心链接调用 API。

调用：

```bash
python3 "<当前工作区根目录>/执行单元/JustOneAPI账号基础抓取执行器.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
  --account-url "<账号主页链接>" \
  --account-info-json "<账号基础信息JSON>" \
  --preflight-only
```

#### 成功条件与失败处理

账号基础信息至少要有真实的 `平台 / 账号ID / 账号名 / 主页链接`。执行器返回的标准主页链接必须与本轮冻结链接和本轮账号已有身份一致。

- 文件存在、可以解析、状态成功、必填身份完整、身份一致且 `基础数据获取方式` 与用户选择一致：进入 `2.4`。
- 必填身份缺失或身份不一致：保持同一账号、数据源和暂存目录补抓一次；仍未通过时说明真实原因并停止。
- 文件没有落盘、无法解析、状态失败或来源不一致：保持同一账号、数据源和暂存目录重试当前步骤一次；仍未通过时说明真实原因并停止，不得进入查重。

本步骤失败时只保留暂存候选和失败信息，已有正式账号库、账号目录和内容列表保持不变。

### 2.4 账号查重

#### 执行

调用：

```bash
python3 "<当前工作区根目录>/执行单元/账号基础数据建档批处理.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
  --account-type self \
  --account-info-json "<账号基础信息JSON>" \
  --prepare-only
```

只消费脚本返回的 `ok / status / account_exists / account_dir / expected_platform / expected_account_id / suspected_duplicates / user_confirmation_required`。

#### 结果判断

- `ok = true`、`status = ready`、`user_confirmation_required = false`：保存返回的账号目录和预期身份字段，进入 `2.5`。
- `status = duplicate_confirmation_required`、`user_confirmation_required = true`：展示 `suspected_duplicates` 并停止，等待用户确认。
- 命令失败、返回无法解析、状态不在允许范围内，或状态与 `user_confirmation_required` 相互矛盾：保留已经校验的账号基础信息，只重跑 `2.4` 一次；仍未通过时说明真实原因并停止，不得重新获取账号基础信息或进入 `2.5`。

#### 疑似重复确认

- 用户确认仍按当前新账号建档：使用相同参数重新执行 `--prepare-only` 并增加 `--allow-suspected-duplicate`。只有返回 `ok = true`、`status = ready`、`user_confirmation_required = false` 才进入 `2.5`；正式建档继续保留该参数。
- 用户确认应改用某个已有账号：取消当前任务并停止，由公开入口按用户选定的已有账号创建或恢复任务；本流程不得直接替换当前任务账号。
- 用户取消建档：向用户说明真实原因并停止；本轮已写入的暂存文件保持实际状态，不另写取消状态。
- 用户没有明确确认：停在本步。

本步骤只检查账号和目标目录，不创建正式目录，不写正式业务文件。

### 2.5 获取账号内容原始列表并立即落盘

本步骤开始前读取 `本地配置.txt` 的 `SELF_ACCOUNT_BASE_LIMIT`（留空、非法或不在 `1`—`2000` 内时按默认 `200`），冻结为本轮 `<基础内容上限>`：

- 本步骤最多保留 `<基础内容上限>` 条；账号不足上限时按实际条数处理。
- 达到上限即停止继续滚动、翻页和逐条补取，不再请求下一页。
- 达上限时必须在 `内容列表停止原因` 写明「达到本轮内容数量上限 N 条」；内容列表完整性按「可能未抓全」处理，不得宣称已获取账号全部内容。
- 本轮的「全部内容」只指本轮基础清单内的全部内容，不代表账号历史全部作品。

#### `chrome_devtools`

1. 完整读取当前工作区根目录下的 `执行单元/创作者中心取内容列表.md`，以该文件的输入、处理和输出合同作为本步骤执行依据。
2. 组装执行上下文：
   - `账号基础信息`：使用 `2.3` 已落盘并校验通过的账号基础信息；
   - `本轮暂存目录`：继续使用本轮 `run_id` 派生的同一 `<本轮暂存目录>`；
   - `中转清单`：首次采集使用 `2.3` 返回的清单；集中重试、清单缺失或临时目录失效时，使用相同暂存目录重新执行 `prepare` 并保存新清单；
   - `内容数量上限`：使用本步骤冻结的 `<基础内容上限>`，达到上限即停止翻页；
   - `内容可见性`：**非公开内容一律不采**（2026-11-01 口径）—— 仅自己可见、草稿、审核中、未通过、其他和未知状态的条目在取数阶段直接丢弃，不写候选、不补抓、不进详细数据、诊断和内容规律分析。跳过条数写进 `内容列表停止原因`。
3. 继续使用 `2.3` 保留的创作者中心页面，按执行单元合同读列表接口、翻页、截账号页面长图，不重新导航到公开主页。Chrome 阶段只能向中转清单中的工作区 `chrome-inbox` 路径写入阶段结果，不得直接写正式业务文件；调用 `get_network_request` 时必须传 `responseFilePath = <manifest.network_response>`，Network 响应只能使用 manifest 返回的 `.network-response` 路径，禁止传 `output_path` 或从内联文本拼 JSON。
4. 采集结束后调用：
   ```bash
   python3 "<当前工作区根目录>/执行单元/Chrome采集临时文件中转.py" finalize \
     --manifest-json "<manifest_json>"
   ```
   截图工具失败时增加 `--screenshot-error "<真实失败原因>"`。
5. 只接受 `finalize` 返回的结构化结果，并确认 `<账号内容原始列表JSON>` 存在、可以解析、账号身份一致且 `基础数据获取方式` 与用户选择一致。
6. `主页长截图状态 = 成功` 时必须确认截图和截图结果 JSON 存在；`失败 | 跳过` 时保留真实状态和原因，但不阻断结构有效的内容列表进入 `2.6`。
7. 中转命令失败、JSON 不可解析、账号身份不一致或来源不一致时，保留账号基础信息和查重结果，保持同一数据源重跑 `2.5` 一次；仍未通过时说明真实原因并停止，不得把未经 `finalize` 的 Chrome 结果交给正式建档脚本。

#### `justoneapi`

复用已经取得的账号基础信息，调用：

```bash
python3 "<当前工作区根目录>/执行单元/JustOneAPI账号基础抓取执行器.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
```

必须传入本步骤冻结的 `--max-items <基础内容上限>`，执行器在翻页过程中达到上限即停止请求下一页，不抓完再截断；不自行补写 API 返回字段。执行器必须在接口返回 `has_more = true` 时使用返回的游标继续请求；游标缺失、重复、后续页失败或达到安全上限时，必须记录“可能未抓全”和真实停止原因。只要存在有效内容，正式建档脚本仍按“已取得内容”处理，不因列表可能未抓全而把本轮改判为失败；但报告必须保留该数据边界，详细分析不得把 `内容列表获取状态 = 成功` 自动解释为“完整”。没有有效内容才按失败处理。执行器不得删除非公开内容，必须为每条内容写入统一的 `公开状态`。

#### 进入正式建档的条件

两种数据源都必须确认：

- `<账号基础信息JSON>` 和 `<账号内容原始列表JSON>` 真实存在并可以解析；
- 账号基础信息包含 `基础数据获取方式 / 平台 / 账号ID / 账号名 / 主页链接`；
- 内容原始列表包含 `基础数据获取方式 / 账号内容原始列表 / 内容列表获取状态`；
- 两份候选的账号身份一致，数据源与用户本轮选择一致。

满足结构和身份条件后，无论 `内容列表获取状态` 是 `成功 / 部分成功 / 失败`，都进入 `2.6`，由正式建档脚本统一判定完成、重试或等待用户。候选里的 `部分成功` 是上游旧值，只要有可识别内容即按 `成功` 归一，正式报告只会给出 `成功` 或 `失败`，本流程不据此单独分支。候选文件缺失、不可解析、身份不一致或来源不一致时保持同一账号、数据源和暂存目录重跑 `2.5` 一次；仍未通过时说明真实原因并停止，不得手工补写后继续。

### 2.6 正式建档并验证产物

#### 执行

调用：

```bash
python3 "<当前工作区根目录>/执行单元/账号基础数据建档批处理.py" \
  --workspace-root "<当前工作区根目录绝对路径>" \
  --account-type self \
  --account-info-json "<账号基础信息JSON>" \
  --raw-list-json "<账号内容原始列表JSON>" \
  --data-source "<chrome_devtools或justoneapi>" \
  --acquisition-attempt "<1或2>"
```

刷新已有账号时增加准备结果返回的 `--expected-platform / --expected-account-id`；用户已确认疑似重复时增加 `--allow-suspected-duplicate`。

正式建档只接收 `2.3` 产生并校验通过的账号基础信息 JSON，以及 `2.5` 对应数据源产生并校验通过的账号内容原始列表 JSON。Chrome 截图状态已经包含在中转脚本 `finalize` 写入的内容列表 JSON 中；JustOneAPI 结果不要求经过 Chrome 中转脚本。AI 不得手工补写、覆盖或修改正式建档输入。

#### 结果判断

只回读脚本输出和脚本返回的 `report_json`。我方账号的正式报告和阶段状态必须记录同一 `run_id`（脚本从候选 JSON 所在的本轮暂存目录名推导，与入口执行器分配值一致），正式报告还必须记录本轮选定的 `data_source`；缺失或不一致时不得当作成功：

- `formal_commit.validated = true`、`complete = true`、`validation_status = accepted`：正式基础建档成功，进入 `2.7`。
- 在上述成功条件同时成立时，`verified_empty = true` 表示账号基础信息已正式建档，但当前确认没有内容；建档脚本同时提交正式阶段状态 `completion_reason = verified_empty`，进入 `2.7`，不询问详情范围。
- `retry_required = true` 且 `acquisition_attempt = 1`：保留账号基础信息、查重结果、疑似重复确认和同一暂存目录，保持同一数据源返回 `2.5`；只把取数和正式建档的 `--acquisition-attempt` 改为 `2`，只允许这一次自动集中重试。
- `validation_status = partial`、`complete = false`（本轮内容列表获取失败，且账号已有正式记录）：账号基础信息按脚本规则更新，既有正式 `内容列表.csv` 保持不变；说明真实失败原因后停在本步，按下方 `失败和恢复` 处理。
- `user_decision_required = true` 或第二次仍未通过：停止自动处理，展示第二次报告中的真实失败原因和已保留结果，等待用户决定更换数据源、开始一轮新的人工重试或停止。
- 命令失败、返回结构不完整，或者正式写入及回读状态无法确认：不得假定正式记录保持不变；明确报告状态无法确认并停止，不自动重跑，也不报告成功。

#### 失败和恢复

正式报告 `content_list_status = 失败` 时，按账号是否已有正式记录分两种处理：

- 新账号（尚无正式账号记录）：建档脚本只允许在 `<本轮暂存目录>/过程记录/` 下写入失败报告和阶段状态；不得创建正式账号目录，不得新增正式账号库记录，不得新增或覆盖正式 `内容列表.csv`。
- 已有账号：保留既有正式 `内容列表.csv`（`formal_commit.content_list_written = false`），账号基础信息按脚本规则更新，并在报告的 `data_limitations` 中记录真实失败原因。

两种情况下存在失败报告都不等于基础建档成功。首次失败只按 `retry_required` 返回 `2.5` 重试失败的取数步骤，不重新选择账号、重抓已经校验的账号基础信息或重做查重确认；第二次失败后停在本步等待用户，不再自动重试。

停在本步等待用户后，用户明确选择：

- 更换数据源：返回 `2.2` 重新检查并确认新来源，新来源从 `acquisition_attempt = 1` 开始；不得静默切换。
- 同一数据源重新开始一轮人工重试：继续复用当前账号和 `<run_id>`，返回 `2.5`，新一轮从 `acquisition_attempt = 1` 开始；每轮仍只允许一次自动集中重试。
- 停止：向用户说明真实原因并结束本轮；本轮已写入的暂存文件保持实际状态，不另写取消状态。
- 尚未决定：保持等待，不执行外部取数或正式写入。
