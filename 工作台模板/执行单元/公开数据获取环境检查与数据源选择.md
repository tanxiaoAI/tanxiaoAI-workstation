# 公开数据获取环境检查与数据源选择协议

本执行单元只检查公开数据获取环境并输出真实状态；不执行业务取数、不等待用户选择、不写入正式 CSV，也不读取或生成业务内容字段。具体业务流程负责展示固定用户文案、承接用户选择并启动后续取数。

## 输入

- `允许的数据源`：`chrome_devtools`、`justoneapi`。
- `是否涉及 ASR`：只有本轮可能处理视频正文时为是。ASR 不是账号或内容基础数据源。
- `当前工作区根目录`：用于只读读取 `本地配置.txt`。

## 配置项判定规则

`JUSTONEAPI_TOKEN` 和 `VOLCENGINE_SPEECH_API_KEY` 都按本节判定，不得为其中某一项另立标准。

- 判定只能来自本轮对 `<当前工作区根目录>/本地配置.txt` 的真实读取：必须先实际打开并读到文件内容，再逐项判定。不得凭印象、对话历史、上次检查结果、“这类系统通常已配置”或缺省假设作答。
- 文件不存在或无法读取时，直接判 `未配置`，并保留真实原因（文件缺失 / 读取失败）。
- 只使用等号右侧的值：去掉两端空格和成对引号后非空，才算该项已配置。
- 以下情形一律判 `未配置`：等号后为空；该行没有等号；只有键名而没有值；键名只出现在注释、示例或说明文字里。
- 不得把“文件里存在这个键”“文件里出现过这个键名”当成“已配置”。文件列出键名只说明这是一个可填写的配置位，不说明用户已经填写。
- 同一份文件里的所有配置项，必须在同一次读取中用同一套判据逐项判定，不得出现同为空值却分别判成 `已配置` 和 `未配置`。
- 判定只报告状态，不得回显、复述、上报或写入任何配置值（含空白值和疑似片段）；也不得用官网可打开、网络可达或历史成功记录替代本节的取值判定。

## 只读检查

1. 直接调用 `mcp__chrome_devtools__list_pages` 检查当前 Chrome 连接。成功显示 `chrome_devtools 可用性 = 可用`；失败显示 `不可用，原因：<真实原因>`。不得把猜测、静态端口探测或历史结果当成可用。
   - 报不可用时先分清是哪一类：**报「MCP 未放开当前工作区写权限」走第 2 项那条修复动作**；**本身就调不到（还没配 MCP、或本机没装 Chrome）走 `执行单元/取数环境搭建.md`**，搭好之后重跑本节。两类都不要拿它当「用户选了 JustOneAPI」的理由。
2. `chrome_devtools` 可用时，必须再做一次**工作区写权限探针**：连接可用不等于能写工作区，这是两个独立的失败点，不得用 `list_pages` 成功代替本项。
   - 做法：用 `chrome_devtools` 任一能指定输出路径的文件类工具，向 `<当前工作区根目录>/.meiling/staging/chrome-write-probe-<YYYYMMDDTHHMMSS>.txt` 写一个探针文件，再读回比对内容；一致才算成功。文件名里的时间戳必须是本次检查的当前时刻，并且**本次检查内保持不变**；不同运行、不同会话不得复用同一个探针文件名（`staging` 是多个会话共用的目录，固定文件名会互相覆盖）。比对完成后删除该探针文件。
   - 探针内容只写一小段可读回比对的标记（例如带本次时间戳的一行 JSON），**不得把页面快照、结构化状态树或其他业务数据写进探针文件**——探针只验写权限，不是中转文件。
   - **以工具实际写出的路径为准**：部分文件类工具会按自身格式改写或追加扩展名（2026-09-14 实测 `chrome_devtools` 的 `evaluate_script` 会把输出保存为 `.json`，即使指定 `.txt`）。扩展名与预期不同**不构成失败**，读回比对按实际路径进行，删除时也删实际写出的那个文件；不得因此改用固定文件名。
   - 探针文件必须在比对后删除，不得留在 `staging` 里；删除失败时如实说明残留路径，不得默认为已清理。
   - 成功显示 `chrome_devtools 工作区写权限 = 可用`。
   - 报 `Access denied` 或 `is not within any of the configured workspace roots` 时显示 `不可用，原因：MCP 未放开当前工作区写权限`。修复按 `执行单元/取数环境搭建.md` 第 1 节的口径做：**改配置由你自己动手** —— 在当前客户端的用户级 MCP 配置里给 `chrome_devtools` 增加 `--workspace=<当前工作区根目录>` 或 `--allow-unrestricted-paths`；**只有让配置生效的那一步才交给用户**（WorkBuddy 是重启客户端 + 去「连接器管理 → 右上角自定义连接器」重新 Trust 一次；其他客户端按各自的重载 / 放行机制写）。改完必须重跑本节检查才算通过。
   - 本项必须在任何需要写 Chrome 中转文件的步骤之前完成，避免取数跑到中途才被拒。
3. 按 `配置项判定规则` 判定 `JUSTONEAPI_TOKEN`：已配置时显示 `JustOneAPI 可用性 = 已配置，选择后通过真实请求验证`，否则显示 `JustOneAPI 可用性 = 未配置`。
4. 当 `是否涉及 ASR = 是` 时，按 `配置项判定规则` 判定 `VOLCENGINE_SPEECH_API_KEY`：非空时显示 `本地火山 ASR = 已配置`，为空时显示 `未配置`。留空就是没有转写能力：转写只能用用户自己的火山 Key，没有内置试用通道。该检查只确认本地配置，不发起 ASR 请求；实际调用由后续视频文案步骤按已选服务执行（同一内容最多尝试 3 次，只对可恢复失败重试）。不涉及 ASR 时报告 `不适用`。

## 输出

每次检查都必须返回以下环境状态，并保留真实失败原因：

- `chrome_devtools 可用性`：`可用`，或 `不可用，原因：<真实原因>`。
- `chrome_devtools 工作区写权限`：`可用`，或 `不可用，原因：MCP 未放开当前工作区写权限`；`chrome_devtools` 本身不可用时报告 `不适用`。
- `JustOneAPI 可用性`：`已配置，选择后通过真实请求验证`，或 `未配置`。
- `本地火山 ASR 配置状态`：`已配置`、`未配置`，或 `不适用`（当 `是否涉及 ASR = 否`）。
- `配置提示`：仅给出与上述缺失配置对应的提示，不把“已配置”表述为服务调用已成功。

检查完成后，执行一次配置状态上报（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind check --chrome <可用|不可用> --api <已配置|未配置> --asr <已配置|未配置>
```

- `--chrome`：取 `chrome_devtools 可用性`，填 `可用` 或 `不可用`。
- `--api`：取 `JustOneAPI 可用性`，填 `已配置` 或 `未配置`。
- `--asr`：取 `本地火山 ASR 配置状态`，填 `已配置` 或 `未配置`。

这一条只报「有没有配好」，不报用户选了哪个数据源。

<br />

## 处理约束

- 无默认数据源；不得自动尝试、排序推荐，不得静默回退。
- 调用方不得把用户选择或已尝试来源伪装成环境检查结果传入本执行单元。
- 检查结果不设置默认数据源；数据源选择必须由用户在调用方展示固定文案后明确确认。
- 本执行单元不读写业务文件。
