# 账号链接规范化与判断协议

本执行单元只负责把用户提供的原始输入转换成本轮唯一的标准账号主页链接，并输出判定状态；不采集账号数据、不写入正式 CSV、不展示面向用户的固定文案，也不等待用户选择。具体业务流程负责读取账号库、展示固定用户文案、承接用户选择并启动后续取数。

## 输入

- `原始输入`：本轮的候选链接或整段分享文案。没有链接时，由业务流程先按自己的规则从账号库取出候选，再传入本执行单元。
- `self 链接处理`：`登录态解析` 或 `直接拒绝`。我方账号流程传 `登录态解析`；对标账号流程传 `直接拒绝`。
- `当前工作区根目录`：用于调用本地执行器。
- `本轮已知身份`（可选）：本轮账号已有的 `平台 / 账号ID`，用于判断新解析出的身份是否与已有身份冲突；不传时跳过该判断。

## 规范化

对 `原始输入` 调用：

```bash
python3 "<当前工作区根目录>/执行单元/JustOneAPI账号基础抓取执行器.py" \
  --account-url "<原始输入>" \
  --normalize-only
```

本调用不读取 JustOneAPI 配置、不调用付费接口，只负责从整段分享文案中提取链接、展开支持的主页短链、判断是否为账号主页，并输出标准主页链接。

成功后把返回的 `account_url` 作为本轮唯一标准主页链接交给业务流程冻结；后续步骤不得继续使用原始短链、分享文案或带跟踪参数的链接。

账号库中已经登记的链接必须同样经过本节规范化后再使用，不得直接沿用账号库中的原始文本。

小红书 `xsec_token`、`xsec_source` 等查询参数只属于访问上下文，不属于账号身份；例如 `https://www.xiaohongshu.com/user/profile/<用户ID>?xsec_token=...` 必须规范化为 `https://www.xiaohongshu.com/user/profile/<用户ID>`。

## 判定与分支

按执行器返回处理：

- `ok = true`：输出 `标准主页链接` 与 `平台`。返回的标准链接与本轮 `已知身份` 的平台或账号 ID 冲突时，输出 `身份冲突`，由业务流程停止处理并说明冲突，不得用新身份覆盖本轮账号。
- `error_code = account_url_requires_login_resolution`：抖音 `user/self`，按 `self 链接处理` 进入 `self 链接的两种处理`。
- `error_code = account_url_not_profile`：输出 `非主页链接`，附执行器返回的真实原因和对应平台正确示例。
- 其他失败（含 `account_short_url_unavailable`、`account_short_url_redirect_limit`、`unsupported_account_url`、`invalid_account_url`）：输出 `规范化失败`，附执行器返回的真实原因和对应平台正确示例。
- 返回无法解析、状态缺失或自相矛盾：输出 `状态不可用`，附真实原因；不得改为猜测链接身份。

## `self` 链接的两种处理

### `self 链接处理 = 登录态解析`

先只读调用 `mcp__chrome_devtools__list_pages` 检查可用性。不可用时输出 `需要用户选择路径`，真实原因为 `chrome_devtools 不可用`，不进入下面的解析动作。

可用时使用当前已登录抖音的 Chrome 打开 `https://www.douyin.com/user/self`，等待页面完成加载。地址栏仍为 `user/self` 不得直接判定失败，也不得从页面任意 `/user/<id>` 链接猜测账号身份。

先调用 `list_network_requests`，只检查当前页面的 `xhr / fetch` 请求，找到抖音主页作品请求 `/aweme/v1/web/aweme/post/`。从该请求的 `sec_user_id` 参数读取真实 `sec_uid`；如果列表只返回请求编号，再调用 `get_network_request` 读取完整请求。必要时再从页面结构化数据读取 `secUid / sec_uid` 作为交叉验证。

`get_network_request` 不得内联返回，只能把结果写入文件后读取；内联返回会带出 Cookie 等敏感信息。

第一次没有找到该请求时，先重载一次页面再查；重载后仍取不到真实 ID，输出 `需要用户选择路径`，真实原因为 `未取得真实账号 ID`，不再继续重试。

只有真实 `sec_uid` 非空、不是 `self`，并且与页面显示的当前账号身份一致时，才规范化为 `https://www.douyin.com/user/<sec_uid>` 并输出为 `标准主页链接`。

本分支只解析链接身份，不采集账号数据，也不代表用户已经选择 `chrome_devtools` 作为本轮数据源。

### `self 链接处理 = 直接拒绝`

输出 `不适用于本流程`，附执行器返回的真实原因。不做登录态解析，不调用 `chrome_devtools`，也不得把 `self` 交给 JustOneAPI 重试。

## 输出

每次调用都必须返回以下状态之一，并保留真实原因：

- `ok`：`标准主页链接 / 平台 / 输入类型`。
- `身份冲突`。
- `非主页链接`。
- `规范化失败`。
- `状态不可用`。
- `需要用户选择路径`：`self` 链接无法自动解析时返回，附真实原因（`chrome_devtools 不可用` 或 `未取得真实账号 ID`）。
- `不适用于本流程`。

输出只包含链接身份与判定状态，不包含账号昵称、粉丝数、作品数据或任何正文内容。

## 处理约束

- 不得猜测账号身份：链接无法解析时如实输出真实原因，不得根据链接文本、页面其他链接、历史结果或旧对话推断。
- 不得把未经过本执行单元的标准链接传给下游取数、建档或任何 API 调用。
- 不得把 `self` 交给 JustOneAPI 重试，也不得因某个数据源不可用就改用另一数据源解析链接身份。
- 本执行单元不展示面向用户的固定文案，不等待用户选择；`self` 场景下用户可选的路径由业务流程负责展示和处理。
- 本执行单元不读写业务文件。
