# 创作者中心取账号基础信息

我方账号专用的取数契约。和对标账号那份 `获取账号基础信息.md` 的区别只有一处：**数据从用户已登录的创作者中心后台取，不打开公开主页**（2026-11-01 起）。用户全程只需要只在自己正在用的 Chrome 里登录创作者中心一个页面。

对标账号没有后台权限，仍走 `获取账号基础信息.md`，两份互不影响。

## 输入

```yaml
平台: 小红书 | 抖音
创作者中心链接: string
账号ID: string          # 可选；传了就用来校验读出来的确实是这个账号
本轮暂存目录: string
中转清单:            # 与其他 Chrome 执行单元同一份
  network_response: string
```

说明：

- `平台`、`创作者中心链接`、`本轮暂存目录` 必填
- `账号ID` 传了就必须和页面读出来的一致，不一致返回失败 `身份不一致`
- 本执行单元固定使用 `chrome_devtools`
- 只取账号级基础信息并写入候选 JSON，不采集内容、不直接回写账号库

## 处理

### 1. 校验输入

1. `平台` 不是 `小红书` 或 `抖音` 时返回失败 `平台不支持创作者中心取数`。
2. `创作者中心链接` 为空返回失败 `创作者中心链接缺失`。
3. `本轮暂存目录` 为空返回失败 `本轮暂存目录缺失`。

### 2. 确认页面还在

1. 先 `list_pages`。已经开着对应创作者中心页面就直接用，**不刷新、不重开**。
2. 没有就 `new_page` 打开：小红书 `https://creator.xiaohongshu.com/new/home`，抖音 `https://creator.douyin.com/creator-micro/home`。
3. 打开后等页面加载完成。
4. 页面停在登录页，或资料请求返回未登录，返回失败 `创作者中心未登录`。
5. 不许关窗口、不许关创作者中心页面 —— 取完资料也留着，后面取内容列表和截图还要用同一个页面。

### 3. 读账号资料

用 `list_network_requests` 找下列请求，再用 `get_network_request` 读响应体。调用 `get_network_request` 时必须把 `中转清单.network_response` 作为 `responseFilePath`；不得传 `output_path`，不得从工具展示文本里抠 JSON。

页面已经加载完时这些请求就在记录里，**不要为了触发请求去刷新页面**。确实一条都没有（页面刚开还没加载完），等页面稳定后再 `list_network_requests` 一次；仍没有才返回失败 `账号资料请求缺失`。

#### 小红书

| 请求 | 用途 |
| --- | --- |
| `/api/galaxy/user/info` | 账号ID、账号名、简介 |
| `/api/galaxy/creator/home/personal_info` | 关注数、粉丝数、获赞、头像 |

字段映射（2026-11-01 实测）：

- `账号ID` <- `user/info` 的 `data.userId`
- `账号名` <- `personal_info` 的 `data.name`（缺失时兼容 `user/info` 的 `data.userName`）
- `简介` <- `personal_info` 的 `data.personal_desc`（兼容 `user/info` 的 `data.userDesc`）
- `关注数` <- `personal_info` 的 `data.follow_count`
- `粉丝数` <- `personal_info` 的 `data.fans_count`
- `获赞数` <- `personal_info` 的 `data.faved_count`（创作者中心页面标签是「获赞」）
- `头像原链接` <- `personal_info` 的 `data.avatar`
- `主页链接` <- `https://www.xiaohongshu.com/user/profile/<账号ID>`
- `性别`、`标签` <- 创作者中心不提供，留空

#### 抖音

主读 `/aweme/v1/creator/user/info/` 的 `user_profile`；`/web/api/media/user/info/` 的 `user` 只作兜底。

字段映射（2026-11-01 实测）：

- `账号ID` <- `user_profile.secret_id`（即 sec_uid）
- `账号名` <- `user_profile.nick_name`
- `简介` <- `user_profile.signature`
- `性别` <- `user_profile.gender`（`1` 写 `男`，`2` 写 `女`，其他留空）
- `关注数` <- `user_profile.following_count`
- `粉丝数` <- `user_profile.follower_count`
- `获赞数` <- `user_profile.total_favorited`
- `头像原链接` <- `user_profile.avatar_url`
- `主页链接` <- `https://www.douyin.com/user/<secret_id>`
- `标签` <- 创作者中心不提供，留空

`secret_id` 缺失时**不要**拿 `unique_id`（抖音号）顶替——两者不是一回事，主页链接会拼错。此时按 `账号基础信息缺失` 处理。

### 4. 处理缺失字段和头像

- `平台`、`账号ID`、`账号名`、`主页链接` 任一仍为空，返回失败 `账号基础信息缺失`。
- 页面导航、遮罩变化或读取失败后，之前 `take_snapshot` 返回的所有 `uid` 均视为失效；必须重新 snapshot 后再点击，不得复用旧 uid。
- `头像原链接` 仅作为下载本地头像的来源；不得把远程头像 URL 直接写入 `头像路径` 或作为工作台图片源。
- 取得 `头像原链接` 后固定尽量下载一次，保存到本轮暂存目录，并输出 `头像临时文件路径`。
- 头像链接缺失、下载超时、格式不支持或保存失败时，固定输出非阻断的 `头像获取状态 / 头像获取提示`，`头像临时文件路径` 留空；不得因此返回失败，也不得影响账号基础字段和内容列表获取。

### 5. 保存和校验

1. 将本执行单元的完整结构化结果保存为 `<本轮暂存目录>/账号基础信息.json`。
2. 重新读取该文件，确认它是有效 JSON；成功结果必须确认 `平台 / 账号ID / 账号名 / 主页链接` 非空。

### 禁止动作

- 禁止在本执行单元内直接拼接或覆盖 `我方账号库.csv`
- 禁止在终端里用 heredoc 或一次性长脚本替代 `账号基础数据建档批处理.py`
- 禁止通过 Shell、curl、Python、Node 或其他 API 重新抓取账号数据
- 禁止为了拿基础信息去打开 `www.xiaohongshu.com` / `www.douyin.com` 的账号主页
- 禁止只在对话中返回账号信息而不写入 `账号基础信息.json`

## 输出

```yaml
状态: 成功 | 失败
基础数据获取方式: chrome_devtools
平台: 小红书 | 抖音
账号ID: string
账号名: string
简介: string
性别: string
关注数: string
粉丝数: string
获赞数: string
标签: string
主页链接: string
头像原链接: string
头像获取状态: 成功 | 失败 | 跳过
头像临时文件路径: string
头像获取提示: string
失败原因: string
```

说明：

- 输出文件固定为 `<本轮暂存目录>/账号基础信息.json`
- 成功时必须返回 `状态`、`基础数据获取方式`、`平台`、`账号ID`、`账号名`、`主页链接`
- `简介`、`性别`、`关注数`、`粉丝数`、`获赞数`、`标签`、`头像原链接`、`头像临时文件路径` 允许阶段性为空
- `头像获取状态 = 失败 | 跳过` 仍属于账号基础信息成功，不得写入 `失败原因`
- 失败时必须返回 `状态`、`失败原因`，并把失败结果写入同一个输出文件
