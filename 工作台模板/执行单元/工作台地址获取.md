# 工作台地址获取协议

本执行单元只负责在需要反馈工作台链接时取得本机工作台的真实基础地址；不启动工作台以外的服务、不猜测端口、不写入业务文件。

## 背景

多个流程的结果反馈需要填写 `<dashboard_base_url>`（例如账号详细分析、内容生产、规划分析）。这些流程同时规定：

- 只能使用工作台真实返回的地址；
- 不得猜测端口、基础地址或页面路径；
- 工作台未启动或未返回地址时，相关链接固定写 `工作台未打开`，但不阻断正式结果反馈。

因此调用方必须先用下面的固定方式取址，再决定填地址还是填 `工作台未打开`。

## 取址方式

查询本机工作台当前状态：

```bash
node "<当前工作区根目录>/工作台/launcher.mjs" status \
  --workspace "<当前工作区根目录绝对路径>"
```

工作台已在运行时返回：

```json
{"ok":true,"running":true,"stale":false,"pid":<进程号>,"url":"<基础地址>","revision":<版本>,"workspace":{"name":"<工作区名>","version":"<版本>"}}
```

判定规则：

- `ok = true` 且 `running = true`，且 `url` 为非空 `http://` 或 `https://` 地址：把 `url` 原样作为 `<dashboard_base_url>`，不得改写、不得补路径、不得替换端口。
- `running = false`：工作台未启动。**先启动一次再取址**：按 `skills/dashboard/SKILL.md` 规定的启动方式起 `node "<当前工作区根目录>/工作台/launcher.mjs" start --workspace "<当前工作区根目录绝对路径>"` —— **必须让它在本次命令结束后还能继续跑**（普通前台命令、`&`、`nohup` 起的会被回收）。**`start` 返回成功不等于它还在**：等 3~5 秒后重新跑一次本节的状态查询做复验，复验仍 `running = true` 才把 `url` 当取到的地址给用户；复验没过就换另一种启动方式重来再验，两次都没留住按未取到地址处理。`start` 自带健康检查，进程还活着会直接复用原地址，所以启动过也不代表这次能跳过 —— 每次要反馈工作台链接，都照本节重跑一遍。
- `stale = true`：登记信息已失效。按未启动处理。
- `url` 缺失、为空或不是 `http(s)` 地址：按未取到地址处理。
- 命令执行成功但**输出为空**（退出码 `0`、stdout 无内容）：按未取到地址处理，不得据此认定工作台目录缺失。
- `stale = true` 且已确认工作台正在运行时：按未取到地址处理，不要用历史地址顶替。
- 命令执行失败（工作台目录缺失、Node 不可用、权限错误等）：按未取到地址处理，并在反馈里说明真实原因。

工作区路径若含符号链接（例如位于 `/tmp`、`/var` 或经云盘同步的目录下），无需自行转换：`launcher.mjs` 会把路径归一到真实路径后判定工作区身份。若同一工作台在本机确实运行时仍返回 `running = false`，按未取到地址处理，并在反馈里说明这一现象，不得改用历史地址。

未取到地址时，所有工作台链接固定写 `工作台未打开`，其余正式结果照常反馈，不得因此中断本轮。

## 拼接规则

取到 `<dashboard_base_url>` 后，各流程按自己的固定页面路径拼接，不得自行改路径。例如：

- 对标账号列表：`<dashboard_base_url>/index.html#benchmark-accounts`
- 当前账号档案：`<dashboard_base_url>/account?kind=benchmark&id=<账号ID>`
- 我的账号档案：`<dashboard_base_url>/account?kind=own&id=<账号ID>`

具体路径以各流程文档的规定为准。

## 处理约束

- 不得把 `127.0.0.1`、`localhost` 或任何端口的推测值直接写进反馈。
- 不得用静态端口探测、历史对话记录、上次运行结果或页面标题代替本节的实际取址调用。**客户端重启过之后（配置 / 重载 MCP、升级后重载都会），之前那次工作台进程一定已经没了，上一次给用户的地址随之作废 —— 每次都按本节现取，不复用旧地址；重启后要给地址，必须先重新启动并复验。**
- **不要把「`start` 命令返回成功」当成「工作台起来了」**：那只说明那一刻它活着。用会被回收的方式起时，命令一结束它就没了 —— 所以必须按本节隔几秒再复验一次，通过了才把地址给用户。
- 不得因为取不到工作台地址就停止或推迟正式结果反馈。
- 本执行单元不启动目标平台的浏览器会话，也不读取业务数据。
