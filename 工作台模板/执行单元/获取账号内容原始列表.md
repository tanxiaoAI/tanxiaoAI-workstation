# 获取账号内容原始列表

## 输入

```yaml
账号基础信息:
  平台: 小红书 | 抖音 | B站
  账号ID: string
  账号名: string
  主页链接: string
本轮暂存目录: string
内容数量上限: integer  # 可选；>0 时达到上限即停止滚动和逐条补取
中转清单:
  manifest_json: string
  stage1_json: string
  screenshot_png: string
```

说明：

- `账号基础信息.平台`、`账号基础信息.账号ID`、`账号基础信息.账号名`、`账号基础信息.主页链接` 必填
- `本轮暂存目录` 必填；候选 JSON、截图和截图结果由中转脚本校验后写入该目录
- `内容数量上限` 可选；缺省或 `0` 表示不设上限。大于 `0` 时，本执行单元最多保留该条数，达到上限即停止滚动、翻页和逐条补取
- 所有获取到的内容都保留；本执行单元只记录每条内容的 `公开状态`，不删除私密、草稿或其他非公开内容
- 本执行单元固定使用 `chrome_devtools`
- 本执行单元只负责获取账号级内容列表索引、主页长截图并写入中转清单指定的阶段结果，不直接回写 `账号库.csv` 或 `内容列表.csv`
- 阶段结果和截图先写入中转清单指定的工作区 `chrome-inbox` 路径；由 `Chrome采集临时文件中转.py finalize` 校验后，统一生成本轮暂存目录中的候选文件

## 处理

本执行单元按以下阶段执行。阶段失败时保留真实失败原因并停止，不改变业务状态判定。

### 阶段一：输入和页面

检查 `账号基础信息.平台`、`账号基础信息.账号ID`、`账号基础信息.账号名`、`账号基础信息.主页链接`、`本轮暂存目录` 和中转清单的 `manifest_json / stage1_json / screenshot_png` 是否齐全，并确认本阶段的任务是获取账号级内容列表索引，不获取内容详情，也不直接写入正式 CSV。

继续使用基础信息阶段保留的 Chrome 标签页，打开或复用账号主页，等待页面完成加载，并记录实际页面 URL、标签页标识和页面就绪状态。关键输入缺失时，记录失败原因 `获取账号内容原始列表输入不完整` 并停止。

### 阶段二：获取候选作品

本阶段按固定协作链执行，不由 AI 自由挑选工具。正常主链只使用当前已连接的 `chrome_devtools`，不得调用 Codex 内置浏览器、`list_mcp_resources`、`read_mcp_resource`、Shell、Node 或 Python 重新采集页面。

1. 如果当前页面还没有选中“作品”标签，使用最近一次有效 `take_snapshot` 获取该标签的 `uid`；没有有效快照时最多调用一次 `take_snapshot`。随后调用一次 `click` 切换到作品列表，点击后等待列表稳定，不能点击其他标签或反复切换。
2. 先获取最新页面快照并用 `evaluate_script` 从当前 DOM/结构化状态提取作品候选。对每条候选固定检查以下字段：`平台原生内容ID` 与 `对外页面链接` 至少一个非空、`点赞数` 非空、`发布时间` 非空、`媒介形式` 不是空值且不是 `未知`。只有全部候选都满足这四项检查时，才允许跳过 Network 请求扫描。
3. 只要任一候选不满足上一步任一检查项，必须调用一次 `list_network_requests`，只读取当前页面本次导航产生的 `xhr/fetch` 请求，不使用历史保留请求，不通过改变 `pageSize` 重复扫描。按返回的 URL、请求类型和响应特征筛选作品列表请求。该固定兜底调用不要求 AI 自行判断“关键字段”，也不触发额外工具试探。
4. 对筛选出的列表请求调用 `get_network_request` 读取响应正文，最多读取 `3` 个最相关请求；优先主列表响应，重复响应或无关响应不再读取。每次调用都必须把中转清单返回的 `network_response` 路径作为 `responseFilePath` 传入，禁止使用 `output_path`、临时猜测路径或从工具返回文本中复制 JSON。调用成功后必须从该文件读取原始响应，再解析候选；文件没有生成或 JSON 无法解析时记录真实失败原因。没有匹配请求时，继续使用已有的结构化状态和 DOM 候选，不把它直接判为失败。
5. `evaluate_script` 允许根据当前页面结构选择 DOM 定位方式，但只能返回紧凑 JSON，字段限定为：账号名、简介、关注数、粉丝数、获赞数、头像；内容 ID、标题、内容链接、封面、媒介形式、点赞数、发布时间；以及 `scrollY`、`clientHeight`、`scrollHeight`。禁止读取或返回 `document.scripts`、`script` 标签全文、`window.__INITIAL_STATE__` 原文、全量 `window`、全页面 `outerHTML` 或与账号和内容卡片无关的页面源码。不得先假设固定对象路径（例如 `user.notes`），以当前页面实际存在的对象和 DOM 结构为准。脚本不要直接返回对象，必须返回普通 JSON 字符串。循环引用安全的返回方式固定为：

   ```javascript
   const seen = new WeakSet();
   return JSON.stringify(candidate, (key, value) => {
     if (value && typeof value === "object") {
       if (seen.has(value)) return undefined;
       seen.add(value);
     }
     return value;
   });
   ```

   调用方再对返回字符串执行 `JSON.parse`。脚本执行成功并返回至少一条有效内容后，立即使用结果；脚本发生语法错误时，原样重试同一脚本一次。重试仍失败时，使用已有 DOM 快照和 Network 候选继续落盘，不得重新猜对象路径、搜索源码或编写第三套脚本。除第 3 步规定的固定 Network 兜底外，字段不完整不触发额外工具试探。返回过宽（包含整页脚本或原始页面源码）视为无效脚本结果，不得继续分析该源码。降级候选必须保留脚本原始返回的全部允许字段，尤其是 `type / time / publish_time / create_time`，不得先投影成只有标题、封面、点赞的窄对象。
6. 将 Network（如已调用）、结构化状态和 DOM 得到的候选合并去重。每条候选尽量提取 `平台原生内容ID`、`标题`、`封面图原链接`、`媒介形式`、`点赞数`、`发布时间`、`公开状态` 和 `对外页面链接`；按稳定的对外页面链接优先、平台原生内容 ID 兜底合并，已有非空字段不得被空值覆盖。Network 有值时，`type / time` 等原始字段必须传入候选，不能因为后续使用 DOM 降级就静默丢弃。

阶段二不负责滚动，滚动固定留给阶段三；不调用 `list_pages` 或 `take_screenshot`。只拿到作品索引但没有拿到其他字段时，保留已有候选并进入阶段三；没有取得候选时，保留页面状态和真实失败原因，继续完成阶段三的滚动确认，不自行切换工具。

### 阶段三：滚动和去重

7. `CONTENT-07`：滚动只用于补充当前页面没有显示出来的内容，不用于判断本轮是否完成：
   - 首先保留当前已识别的所有有效内容；
   - 根据最新页面快照选择滚动对象；
   - 每次滚动后只检查是否出现新的内容 ID；
   - 有新增就合并，没有新增就停止；
   - 已识别内容条数达到 `内容数量上限`（大于 `0` 时）立即停止滚动，并在停止原因写明「达到本轮内容数量上限 N 条」；
   - 无法识别滚动对象时停止滚动，但保留已经取得的内容；
   - 不因停止滚动把已经取得的内容降级；
   - 不因停止滚动自动触发第二轮采集；
   - 连续 `2` 次滚动没有新增或达到 `20` 轮时停止，仅记录停止原因。
8. `CONTENT-08`：停止滚动不改变内容列表状态，也不触发重试；达到数量上限同样按已取得内容继续，不触发重试。

### 阶段四：主页截图

9. `CONTENT-09`：内容列表抓取结束后重新导航到账号主页，再执行长截图：
   - 内容滚动完成后，重新导航到同一账号主页，等待首屏和页面布局恢复；不得对已经加载全部作品的超长 DOM 直接截图；
   - 导航、遮罩变化或截图失败会使旧 `take_snapshot` 的全部 `uid` 立即失效；重新取得 snapshot 后才允许任何点击，截图失败时直接重新导航，不得点击旧 uid；
   - 固定调用 Chrome 截图工具，`fullPage = true`，`format = png`；
   - 截图输出路径固定为 `中转清单.screenshot_png`；
   - 结果记录由 `Chrome采集临时文件中转.py finalize` 写入 `<本轮暂存目录>/主页长截图结果.json`；
   - 截图结果 JSON 必须记录真实的 `fullPage = true` 和 `format = png`。

### 阶段五：映射和状态判定

10. `CONTENT-10`：平台字段映射固定如下。页面字段缺失时留空或写 `未知`，不得用猜测值补齐；任何字段都不得从身份/账号节点（`author`、`user`、`owner`、`account`、`profile`、`creator`）或音乐节点（`music` 等）里取——那里放的是账号头像与音频封面，不是作品字段：

| 平台 | 平台原生内容 ID | 标题 | 封面图原链接 | 媒介形式 | 公开状态 | 点赞数 | 发布时间 | 对外页面链接 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 小红书 | `note_id` | `title` | `cover` | `type`；缺失写 `未知` | `corner`（页面结构化数据与列表接口都带该字段；值为 `仅自己可见` 时写 `私密`，**为空时写 `公开`**——该字段只用于标注非公开笔记，公开笔记上它本身就是空的，2026-09-14 实测 69 条里 8 条公开笔记 `corner` 均为空；字段整体缺失、连键都取不到时才写 `未知`） | 优先 `noteDetailMap[<note_id>].note.interactInfo.likedCount`；兼容 `interactInfo.likedCount`、`interact_info.liked_count` | `time` / `publish_time` / `create_time` | 必须优先保留页面已有完整 `href`（包括 `xsec_source`、`xsec_token`）；确实没有链接时才由 `note_id` 生成带 `?xsec_source=pc_feed` 的降级链接 |
| 抖音 | `aweme_id` | `desc` | `video.cover` | 按作品结构判定：图文节点（`images` / `image_list` / `image_infos` / `img_bitrate` / `original_images`）非空写 `图文`，否则写 `视频`；不依赖数字枚举 | `status.private_status`（`1` 写 `私密`，`0` 为非私密；不得因为键名相近写成 `privacy_status`） | `statistics.digg_count` | `create_time` / `publish_time` | 页面已有链接；缺失时由 `aweme_id` 组合 |
| B站 | `bvid` | `title` | `cover` | `视频` | 投稿列表的可见性标注（明确标注「仅自己可见」时写 `私密`） | `data.stat.like`（来自 `x/web-interface/view`，列表接口没有该字段，需逐条补取，见下方提示） | `pubdate` / `publish_time` | 由 `bvid` 组合标准页面链接 |

经验提示（非契约，以本轮探索为准）：抖音主页作品卡片只有索引级信息，不含发布时间，发布时间只存在于详情接口响应里。因此本阶段“最多读取 `3` 个列表请求”的上限，会直接决定有多少条带发布时间，这个边界必须写进 `内容列表停止原因`。另：作品链接存在多种类型（视频、图文、长文），采集索引时不能只匹配一种。

**B站「点赞数」补取的可执行做法**（2026-09-14 实测，36/36 成功，属本阶段的规定动作而非可选优化）：

1. **取数方式**：用 `evaluate_script` 在**当前已登录的 B站 页面上下文**里直接发请求：`fetch("https://api.bilibili.com/x/web-interface/view?bvid=<bvid>", {credentials:'include'})`，取 `data.stat.like`。该接口返回 200 且 `code: 0`，不需要额外签名。
2. **分批执行**：每批 12~18 条，批内每条之间间隔约 200ms，避免单次脚本调用超时。
3. **断点续取**：把本轮已取到的结果累积写进 `中转清单.stage1_json` 同目录下的 `B站点赞数补取结果.json`，内容形如 `{"<bvid>": "<点赞数>"}`，**每批结束后覆写一次**。重新进入本阶段、或需要补跑时，先读该文件，只补取其中没有的 `bvid`，已取到的直接复用，不重复发请求。该文件只作本阶段的中间缓存，不进入正式产物，也不参与 `finalize` 校验。
4. **失败重试**：全部批次跑完后，对本轮仍未取到的 `bvid`（即第 3 步缓存里缺的那些）统一重试一次；重试仍失败的才写 `未知`。
5. **规模告警**：本轮需要补取的内容条数超过 `100` 时，必须在 `内容列表停止原因` 里写明本轮需逐条补取点赞数的实际条数，以及「短时间内大量请求可能触发平台风控、耗时较长」的提示。达到 `内容数量上限` 时，只对本轮保留范围内且缺少点赞数的条目补取，不再向外扩大范围。
6. 单条最终仍取不到时（非 `code 0`、异常或超时，含第 4 步重试后仍失败），该条「点赞数」写 `未知`，**不得用 `play` 顶替**；失败条数必须写进 `内容列表停止原因`。
7. 该补取属于本阶段字段映射的必要组成，不受“本阶段只读列表请求”的限制。

11. `CONTENT-11`：每条 `账号内容原始列表` 记录固定包含：`平台原生内容ID`、`平台`、`账号ID`、`账号名`、`标题`、`封面图原链接`、`媒介形式`、`公开状态`、`点赞数`、`发布时间`、`对外页面链接`、`基础数据获取方式`；`bvid / aid / cid` 仅在 `B站` 有对应值时填写。

公开状态唯一规范：`公开、草稿、私密、其他、未知`。`仅自己可见` 统一写 `私密`；`未发布` 统一写 `草稿`；没有拿到状态写 `未知`；拿到但不属于前三种的明确状态写 `其他`。必须按上表的平台来源字段实际取值，不得因为"反正下游会兜底"就一律写 `未知`。兜底规则以建档批处理为准：在唯一的正式合并边界上，对标账号的公开状态一律规范化为 `公开`（对标取数只接受公开主页的内容），我方账号的 `未知` 也规范化为 `公开`；因此 `未知` 不会中断详细数据流程。即便如此，取不到时仍必须在 `内容列表停止原因` 里写明是哪个字段没拿到。

媒介形式唯一规范：`视频、图文、其他、未知`。抖音按作品结构判定（见上表）；B站默认 `视频`、小红书默认 `未知`，该默认值只在接口字段完全缺失时使用；明确但无法归入视频或图文的值写 `其他`。

12. `CONTENT-12`：`内容列表获取状态` 固定只允许：`成功、失败`。
13. `CONTENT-13`：判定规则固定如下：
   - `成功`：拿到并规范化了至少一条有效内容；是否还有遗漏不参与状态判断。
   - `成功（确认空列表）`：当前主页已正常加载、作品列表已完成规定的页面与滚动检查、没有取得任何候选，且页面明确显示无作品或等价空列表状态。此时固定写入 `账号内容原始列表 = []`、`内容列表为空原因 = no_public_content`；是否截图成功不影响该判定。
   - `失败`：页面不可用，或未取得可识别内容且也无法依据页面明确空列表状态确认账号无内容。
   - 无论最终取哪一种状态，`内容列表停止原因` 都必须写清本轮为什么停止、以及是否拿到平台给出的结束信号；确实拿到时必须明确写出「已到达列表末尾」（例如接口返回 `has_more = false`、页面明确显示没有更多内容、已读到列表末页），没有写就视为未确认。下游的 `内容列表完整性` 只认这一句声明，不认滚动次数、也不认条数是否稳定。滚动停止和条数稳定都不等于账号内容已经全部加载完。
14. `CONTENT-14`：顶层 `状态` 与 `内容列表获取状态` 的关系固定如下：
   - `内容列表获取状态 = 成功` 时，顶层 `状态 = 成功`
   - `内容列表获取状态 = 失败` 时，顶层 `状态 = 失败`
15. `CONTENT-15`：如果 `内容列表获取状态 = 失败`，固定补充默认结果：
   - `账号内容原始列表 = []`
   - `主页长截图状态 = 跳过`
   - `主页长截图路径 = 空`
   - `主页长截图结果JSON路径 = 空`
16. `CONTENT-16`：如果当前步骤成功，固定返回：
   - `账号内容原始列表`
   - `内容列表获取状态`
   - `内容列表为空原因`；仅确认空列表时为 `no_public_content`，其他成功场景为空
   - `内容列表停止原因`
   - `内容列表停止位置`
   - `主页长截图状态`
   - `主页长截图路径`
   - `主页长截图结果JSON路径`
   - `主页长截图失败原因`
17. `CONTENT-17`：将本执行单元返回的完整结构化阶段结果保存为 `中转清单.stage1_json`；候选 JSON 由 `Chrome采集临时文件中转.py finalize` 校验后写入 `<本轮暂存目录>/账号内容原始列表.json`。
18. `CONTENT-18`：由 `Chrome采集临时文件中转.py finalize` 重新读取阶段结果并校验候选 JSON；`主页长截图状态 = 成功` 时，确认截图和截图结果 JSON 真实存在。

禁止动作：

- 禁止在本执行单元内直接拼接或覆盖正式 `内容列表.csv`
- 禁止在终端里用 heredoc 或一次性长脚本替代 `账号基础数据建档批处理.py`
- 禁止通过 Shell、curl、Python、Node 或其他 API 重新抓取账号主页数据
- 禁止只在对话中返回内容列表而不写入中转清单指定的阶段结果 JSON
