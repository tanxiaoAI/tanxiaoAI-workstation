# 获取账号基础信息

## 输入

```yaml
账号主页链接: string
本轮暂存目录: string
```

说明：

- `账号主页链接` 必填，且应为单个账号主页链接
- `本轮暂存目录` 必填
- 本执行单元固定使用 `chrome_devtools`
- 本执行单元只负责获取账号基础信息并写入候选 JSON，不直接回写账号库

## 处理

### 1. 校验输入

按以下顺序检查：

1. 检查 `账号主页链接` 是否存在。
2. 如果链接为空，返回失败：`账号主页链接缺失`。
3. 识别链接所属平台，当前只允许 `小红书 / 抖音 / B站`。
4. 如果平台无法识别，返回失败：`链接无法识别`。
5. 如果链接不是账号主页链接，返回失败：`当前链接不是账号主页链接`。

### 2. 打开并读取页面

1. 连接本机已登录的 `Chrome`。
2. 新开标签页，或复用本轮已经打开的账号主页标签页。
3. 打开 `账号主页链接`，等待页面加载和跳转完成。
4. 按以下优先级读取账号信息：
   - 优先读取页面结构化状态中的完整账号基础信息。
   - 结构化状态缺字段时，从 DOM 补齐缺失字段。
   - DOM 仍缺字段时，从 Network 补齐缺失字段。

只有在结构化状态和 DOM 仍缺少 `平台 / 账号ID / 账号名 / 主页链接` 中的必要字段时，才调用 `list_network_requests` 查找对应的账号资料请求，再调用 `get_network_request` 补齐缺失字段。字段已经齐全时跳过 Network，不为同一页面额外扫描请求。

Network 兜底规则：如果当前流程提供了中转清单，调用 `get_network_request` 时必须把清单提供的响应文件路径作为 `responseFilePath`；不得传 `output_path`，不得从工具展示文本中抠 JSON，也不得手工拼接响应。读取响应文件时保留原始字段，后续映射不能丢弃平台 ID、时间戳或媒介类型。

### 3. 提取账号字段

从成功结果中统一映射并尽量提取：

- `平台`
- `账号ID`
- `账号名`
- `简介`
- `性别`
- `关注数`
- `粉丝数`
- `获赞数`
- `标签`
- `主页链接`
- `头像原链接`

平台字段映射如下。

#### 小红书

2026-09-14 实测：当前页面结构下账号资料分两层——`user.userInfo` 放身份与文字资料，`user.userPageData` 放基本资料与互动计数。路径区分大小写，以下是实测值：

- `账号ID` <- `user.userInfo.userId`
- `账号名` <- `user.userInfo.nickname`（兼容 `user.userPageData.basicInfo.nickname`）
- `简介` <- `user.userInfo.desc`（兼容 `user.userPageData.basicInfo.desc`）
- `性别` <- `user.userInfo.gender`（兼容 `user.userPageData.basicInfo.gender`）
- `关注数` <- `user.userPageData.interactions[]` 里 `type = "follows"` 那一项的 `count`
- `粉丝数` <- 同上，`type = "fans"` 那一项的 `count`
- `获赞数` <- 同上，`type = "interaction"`（页面标签是「获赞与收藏」）那一项的 `count`
- `标签` <- `user.userPageData.tags`
- `主页链接` <- `https://www.xiaohongshu.com/user/profile/<账号ID>`
- `头像原链接` <- `user.userInfo.images`（兼容 `user.userPageData.basicInfo.images`）

注意：`userPageData.interactions` 是**数组**，三项按 `type` 区分（`follows` / `fans` / `interaction`），不是对象；`userPageData` 本身只有 `basicInfo`、`interactions`、`tags` 等键，没有粉丝数这类计数。

#### 抖音

- `账号ID` <- `sec_uid`
- `账号名` <- `nickname`
- `简介` <- `signature`
- `性别` <- `gender`
- `关注数` <- `following_count`
- `粉丝数` <- `follower_count`
- `获赞数` <- `total_favorited`
- `标签` <- `account_labels`
- `主页链接` <- `https://www.douyin.com/user/<sec_uid>`
- `头像原链接` <- `avatar_larger.url_list[0]`

#### B站

- `账号ID` <- `mid`
- `账号名` <- `name`
- `简介` <- `sign`
- `性别` <- `sex`
- `关注数` <- `following`
- `粉丝数` <- `follower`
- `获赞数` <- `archive.view`
- `标签` <- `tags`
- `主页链接` <- `https://space.bilibili.com/<mid>`
- `头像原链接` <- `face`

### 4. 处理缺失字段和头像

- 如果结构化状态、DOM 和 Network 仍缺少 `平台 / 账号ID / 主页链接`，允许从跳转完成后的真实账号主页链接识别平台、提取账号ID并组合标准主页链接。链接提取只作为缺失字段兜底，不替代页面账号基础信息采集。
- 页面导航、遮罩变化或读取失败后，之前 `take_snapshot` 返回的所有 `uid` 均视为失效；必须重新 snapshot 后再点击，不得复用旧 uid。
- `头像原链接` 仅作为下载本地头像的来源；不得把远程头像 URL 直接写入 `头像路径` 或作为工作台图片源。
- 取得 `头像原链接` 后固定尽量下载一次，保存到本轮暂存目录，并输出 `头像临时文件路径`。
- 头像链接缺失、下载超时、格式不支持或保存失败时，固定输出非阻断的 `头像获取状态 / 头像获取提示`，`头像临时文件路径` 留空；不得因此返回失败，也不得影响账号基础字段和内容列表获取。
- 如果 `平台 / 账号ID / 账号名 / 主页链接` 仍有缺失，返回失败：`账号基础信息缺失`。

### 5. 保存和校验

1. 将本执行单元的完整结构化结果保存为 `<本轮暂存目录>/账号基础信息.json`。
2. 重新读取该文件，确认它是有效 JSON；成功结果必须确认 `平台 / 账号ID / 账号名 / 主页链接` 非空。

### 禁止动作

- 禁止在本执行单元内直接拼接或覆盖 `对标账号库.csv` / `我方账号库.csv`
- 禁止在终端里用 heredoc 或一次性长脚本替代 `账号基础数据建档批处理.py`
- 禁止通过 Shell、curl、Python、Node 或其他 API 重新抓取账号主页数据
- 禁止只在对话中返回账号信息而不写入 `账号基础信息.json`

## 输出

```yaml
状态: 成功 | 失败
基础数据获取方式: chrome_devtools
平台: 小红书 | 抖音 | B站
账号ID: string
账号名: string
简介: string
性别: string
关注数: string
粉丝数: string
获赞数: string
标签: string
主页链接: string
头像原链接: string
头像获取状态: 成功 | 失败 | 跳过
头像临时文件路径: string
头像获取提示: string
失败原因: string
```

说明：

- 输出文件固定为 `<本轮暂存目录>/账号基础信息.json`
- 成功时必须返回 `状态`、`基础数据获取方式`、`平台`、`账号ID`、`账号名`、`主页链接`
- `简介`、`性别`、`关注数`、`粉丝数`、`获赞数`、`标签`、`头像原链接`、`头像临时文件路径` 允许阶段性为空
- `头像获取状态 = 失败 | 跳过` 仍属于账号基础信息成功，不得写入 `失败原因`
- 失败时必须返回 `状态`、`失败原因`，并把失败结果写入同一个输出文件
