# 创作者中心取内容列表

我方账号专用的取数契约。和对标账号那份 `获取账号内容原始列表.md` 的区别：**内容列表从用户已登录的创作者中心后台取，不打开公开主页**（2026-11-01 起）。用户全程只需要只在自己正在用的 Chrome 里登录创作者中心一个页面。

对标账号没有后台权限，仍走 `获取账号内容原始列表.md`，两份互不影响。

## 输入

```yaml
账号基础信息:
  平台: 小红书 | 抖音
  账号ID: string
  账号名: string
  主页链接: string
本轮暂存目录: string
内容数量上限: integer   # 可选；>0 时达到上限即停止翻页
中转清单:
  manifest_json: string
  stage1_json: string
  screenshot_png: string
```

说明：

- `账号基础信息` 四项必填；`本轮暂存目录` 必填
- `内容数量上限` 可选；缺省或 `0` 表示不设上限
- 本执行单元固定使用 `chrome_devtools`
- 本执行单元只负责账号级内容列表索引和账号页面长截图，不写 `我方账号库.csv` 或 `内容列表.csv`
- 阶段结果和截图先写入中转清单指定的工作区 `chrome-inbox` 路径；由 `Chrome采集临时文件中转.py finalize` 校验后统一写入本轮暂存目录

### 只取公开内容

**非公开内容一律不采，连标题、时间、数据也不采。** 创作者中心里「仅自己可见」「草稿」「审核中」「未通过」的条目在阶段二就过滤掉，不进入候选、不进入后续诊断和内容规律分析。

这条是用户 2026-11-01 明确的口径：不看非公开内容，也不用为了它们多登录一个页面。

**已知边界（不处理，写在这里备查）**：如果某条内容以前是公开的、已经进了内容列表，后来被你设成私密或删掉，库里那条会一直保持 `公开` 状态 —— 因为本执行单元不采非公开条目，感知不到这个变化。下次诊断可能仍把它当证据。要清掉，只能手动从内容列表删掉那一行，或把整个账号重建一遍。

## 处理

### 阶段一：输入和页面

检查 `账号基础信息` 四项、`本轮暂存目录`、中转清单的 `manifest_json / stage1_json / screenshot_png` 是否齐全。关键输入缺失时，记录失败原因 `获取我方内容列表输入不完整` 并停止。

确认创作者中心的内容管理页还在：

1. 先 `list_pages`。已经开着对应页面就直接用，**不刷新、不重开**。
2. 没有就 `new_page` 打开：
   - 小红书 `https://creator.xiaohongshu.com/new/note-manager`
   - 抖音 `https://creator.douyin.com/creator-micro/content/manage`
3. 等页面加载出内容列表。
4. 页面停在登录页，或列表请求返回未登录，记录失败原因 `创作者中心未登录` 并停止，不进入阶段二。
5. 不许关窗口、不许关创作者中心页面。

### 阶段二：读列表接口

本阶段只读接口，不从 DOM 抓卡片、不滚动页面。

1. `list_network_requests`（只读本次导航产生的 `xhr`），从中找列表请求：
   - 小红书：`/api/galaxy/v2/creator/note/user/posted`
   - 抖音：`/janus/douyin/creator/pc/work_list`
2. 对匹配到的请求调用 `get_network_request`，必须把 `中转清单.network_response` 作为 `responseFilePath` 传入；不得传 `output_path`，不得从工具展示文本里抠 JSON。
3. 数据从 `中转清单.network_response` 文件里解析，字段按下表映射。
4. 一条列表请求都没出现在记录里（页面刚开还没加载完）时，等页面稳定后再 `list_network_requests` 一次；仍没有才用 `evaluate_script` 从页面里读已渲染的列表结构兜底。两条路都不通时记录失败原因并停止。

返回体位置：

- 小红书：`data.notes[]`；总数在 `data.tags[]` 里 `id = special.note_time_desc` 那一项的 `notes_count`
- 抖音：`aweme_list[]`；翻页游标 `max_cursor`、是否还有 `has_more`、总数 `total`

### 阶段三：翻页

`CONTENT-07`：翻页只用于补齐前面还没拿到的条目，不用于判断本轮是否完整。

- 小红书：`page` 从 `0` 递增，每页 10 条。**累计的是接口返回的全部条目（含非公开），不是只数公开的** —— 公开条数远小于 `notes_count` 时，只数公开的会永远「没到末尾」。停止条件取先到的那个：累计条数达到 `notes_count`、某页返回空列表、或累计条数达到 `内容数量上限`（大于 `0` 时，此时按「可能未抓全」处理）。
- 抖音：用上一页返回的 `max_cursor` 请求下一页；`has_more = false`、累计条数达到 `内容数量上限`、或达到 `total` 时停止。
- 每次翻页后只合并新出现的 `平台原生内容ID`；整页都是已见过的 ID 时停止，防死循环。
- 达到上限时必须在 `内容列表停止原因` 写明「达到本轮内容数量上限 N 条」，并按「可能未抓全」处理。
- 连续 `2` 页没有新增，或累计 `20` 页时停止，只记录停止原因。
- 不为凑数重新导航、不切换排序、不筛标签页。

`CONTENT-08`：停止翻页不改变内容列表状态，也不触发重试。

### 阶段四：账号页面截图

`CONTENT-09`：内容列表取完后，对**当前创作者中心页面**做长截图（不打开公开主页）：

- 固定调用 Chrome 截图工具，`fullPage = true`，`format = png`
- 截图输出路径固定为 `中转清单.screenshot_png`
- 结果记录由 `Chrome采集临时文件中转.py finalize` 写入 `<本轮暂存目录>/主页长截图结果.json`
- 截图结果 JSON 必须记录真实的 `fullPage = true` 和 `format = png`
- 截图失败不阻断内容列表落盘，按真实原因写 `--screenshot-error`
- 字段名沿用 `主页长截图` 系列（`finalize` 和建档脚本按这套名字取值），**实际内容是创作者中心内容管理页的长截图**

### 阶段五：映射和状态判定

`CONTENT-10`：字段映射固定如下。字段缺失时留空或写 `未知`，不得用猜测值补齐。

| 平台 | 平台原生内容ID | 标题 | 封面图原链接 | 媒介形式 | 公开状态 | 点赞数 | 收藏数 | 分享数 | 评论数 | 发布时间 | 对外页面链接 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 小红书 | `id` | `display_title` | `images_list[0].url` | `type`：`video` 写 `视频`，`normal` 写 `图文`，其他写 `其他` | `permission_code = 1` 或 `permission_msg = 仅自己可见` 写 `私密`，`permission_code = 0` 写 `公开` | `likes` | `collected_count` | `shared_count` | `comments_count` | `time`（已是 `YYYY-MM-DD HH:mm`，原样保留） | `https://www.xiaohongshu.com/explore/<id>?xsec_token=<xsec_token>&xsec_source=<xsec_source>`；两个参数都取自同一条记录 |
| 抖音 | `aweme_id` | `desc` | `video.cover.url_list[0]` | `images` / `image_infos` / `img_bitrate` 任一非空写 `图文`，否则写 `视频` | `status.private_status`：`1` 写 `私密`，`0` 写 `公开` | `statistics.digg_count` | `statistics.collect_count` | `statistics.share_count` | `statistics.comment_count` | `create_time`（unix 秒，转成 `YYYY-MM-DD HH:mm`） | `https://www.douyin.com/video/<aweme_id>` |

**互动数（点赞 / 收藏 / 分享 / 评论）在创作者中心列表里就有准确值，必须在这里一次取全**（2026-11-01 起）。创作者中心一次返回全部条目的四个数，公开页只能一条一条开；而且公开页还有个坑：**数值为 0 时返回空字符串**，容易被当成「没拿到」再补成 0。

公开笔记页未登录时其实读得到 `interactInfo`（四个数都在）、也读得到 `desc` 和 `video` —— **页面上有登录墙不等于读不到这些字段**，别看到扫码框就判断要登录。互动数以创作者中心为准的目的只是「一次取全、不和页面数字打架」，不是「公开页拿不到」。

小红书 `xsec_token` 必须原样带上，它是公开页能打开的唯一凭据；漏了以后视频直链就拿不到。`xsec_token` 缺失时仍按 `https://www.xiaohongshu.com/explore/<id>` 拼，并在 `内容列表停止原因` 里写明哪些条目缺 token。

`CONTENT-10b`：只保留 `公开状态 = 公开` 的条目写入 `账号内容原始列表`。判定为 `私密 / 草稿 / 其他` 的条目直接丢弃，不写入候选、不做补抓；被丢弃的条数写进 `内容列表停止原因`（例如「跳过 4 条仅自己可见内容」）。

`CONTENT-11`：每条记录固定包含：`平台原生内容ID`、`平台`、`账号ID`、`账号名`、`标题`、`封面图原链接`、`媒介形式`、`公开状态`、`点赞数`、`收藏数`、`分享数`、`评论数`、`发布时间`、`对外页面链接`、`基础数据获取方式`。

公开状态唯一规范仍是 `公开、草稿、私密、其他、未知`，但本执行单元的输出里只会出现 `公开`。取不到可见性字段时该条不写入，并在 `内容列表停止原因` 写明「N 条可见性未知，未写入」。

媒介形式唯一规范：`视频、图文、其他、未知`。

`CONTENT-12`：`内容列表获取状态` 固定只允许：`成功、失败`。

`CONTENT-13`：判定规则：

- `成功`：拿到并规范化了至少一条公开内容；是否还有遗漏不参与状态判断。
- `成功（确认空列表）`：列表正常加载、翻页已走完，没有任何公开内容，且接口或页面明确显示无内容。此时固定写入 `账号内容原始列表 = []`、`内容列表为空原因 = no_public_content`。
- `失败`：页面不可用，或未取得可识别内容且也无法确认账号没有公开内容。

`内容列表停止原因` 必须写清本轮为什么停止，以及是否拿到平台给出的结束信号；拿到了要明确写出「已到达列表末尾」（例如抖音 `has_more = false`、或累计条数达到小红书 `notes_count`）。没写就视为未确认。

`CONTENT-14`：`内容列表获取状态 = 成功` 时顶层 `状态 = 成功`；`= 失败` 时顶层 `状态 = 失败`。

`CONTENT-15`：`内容列表获取状态 = 失败` 时固定补充：`账号内容原始列表 = []`、`主页长截图状态 = 跳过`、`主页长截图路径 = 空`、`主页长截图结果JSON路径 = 空`。

`CONTENT-16`：成功时固定返回 `账号内容原始列表`、`内容列表获取状态`、`内容列表为空原因`、`内容列表停止原因`、`内容列表停止位置`、`主页长截图状态`、`主页长截图路径`、`主页长截图结果JSON路径`、`主页长截图失败原因`。

`CONTENT-17`：把完整结构化阶段结果保存为 `中转清单.stage1_json`；候选 JSON 由 `Chrome采集临时文件中转.py finalize` 校验后写入 `<本轮暂存目录>/账号内容原始列表.json`。

### 禁止动作

- 禁止打开 `www.xiaohongshu.com` / `www.douyin.com` 的账号主页取内容列表
- 禁止写入非公开内容（仅自己可见、草稿、审核中、未通过）
- 禁止在本执行单元内直接拼接或覆盖正式 `内容列表.csv`
- 禁止在终端里用 heredoc 或一次性长脚本替代 `账号基础数据建档批处理.py`
- 禁止通过 Shell、curl、Python、Node 或其他 API 重新抓取数据
- 禁止只在对话中返回内容列表而不写入中转清单指定的阶段结果 JSON
