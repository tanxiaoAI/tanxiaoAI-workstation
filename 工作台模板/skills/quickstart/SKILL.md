# 快速开始

## 执行入口

**开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind skill --name quickstart --phase start
```

当前 Skill 的唯一主流程文件是：

`<当前工作区根目录>/执行流程/上手引导流程.md`

执行要求：

1. 第一动作必须直接读取这个文件。
2. 本 Skill 中出现的相对路径，一律相对“当前工作区根目录”解析，不相对 Skill 目录解析。
3. 不得在读取该文件前先做全局搜索、模糊匹配、代码库检索或自行猜测其他路径。
4. 如果该文件不存在，或直接读取失败，必须立即报错并停止，不得搜索替代文件，不得换路，不得继续执行。
5. 成功读取主流程文件后，严格按流程文件中的顺序执行；流程中引用的后续文件也按同样规则处理：能直接读取就直接读取，读取失败就立即报错并停止。

## 入口边界

- 本 Skill **只从 `install.md` 的收尾进入**：装包阶段全部做完、用户重启客户端之后，回来说「已重启 / 继续」或任何同义的话，就进这里。装包阶段做过的事（Python、Node、装包、技能目录适配、Chrome、MCP 配置、建账本）**一件都不要重做，也不要再问一遍**。
- 用户平时自己说「分析一下这个账号」「帮我做个选题」这类请求**不进本 Skill**，直接走对应的公开 Skill。不要主动把普通请求塞进引导，也不要给老用户补建进度账本。
- 先起工作台、再问账号情况、再分派到哪条链路，这些规则全部写在流程文档里，本 Skill 不重复。

## 进度账本

进度记在 `<当前工作区根目录>/.meiling/引导状态.json`，由 `执行单元/上手引导状态执行器.py` 读写。

**换会话后的第一件事就是读进度**（`--action status`），不要重新问一遍已经落定的事。
