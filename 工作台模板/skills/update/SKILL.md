# 版本更新

把工作区的「**工具层**」升级到最新发布版。

工具层指系统本身：执行流程、提示词、分析框架、执行单元、工作台、技能。用户的资料（对标资料、我方资料、沉淀结论）和本机配置（本地配置.txt）不会被动到。

## 执行

**开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind skill --name update --phase start
```

1. 先检查版本：

```
python3 skills/update/update.py --check
```

2. 把脚本输出的「当前版本」「线上版本」原样告诉用户。

3. 按脚本给的结论分两种情况处理：

- **已经是最新版本**：告知用户，结束。不要执行更新。
- **有新版本**：把脚本列出的「会覆盖什么」和「不会动什么」两组内容一并说给用户，然后**问用户要不要更新**。用户确认后再往下走。

4. 用户确认后执行：

```
python3 skills/update/update.py --apply
```

5. 把脚本输出如实汇报，至少包含这三项：更新前版本、更新后版本、备份位置。

   脚本最后可能多打一行，照原样转述：写「工作台进程已重启（地址不变）」的，让用户刷新浏览器页面即可；写「自动重启没成功」的，把那两条手动重启命令原样给用户。

## 更新后：确认技能目录还在

更新只覆盖工作区的工具层。技能真源是 `skills/`：客户端如果直接读它，什么都不用做；
如果是读自己约定的目录（`.workbuddy/skills`、`.claude/skills` 这类），**脚本会把已经存在的那几处自动刷成新的**，也不用管。

只有当**脚本一处「已重新适配」都没打印、而用户又反映技能 / 快捷命令不见了**时，才按
`执行流程/上手引导流程.md` 的 `2.1 把技能目录适配到当前客户端` 重新配一次，配完告诉用户一句。
**不要自己猜目录名乱复制。**

## 约束

- **不要绕过脚本手工覆盖文件**。脚本限定了覆盖范围（只碰工具层），并且会在覆盖前自动备份；手工操作会丢掉这层保护。
- 脚本报错时，把错误原文转述给用户并停下，不要自行改用别的方式下载或覆盖。
- 更新只换工具层，不修改用户的资料和本地配置。
- 脚本输出的版本号、路径、备份位置要如实转述，不要改写、不要省略。
