# 对标账号分析

## 执行入口

**开始前先执行一次使用统计上报**（静默脚本，失败不影响任何流程，也不必向用户提及）：

```bash
python3 执行单元/使用统计上报.py --kind skill --name benchmark-account-diagnose --phase start
```

当前 Skill 的唯一主流程文件是：

`<当前工作区根目录>/执行流程/账号基础数据获取流程.md`

执行要求：

1. 第一动作必须直接读取这个文件。
2. 本 Skill 中出现的相对路径，除非另有说明，一律相对“当前工作区根目录”解析，不相对 Skill 目录解析。
3. 不得在读取该文件前先做全局搜索、模糊匹配、代码库检索或自行猜测其他路径。
4. 如果该文件不存在，或直接读取失败，必须立即报错并停止，不得搜索替代文件，不得换路，不得继续执行。
5. 成功读取主流程文件后，严格按流程文件中的顺序执行；流程中引用的后续文件也按同样规则处理：能直接读取就直接读取，读取失败就立即报错并停止。

## 一键主链路

本 Skill 的一次执行默认直接跑到最终结果，不在中间设置需要用户决策的关卡：

1. 账号基础数据获取
2. 账号详细数据获取
3. 账号详细分析
4. 账号内容规律分析
5. 行动建议

固定规则：

- 取数方式、基础内容上限和详细内容范围都从工作台设置读取，不再逐轮询问。
- 只有账号无法唯一确定时才向用户确认；其他异常按失败结果说明真实原因。
- 概要分析是独立初筛入口，不在一键主链路内，基础数据直接交接详细数据。

## 本地批次身份

对标账号分析只保留一个 `run_id` 作为本轮批次身份，不依赖
`.meiling/workflows/benchmark-account-diagnose/<task_id>/调度状态.json`。

`run_id` 由《账号基础数据获取流程》创建：确定取数方式、进入该流程 `2.3` 之前，调用
`账号分析本地批次初始化执行器.py` 取得，并写入暂存目录
`.meiling/staging/benchmark-account-diagnose/<run_id>/`。

之后各阶段原样复用同一个 `run_id`，不得各自新建：

- 概要独立入口只有在用户直接进入且本轮确实不存在批次身份时才新建一个。
- 详细数据流程复用同一个 `run_id`，由本流程调用 `账号内容明细补全批处理.py --action init-batch`
  创建并确认 `.meiling/staging/benchmark-account-diagnose/<run_id>/detail-data/批次上下文.json`，
  写入账号、正式 CSV 路径和数据源。
- 详细分析必须原样传递该 `run_id`；如果上下文缺失、损坏或身份不一致，应报告真实错误并停止，禁止根据目录名或模型记忆编造新的 `run_id`。

**暂存目录下可能存在其他批次。** `.meiling/staging/benchmark-account-diagnose/` 会同时保留其他会话或其他任务创建的 `run_id` 目录——本机可能并行运行多个会话。只允许读写本轮 `run_id` 对应的目录；不得盘点、罗列、评价其他批次目录，也不得建议删除或清理它们。发现非本轮的 `run_id` 目录时保持沉默，按本轮身份继续执行。
