# 内容分析方法论

## 1. 文档目标

本方法论用于判断单篇内容为什么成立或不成立，并把判断落到选题、切口、结构、表达等可复用结论。

四层框架（表现 / 动作 / 策略 / 内核）、用户验收链路和数据校正都是**分析过程**，不直接作为报告章节。最终报告按「用户拿它做内容」的需要组织，两者的对应关系见第 7 节。

## 2. 分析原则

- 先分析内容本身，再用数据校正，不能一开始就被数据牵着走。
- 先看用户实际看到的表现，再反推动作、机制、策略和内核。
- 逆向拆解后必须正向校验，确认各层能够互相解释。
- 各层只回答自己的问题，不用结果倒推不存在的设计意图。
- 先判断内容类别和主要任务，再按对应标准评价。
- 内容质量看用户是否愿意进入、持续、获得和沉淀，不看作者自我感觉。
- 数据是事后证据，不等于内容质量本身。
- 缺少正文、封面、画面或数据时，只限制对应结论，不补造证据。
- 分析最终必须形成明确的借鉴判断，不能只复述内容。
- 本地 MVP 只使用当前分析输入快照中列出的资料；不得用历史暂存文件、旧结果或外部资料补证据。

## 3. 标准分析顺序

| 步骤 | 判断内容 | 形成结果 |
| --- | --- | --- |
| 1 | 观察用户最终看到的标题、正文、封面或画面 | 表现层观察 |
| 2 | 拆解标题、开头、结构、结尾和表达方式 | 动作层判断 |
| 3 | 解释这些动作各自在哪个环节起作用（吸引／持续／信任／获得／沉淀） | 作用环节属性判断 |
| 4 | 判断媒介形式、内容类别和主要任务 | 策略层判断 |
| 5 | 反推目标用户、痛点、收益、主题、切口和命题 | 内核层判断 |
| 6 | 从内核向表现正向检查是否一致 | 一致性判断 |
| 7 | 检查吸引、持续、信任、获得和沉淀五个关卡 | 内容质量判断 |
| 8 | 用可用数据支持、削弱或限制前面的判断 | 最终结论 |

## 4. 四层分析框架

### 4.1 四层关系

| 层级 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 内核层 | 为谁讲、解决什么、最终想让人相信什么 | 目标用户、核心痛点、收益承诺、主题、切口、核心命题 |
| 策略层 | 用什么路径交付价值 | 媒介形式、内容类别、主目标侧重 |
| 动作层 | 具体用了哪些写法和组织方式 | 标题、封面、开头、结构、结尾、表达、互动设计 |
| 表现层 | 用户最终实际看到了什么 | 标题文本、正文文本、封面或画面、剪辑或版式 |

表现层是事实入口，动作层是可观察手法，策略层是总体打法，内核层是内容的根。五个作用环节（吸引／持续／信任／获得／沉淀）不是独立的一层，而是贴在动作层标签上的**属性**，表示这个做法在哪个环节起作用，不等于效果归因，也不能仅凭数据高就倒推某个环节成立。

### 4.2 内核层

| 字段 | 回答的问题 |
| --- | --- |
| 目标用户 | 这篇内容主要写给谁 |
| 核心痛点 | 主要回应受众的什么问题、欲望或冲突 |
| 收益承诺 | 用户消费后能获得什么 |
| 主题 | 内容讨论的是哪一类问题 |
| 切口 | 从主题中的哪个具体角度进入 |
| 核心命题 | 最终希望用户接受什么判断 |

关键边界：

- `主题` 是问题范围，`切口` 是进入角度，`核心命题` 是最终落点。
- `收益承诺` 回答用户能得到什么，`核心命题` 回答作者希望用户相信什么。
- 受众、痛点和收益必须能够相互对应，不能各说各话。

### 4.3 策略层

| 字段 | 判断内容 |
| --- | --- |
| 媒介形式 | 图文、口播、录屏、访谈、Vlog等载体是否适合当前内容 |
| 内容类别 | 主要通过教程、观点、资料、案例、复盘、清单、故事或混合方式交付价值 |

内容类别按主要价值交付方式判断，混合型必须说明主次。对标内容没有可查证的作者目标，因此不判断主目标侧重。

### 4.4 动作层与表现层

| 动作 | 主要判断 |
| --- | --- |
| 标题、封面 | 是否把进入理由清楚地呈现出来 |
| 开头 | 是否迅速承接标题并让用户继续 |
| 内容结构 | 是否有清晰推进和持续的信息增量 |
| 结尾 | 是否完成收束并形成记忆或动作 |
| 表达风格 | 是否降低理解成本并建立适当信任 |
| 互动设计 | 是否自然推动内容内互动 |

表现层只记录真实可见内容：标题原文、正文、封面或画面、剪辑或版式。看不到的部分写 `信息不足`，不得猜测。

咨询、加微信和成交属于业务承接，不直接等于单篇内容质量。

## 5. 用户验收链路

内容质量看五个连续关卡：

| 关卡 | 核心问题 | 主要证据 |
| --- | --- | --- |
| 吸引 | 目标用户是否愿意点开、停下或开始消费 | 主题、切口、标题、封面、开头 |
| 持续 | 用户是否愿意继续看、读或听 | 结构、信息增量、表达阻力、相关性 |
| 信任 | 用户为什么愿意相信这里说的 | 证据是否可核对、案例与数据、专业解释、权威来源、边界说明 |
| 获得 | 用户是否真正得到信息、方法、判断或情绪价值 | 收益兑现、核心命题、证据和解释 |
| 沉淀 | 用户是否留下记忆、态度或内容内动作 | 结尾、互动设计、认知和情绪收束 |

执行时先逐关判断是否成立，再回到四层框架定位原因：

| 关卡 | 优先检查 |
| --- | --- |
| 吸引 | 内核是否相关，策略是否适合，标题、封面、开头是否有效 |
| 持续 | 内容类别和载体是否合适，结构和表达是否有效 |
| 信任 | 结论由什么支撑、能不能被观众自己核对，边界有没有说清 |
| 获得 | 收益承诺和命题是否兑现，正文是否真正讲清、讲透 |
| 沉淀 | 是否形成明确判断、记忆、情绪或内容内动作 |

判断规则：

- 前一关明显失败，会限制后一关，但不能假装知道真实用户行为。
- 先找影响结论的主因，再补充放大或削弱效果的次因。
- 选题相关性、价值兑现、结构清晰度和进入效率通常属于主因。
- 风格、情绪包装、互动和信任证据通常用于放大或削弱主因。

## 6. 数据校正

数据只用于验证、削弱或限制内容判断：

- 数据高，不代表四层设计全部成立。
- 数据低，不代表内容完全没有价值。
- 数据与初判一致时，说明对应判断得到支持。
- 数据与初判冲突时，重新检查证据和主因，不为了迁就数据强行改写全部结论。
- 数据缺失或口径不足时写 `无法验证`，不把缺失解释成表现差。

当前只使用系统已经计算好的平台级 `数据水平` 和可用互动数据，不在方法论中重复计算平台阈值，也不额外引入账号历史平均值。

校正时重点观察：

| 关卡 | 可用数据方向 |
| --- | --- |
| 进入 | 播放或打开规模、点击相关信号 |
| 持续 | 完读、完播、停留和流失相关信号 |
| 获得 | 收藏、转发、有效评论和停留深度 |
| 沉淀 | 关注、私信和二次传播等信号 |

只有当前实际取得的数据才能使用。没有对应数据时，保留内容本身判断，并明确证据边界。

## 7. 分析过程与报告章节的对应

报告不按分析方法组织，读者先看到的是「这条内容能怎么用」。分析过程与报告章节一一对应，过程本身不单独成节、不写进标题：

| 报告章节 | 由哪些分析过程支撑 |
| --- | --- |
| 这条内容最值得学什么 | 内核层 + 动作层的整体判断，收束成一条最值得借鉴的结论 |
| 内容定位 | 内核层六字段（主题、目标用户、核心痛点、收益承诺、核心命题、切口） |
| 内容框架 | 动作层的结构判断；与内容生产同一套划分（进入 / 主体 / 结尾），主体按职责逐段写清它怎么设计、起什么作用、怎么衔接 |
| 借鉴判断 | 选题 / 切口 / 结构 / 表达四维独立判断，用数据校正支持、削弱或限制结论 |
| 不能忽略的边界 | 证据缺口、未核验项和跨维度的限制 |

写法要求：结论在前、证据在后；用「原作具体怎么做的」代替抽象评价；不把 `表现层 / 动作层 / 策略层 / 内核层` 这类术语写进正文标题；面向读者复述分析过程的做法一律不写。
