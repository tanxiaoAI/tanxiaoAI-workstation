# 账号分析方法论

## 1. 文档目标

本方法论文档用于定义“如何分析一个账号”。

这里的账号分析，是通过对其商业模式、内容证据和账号整体心智的判断，回答以下问题：

- 这个号到底是什么
- 这个号为什么能成立
- 这个号是如何用内容连接商业的

本方法论的主要用途有三类：

- 对标账号研究
- 优质账号筛选
- 为后续启发讨论提供稳定的对标结论

账号分析的输出，是为了形成可判断、可比较、可复用的结论。

## 2. 分析原则

- 证据先行：所有账号判断都应由商业证据、正文证据和程序统计支撑，避免凭印象下结论
- 分工判断：商业供给、内容证据、账号表现各自解决不同问题，不混用边界
- 先描述后判断：先提取证据，再收束为账号结论
- 分析与启发分开：详细分析只判断对方账号；是否适合我学习，交给账号分析后讨论
- 概要与详细分开：概要分析只做初筛和导航，详细分析才形成正式判断
- 概要分析是筛选材料，不是详细分析的事实来源；详细分析必须回到本轮详细数据重新判断
- 分析后讨论只产生当前对话结论，不反向改写对标事实或制造流程状态

## 3. 核心层级

### 3.1 总览

详细分析不再按「模式层—内容层—账号层」并列组织，改为按用户的问题组织：先回答这是一个什么账号、作品表现处于什么状态，再分别回答用户、产品、价值、人设、差异化和成立逻辑。概要分析只做初筛和导航，不逐层展开完整结论。

| 部分 | 核心问题 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 账号定位 | 服务谁、围绕什么问题、靠什么能力或方式提供价值 | 账号基础资料、商业证据、内容证据 | 一至两句话，写清目标对象、核心问题、内容或能力方式和已证实的商业边界 |
| 账号表现 | 这些已采集作品表现处于什么状态 | 程序统计 | 一句话结论、统计依据、样本范围、统计时间和限制 |
| 1. 用户画像 | 这个号吸引和服务的是谁 | 账号资料、内容正文、人工补充 | 目标内容用户、目标付费用户、需求、行为条件 |
| 2. 产品服务体系 | 这个号卖什么、怎么交付 | 图片、产品页面、人工补充 | 产品、类型、用途、价格状态、公开入口 |
| 3. 价值主张 | 用户能获得什么帮助 | 内容正文、产品说明 | 内容价值、付费价值及两者联系 |
| 4. 人设风格 | 它以什么身份和姿态出现 | 内容正文、主页资料 | 身份标签、角色标签、表达标签、定性倾向 |
| 5. 差异化 | 它和同类号有什么区别 | 内容正文、可用的同类对照 | 账号特点、比较对象、对比状态 |
| 6. 成立逻辑 | 这些要素为什么能连起来 | 前五项结论 | 成立条件、证据、限制；不写成成功归因 |
| 资料范围与来源 | 结论来自哪里、缺什么 | 证据清单、程序统计 | 样本范围、统计时间、来源、主要缺口 |

完整报告以“综合结论”作为总入口：它把账号定位、账号表现和六个分析模块收束为一份可复核的判断；各模块只提供证据和边界，不另起一份相互竞争的结论。

### 3.2 六个模块的统一结构

每个模块统一写成三块：

1. **核心描述**：可直接用于首页的一句话，页面数据区与详情逐字一致。
2. **细分分析**：展开用户分层、产品关系、具体表现等证据。
3. **依据与边界**：关联资料、作品和来源，说明不确定性。

「判断」转为核心描述；「依据」保留为证据。清晰度、支撑度不再作为用户可见字段，重要限制必须直接影响措辞，不能靠一个评级标签修补过度确定的结论。

账号定位是整份文档的入口；账号表现保留在完整文档中，配合程序统计图表解释，不进入首页页面数据区。转化路径不独立成节：可见入口归产品服务体系，有依据的筛选与承接归成立逻辑，通用漏斗描述不写。关键依赖并入成立逻辑的条件与限制，不新增成功要素卡片。

### 3.3 原内容层证据的归属

原内容层与《账号内容规律分析》有重叠，但不直接删除。内容证据的归属如下：

| 原内容层字段 | 新归属 |
| --- | --- |
| 核心议题 | 账号详细分析：综合结论与用户画像；内容规律分析不再单设内容方向 |
| 目标问题 | 账号详细分析：用户画像；内容规律分析不再单设内容方向 |
| 价值表达方式 | 内容规律分析的「内容打法」：表达组织、观点与证据的呈现方式 |
| 用户吸引机制 | 内容打法：标题、开头、具体吸引方式；效果判断放表现比较 |
| 信任建立机制 | 内容打法：经历、案例、演示及证据方式；账号分析只引用必要结论 |
| 认知一致性 | 融入方向与打法的稳定特点、条件变化和反例，不单列大模块 |
| 商业连接线索 | 产品、价格、入口归详细分析；单条内容如何提及产品、如何收尾承接，留在内容打法 |

内容打法只描述做法，不判断有没有用；高频做法与「和数据好坏有关」的做法必须分开。没有明显差异不等于「学了没用」。

### 3.4 与概要分析的关系

- 概要分析负责筛选与导航，不输出完整六模块。
- 详细分析负责正式判断与提炼，必须回到本轮原始资料重新判断。
- 详细分析不继承概要分析的初步结论；概要中过时的数据边界，以本轮明细为准，并在反馈中说明。

## 4. 标准推导顺序

账号详细分析时，按照以下顺序推导结论。这里定义的是分析逻辑，不是系统执行步骤：

| 步骤 | 目标 | 输入 | 输出 | 方法 |
| --- | --- | --- | --- | --- |
| 1. 读账号与商业证据 | 判断这是一个什么号、卖什么 | 主页资料、商品或服务信息、简介、人工补充 | 账号定位的素材、产品与价格 | 先建立商业边界，不追求一次全对 |
| 2. 读作品正文证据 | 看这个号长期讲什么、怎么讲 | 已验证正文证据、内容特征统计 | 内容主题与打法素材、代表作品 | 只提证据，不提前下账号结论 |
| 3. 读程序统计 | 看已采集作品表现处于什么状态 | 账号表现统计 | 一句话表现结论、统计依据、范围与限制 | 只引用统计，不重算、不推因果 |
| 4. 收束六模块与账号定位 | 把证据收束成账号画像 | 前几步输出 | 用户画像、产品服务体系、价值主张、人设风格、差异化、成立逻辑 | 用证据推导，不重复罗列现象 |

## 5. 常见证据与作用

账号分析不要求每次都有完全相同的证据，但必须清楚不同证据能够支撑什么判断。

| 输入项 | 说明 | 主要作用 | 更偏支持哪一部分 |
| --- | --- | --- | --- |
| 图片说明 | 商品或服务截图、价格页、服务说明页、报名页、社群截图、主页截图、封面截图等 | 辅助判断卖什么、怎么分层、如何交付，以及主页气质和整体呈现 | 产品服务体系；账号定位 |
| 已验证的正文证据 | 作品原文、实际读取的图片和按任务整理的证据记录 | 观察议题、用户问题、表达方式、信任方式和反例 | 用户画像、价值主张、人设风格、差异化 |
| 程序统计 | 作品数、互动中位数、分档、发布分布 | 描述作品表现常态、差异和集中程度 | 账号表现 |
| 人工先验说明 | 购买体验、产品信息、群体感受、是否有私域、社群、线下课等 | 补充前台看不到的商业信息 | 产品服务体系；成立逻辑 |

判断时遵循以下原则：

- 没有全部输入也可以分析，但要明确哪些结论是低置信度判断
- 图片说明和人工先验说明越完整，商业判断越稳
- 正文证据覆盖越完整，内容主题和打法越容易看出主线与反例
- 程序统计只说明已采集作品，不代表账号全部历史作品；累计互动不能当增长趋势

## 6. 两种分析深度

### 6.1 基本定义

账号分析只有一套底层方法论，但存在两种分析深度：

- 概要分析：低成本快速判断，用于初筛和导航
- 详细分析：证据更充分、输出更完整，用于深挖和形成稳定的账号结论

两者不是两套不同的方法，而是同一套方法在不同证据条件和分析目标下的深度差异。

### 6.2 概要分析

概要分析适用于以下场景：

- 快速筛选对标账号
- 批量初看多个账号
- 判断一个账号是否值得进入详细分析

概要分析的特点：

- 输入更轻
- 速度更快
- 只保留影响筛选结果的关键信号
- 输出是一页式初步判断，不代替完整六模块分析

概要分析的核心任务不是把账号讲透，而是回答五个问题：

- 这个号大概面向谁、讲什么、通过什么方式承接
- 当前最明显的成立信号是什么
- 这个号本身是否值得研究
- 这个号对我方是否有现实参考价值
- 是否值得继续深挖，以及详细分析应重点验证什么

概要分析不得逐项输出完整的六模块详细分析。缺少详细内容证据时，只能写初步判断和判断边界，不得把表面线索包装成正式结论。概要中的适配判断只用于快速筛选，不等于最终的学习或采用结论。

### 6.3 详细分析

详细分析适用于以下场景：

- 已确认值得研究的对标账号
- 需要看清账号定位、内容机制和商业承接
- 需要形成稳定的对标结论或案例沉淀

详细分析的特点：

- 输入更充分
- 字段更完整
- 证据要求更高
- 输出可作为案例沉淀或后续启发讨论的依据

### 6.4 两种深度的关系

- 概要分析的作用是导航，不是最终定论
- 详细分析的作用是形成正式、稳定的账号判断
- 详细分析不得继承概要分析的初步结论
- 详细分析必须回到更原始的输入材料重新判断

一句话说，概要分析负责“筛选与导航”，详细分析负责“正式判断与提炼”。

### 6.5 深挖建议的判断标准

概要分析必须直接给出 `建议深入` 或 `暂不建议深入`，判断时主要看以下几个维度：

- 质量高：内容与商业整体成熟，有研究价值
- 适配度高：与我方目标、产品、能力和阶段有较强关联
- 商业模式值得研究：承接方式、产品结构或转化路径有参考价值
- 内容机制明显：选题、表达、信任建立或转化机制具有清晰特征

只要存在一个有证据支撑、值得继续验证的明确方向，就可以建议深入，不要求所有条件同时满足。当前材料里没有清晰研究价值时，应写 `暂不建议深入`。

## 7. 深度研究时的补充维度

前面的主框架，适合大多数账号分析任务。如果要做更深入的研究，可以加入以下补充维度。

### 7.1 前台可见的补充维度

| 元素      | 说明                                                                                |
| ------- | --------------------------------------------------------------------------------- |
| 更细的模式分析 | 产品价格带和价格梯度；免费内容和付费产品之间的关系；是否存在低价引流品、中价成交品、高价利润品；广告合作频率和品牌类型；账号更偏品牌号、IP 号、销售号还是转化号 |
| 更细的账号分析 | 账号名字、头像、简介的设计逻辑；主页置顶内容在传递什么；沟通姿态是平视、仰视、俯视还是陪伴型；人设是天然形成还是明显设计过；差异化来自身份、观点、视觉还是表达气质 |
| 更细的内容分析 | 高频爆款选题模板；常见标题公式；开头常用话术；冲突点、反转点、记忆点；信息密度；更偏“看完爽”还是“看完有用”；更适合推荐流还是搜索流；栏目化程度和系列化能力   |
| 用户反馈分析  | 评论区高频问题；评论区用户画像倾向；用户为什么点赞、收藏、争论；热门评论是否反映真实需求和情绪；用户把这个账号当作工具、陪伴、娱乐还是消费决策参考         |
| 平台适配分析  | 这个账号为什么适合当前平台；同样内容换个平台是否还成立；它更依赖平台推荐、搜索，还是主页与私域承接；平台机制是否放大了它的内容形式                 |

### 7.2 需要额外信息的补充维度

很多更深的判断，不能只靠前台账号信息完成，通常还需要结合外部信息，例如：

- 账号主理人背景
- 团队规模和生产方式
- 是否投流
- 是否有供应链或线下资源
- 私域承接能力
- 实际产品能力
- 商业合作情况
- 运营周期和关键增长节点

这些内容不属于账号分析的标准必选输入，而属于“深度研究时的补充情报”。
