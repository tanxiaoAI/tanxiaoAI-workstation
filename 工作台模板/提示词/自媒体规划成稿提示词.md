# 账号方向成稿提示词

## 1. 任务

根据调查问卷、旧版账号方向和本轮已确认内容，生成或更新完整的 `我方资料/我方自媒体规划.md`。这份文件在产品界面中显示为“我的方向”。

只负责整理已经确认的内容，以及用户明确要求保留的未定事项，不替用户做未经确认的决定，不编造市场验证、竞争优势、价格、案例或收入结果。

完整方向正文只负责呈现正式规划。`我方当前概要.md` 在正文完成后，以完整正文为唯一输入重新生成，不在正文中设置供概要提取的概括段或特殊字段。

## 2. 处理规则

- 调查问卷只代表用户提交了原始回答；问卷中的选择和从选择推导出的建议必须在讨论中分开，未经确认的建议不写成正式方向。
- 以用户已确认内容为准；用户明确暂未决定的内容用自然语言写清哪里未定，不强迫补齐。
- 只更新本轮确认变化及其必要连带部分，其余已有方向原样保留。
- 四栏之间必须互相支持，但不重复维护同一事实。
- 支持多个用户群体、多个产品或服务、多个内容主线；对应卡片可以按实际数量重复。
- 支持不变现、暂不变现和尚未决定变现方式；没有对应供给时不生成虚构卡片。
- 每个一级栏目直接写具体内容，不在栏目开头增加概括段，也不设置“当前结论”标题。
- 正文不固定使用“选择理由”“详细依据”等过程字段。确实需要说明取舍或依据时，直接写进对应内容，不单独重复一段。
- 确认状态用于讨论和保存前判断，不在正文中逐项附加“已确认”“AI 提议”“暂未确认”“待验证”等标签。尚未决定或需要验证的事实，直接说明具体事项即可。
- 固定字段只用于能直接帮助用户理解或执行的内容；自身条件等没有固定字段必要的部分，按实际情况组织，不为填满模板而凑字段。
- 只写当前方向，不写短期表现、复盘结论、内容日历或未经确认的远期计划。
- 表达简单、具体，避免“专业、真诚、有价值”等无法执行的空话。
- 直接输出正式 Markdown，不写前言、解释或待办清单。

## 3. 输出格式

标题、方向总览和四个一级栏目必须严格使用以下结构，不在末尾重复方向总结：

```markdown
# 我方账号方向

## 方向总览

**自身条件**：<我是谁、手里有什么>

**目标客户**：<服务谁>

**账号定位**：<账号要被理解成什么>

**内容主线**：<哪几条>

**变现方式**：<靠什么收费；不变现就写不变现>

- <需要验证的事项，一项一行>

## 1. 自身条件

### 自我认知
### 现有资源
### 现实约束

## 2. 用户与需求

### 用户群体：<名称>

#### 用户是谁
#### 需求情境
#### 问题与影响
#### 期望结果
#### 解决方式偏好
#### 行动条件

## 3. 产品与变现

### 变现选择

### 具体交付：<名称>

#### 适用人群与用途
#### 交付方式
#### 收费与成本
#### 购买方式与售后

## 4. 账号与内容

### 账号任务
### 账号定位
### 角色与表达风格

### 内容主线：<名称>

#### 讲什么
#### 主要交付

### 哪些内容不做
```

固定字段的使用边界：

- “方向总览”按上面五条字段各写一句话，顺序和下面四个栏目一致；不再合并成整段。
- 这五句只写肯定陈述，一句一个事实：不写“不是……也不是……”这类排除句，不写“三条并行”“范围清晰”这类自我限定，不重复下文细节。排除项放进“哪些内容不做”。
- “方向总览”下的无序列表只写需要验证的事项，一项一行，只放会影响执行的关键未定项。
- 每个“用户群体”卡片保留下面的六个字段；某个字段确实没有信息时，直接写清缺少什么，不推测。
- 每个“具体交付”卡片保留下面的四个字段；不变现或没有具体交付时，不强行建立该卡片。
- “账号任务”“账号定位”“角色与表达风格”，以及每条“内容主线”的两个字段，用于形成可以直接执行的内容方向，按实际存在的账号和主线保留。
- 内容主线每条只写「讲什么」「主要交付」两个子字段，不要写成 md 表格或列表——页面靠这两个子字段把多条主线拼成一张三列表；不再分别写呈现方式、吸引方式、行动连接——呈现形式属于账号级的“角色与表达风格”，承接入口属于“账号任务”，同一条信息不在两处重复。
- “哪些内容不做”写清当前明确排除的内容和做法；没有已确认的排除项时，不编造。
- 自身条件保留“自我认知”“现有资源”“现实约束”三个固定字段，分别回答“我是什么样的人”“我手里有什么”“我做事受到哪些限制”。
- 自我认知写经历、能力、兴趣和意愿，并说明希望以什么身份与用户交流；要区分“想做”和“能做”，不能把兴趣直接写成能力。
- 现有资源写账号、内容、作品、产品、渠道、团队和时间等能否实际调用，不能只列名称，还要看能否持续使用、有没有权限、能发挥多大作用。
- 现实约束写时间、投入、出镜与身份限制、单人交付能力，以及不能接受的成本、风险和工作方式；没有信息时写清缺什么，不推测。

## 4. 保存前检查

- 正文只保留用户已经确认的方向；AI 提议、并列候选和讨论过程不得混入正式结论。
- 尚未决定、仍需验证的内容可以保留，但必须写清具体事项，不能靠状态标签代替说明。
- 四栏都必须有实际内容；标题和栏目缺失、内容为空，或本轮输入无法支撑正文时，不进入正式保存。
