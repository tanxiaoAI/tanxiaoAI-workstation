# 内容生产-内容初稿提示词

## 1. 任务

按照已确认定位，一次生成内容框架和完整初稿。框架与正文同属内容初稿，不再拆成两个阶段。

## 2. 处理规则

读取当前参考内容分析的四维借鉴判断（取自内容分析的「借鉴判断」表）：`选题 / 切口 / 结构 / 表达`，同时读取每一维的 `值得借鉴` 和 `不值得借鉴` 结论。这里只读这些结论，不重新判断、不改写结论，也不生成计划外特征。

### 执行要求

- 不得搜索新参考或重新分析参考内容；只允许使用已确认的定位和已确认的借鉴结论。
- 只生成一个版本，不给主方案、备选方案或选择状态。
- 先确定本条内容对“吸引、持续、信任、获得、沉淀”五个用户关卡的总体策略，再把策略落到具体段落；这五个关卡只作为判断过程，不单独输出成表。
- 五个用户关卡是验收维度，不是五个固定段落；同一段可以承担多个关卡，但必须写清主要作用。
- 框架分总览、开头、主体、结尾四块；每块只写一句话说清“这块写什么”，不写成本段正文，也不写“这段讲什么、用户得到什么”这类字段。
- 开头统一处理标题、封面、首屏、第一句话和开头首次交付，不把“入口”和“开头”拆成两个并列模块。
- 每一块都必须产生新的信息、判断、方法或行动，并与前一块形成递进，不得写成并列罗列。
- 开头不交代背景、不自我介绍、不铺趋势，第一句就进入这条内容本身。
- 结尾把全篇已经交付的价值收束成明确的判断、记忆或行动，不把核心价值全留到结尾。
- 主体段落数量和功能名称按实际内容需要决定，不默认三段，不为凑数量拆段。
- 正文严格按框架顺序展开，每段兑现自己的职责并提供新信息。
- 标题、封面和开头承接同一进入策略，但不机械重复。
- 内容标题不超过 `20` 个展示字符，不机械截断。
- 关键判断有支撑；不编造数据、案例和个人经历。
- 开头、正文和结尾必须完整，使用户可以独立判断进入、持续、获得和沉淀。
- 段落名称用一个词概括这一段的思路（痛点 / 如何解决 / 两条路 / 怎么核），不写「分界线：按…分」这种长短语，不写「第 1 段｜」前缀。
- 框架每一块只写一句话，说清这块写什么，不超过 30 字；不复述正文，不写“本段负责什么”“用户从本段得到什么”这类元描述。
- 每块标题后给一个预估时间区间，按口播 4.5 字/秒估算，格式 `（0:25–1:10）`。
- 不输出「规律应用」栏，不输出表格，不输出 `<small>`、`<br>` 等 HTML 标签。
- 不输出风格标签或额外栏目。

## 3. 输出格式

只输出一个二级区块 `## 内容初稿`，其中包含框架和完整初稿两部分。不要写版本号。

```markdown
## 内容初稿

### 一、内容框架

推进主线：A → B → C

#### 开头（0:00–0:40）

<一句话：这一块写什么>

#### <段名>（0:40–1:55）

<一句话：这一块写什么>

#### 结尾（4:42–5:15）

<一句话：这一块写什么>

### 二、完整初稿

标题：<内容标题>

完整初稿

【开头】
<正文>

【<段名>】
<正文>

【结尾】
<正文>
```

`<段名>` 用一个词，与框架里的段落名称逐字相同；按实际框架增加中间段，不加「第 1 段｜」前缀。不输出策略解释、内部对照、审查结论或终稿。
