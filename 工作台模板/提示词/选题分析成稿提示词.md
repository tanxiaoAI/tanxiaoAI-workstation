# 选题分析成稿提示词

## 1. 任务

根据本轮冻结输入和 `分析框架/选题分析方法论.md`，一次生成或更新单个选题的正式分析正文。直接形成简短、可读的选题决策结果，不等待用户先确认候选，也不提前设计内容生产。

## 2. 处理规则

本轮冻结输入和当前对话是业务依据。旧版正文只用于保留未修改内容和说明本轮变化，不覆盖本轮新判断。

### 成稿边界

- 按方法论理解题意、形成六个核心要素和是否值得做的结论，并直接写入正式正文。
- 只写当前选题是否值得做，以及这个题当前被定义成什么。
- 不输出内部推理、依据状态、一致性校验过程、最高风险判断或生产建议。
- 不展开媒介形式、内容类别、表达方向、内容机制、段落安排或正文写法。
- 不逐字段写成长段解释。六个核心字段各用一句清楚的话写完。
- 六个核心字段都给出当前明确判断，不留空，不写成“AI 暂定”或“待确认”。
- 信息不足时仍给出当前最合理的完整判断；没有的数据、没有执行的分析和没有读取的资料不得编造。
- 不设置“当前限制”栏目，也不添加固定证据边界或免责声明。
- 新题不写旧版对比；老题只有确实提供旧版正文时才写本轮变化。
- 老题局部修改时只更新受影响内容，未修改部分沿用当前有效判断。

### 用户可见表达

- 保留标准业务术语，并在字段名后用括号说明它回答什么问题。
- 字段内容必须直接写清具体的人、问题、结果和角度，不使用系统内部术语代替实际判断。
- 判断理由最多三条，每条只说一个真正影响是否要做的原因。
- 正常结果控制在一个常规页面内，不用格式完整制造篇幅。

## 3. 输出格式

正常成稿严格使用下面的结构；标记为可选的部分没有实际内容时直接省略。

```markdown
# 选题分析：<选题名称>

## 选题结论

- 是否建议做：<三选一，只写选中的那一个：建议做、暂缓、不建议做；不要把三个值都留在正文里，正式化执行器要求这一行恰好匹配其中一个值>
- 核心判断：<一句话说明为什么值得做、为什么暂缓或为什么不建议做>
- 判断理由：
  - <理由1>
  - <按实际需要写理由2或理由3>

## 选题定义

| 字段 | 当前结论 |
| --- | --- |
| 主题（这个题主要讲什么） |  |
| 目标用户（主要写给谁） |  |
| 核心痛点（他们现在卡在哪里） |  |
| 收益承诺（看完能得到什么） |  |
| 核心命题（最后希望用户相信什么） |  |
| 切口（从哪个具体角度开始讲） |  |

## 参考内容借鉴

仅在存在可读参考内容时保留，只写选题和切口两个维度：

| 维度 | 结论 | 可借鉴内容 |
| --- | --- | --- |
| 选题 | 值得借鉴 / 不值得借鉴 | 值得时写具体内容，否则写 `—` |
| 切口 | 值得借鉴 / 不值得借鉴 | 值得时写具体内容，否则写 `—` |

## 本轮变化

仅在老题且确实提供旧版正文时，用一至三条短句写清改变了什么。
```

### 输出要求

- 直接输出正式正文。
- 不写解释性前言、输入检查、对话过程、待确认清单或后续生产建议。
- 不新增固定结构外章节。
- 不把同一个结论先写在段落里、再写进表格重复一遍。
