# 账号内容规律分析提示词

## 1. 任务

根据本轮的机器准备结果，生成一份面向普通内容创作者的 `账号内容规律分析候选.md`。

输入只有一份：

| 输入 | 用途 |
| --- | --- |
| `账号内容规律分析准备结果.json` | 第 1 节的四个数字、第 2 节的做法统计、第 3 节的机器表格与分档数字 |

准备结果里的 `generated_at`、`analysis_scope_label`、`active_sample_count`、`rule_count` 是第 1 节的唯一取值；`rules`、`markdown`、`rank_comparison`、`table_content_count`、`warnings` 是第 2、3 节的机器依据。任何数字都只能取自准备结果，不得回头重算 CSV、样本数、规律数或篇数。

本报告不读作品正文，不写内容方向、代表作品或正文补充；正文相关内容不在本报告职责内。

## 2. 报告结构

固定 3 节，节名逐字、顺序固定，不得增删节：

`1. 分析范围`、`2. 内容打法`、`3. 表现比较`。

整篇不得出现「新特征」「候选」「入库」这类字样——新特征是全工作区共用的资产，单个账号撑不起这个判断。

### 第 1 节 分析范围

四项，写成 `- 标签：值`，每项只能出现一次：

- `生成时间`：逐字等于 `generated_at`；
- `分析范围`：逐字等于 `analysis_scope_label`；
- `纳入内容数`：逐字等于 `active_sample_count`；
- `规律数量`：逐字等于 `rule_count`。

### 第 2 节 内容打法

这一节只描述「他怎么打」，不判断有没有用；哪些做法和数据好坏有关，放到第 3 节。节名之后直接给两张表，不写任何交代句。

素材是 `rules`。同一标签出现多行时（不同媒介形式各一行），先把 `去重样本数` 相加，再排序、算占比。

#### 2.1 按环节看：他每一步用什么形式

`### 按环节看：他每一步用什么形式`，一张三列表：

| 环节 | 他习惯怎么做 | 具体分布 |
| --- | --- | --- |

- 「环节」取规律记录的 `特征小类`，六个取值固定：`内容类别`、`标题`、`开头`、`内容结构`、`表达风格`、`互动设计`。按这个顺序排列，只写有数据的行。
- 「他习惯怎么做」用一句话总结这一环节的偏好，要具体（写他用什么，不写「比较多样」这类空话）。
- 「具体分布」把这一环节出现的每个标签写成 `标签名 篇数（占比%）`，按篇数降序，用顿号分隔。篇数逐字取 `去重样本数`；占比 = 该标签篇数 ÷ 本环节各标签篇数之和。

#### 2.2 按机制看：他靠什么起作用

`### 按机制看：他靠什么起作用`，一张四列表，表前不写交代句：

| 机制 | 定义 | 观察到的事实 | 作用解读 |
| --- | --- | --- | --- |

- 「机制」顺序固定：吸引、持续、信任、获得、沉淀。归类依据是规律的 `作用环节`（该字段可能写成 `吸引|持续` 这种多值，表示这条做法在这几个环节都起作用）。
- 「定义」逐字照抄下表，不得自编：

| 机制 | 定义 |
| --- | --- |
| 吸引 | 观众为什么点开这条内容 |
| 持续 | 观众为什么看下去、下次还愿意来 |
| 信任 | 观众为什么愿意相信他说的 |
| 获得 | 观众看完实际拿到了什么 |
| 沉淀 | 内容结束后留在观众身上的是什么 |

- 「观察到的事实」写这个机制下实际出现的主要做法：`标签名（篇数）`，按篇数降序，最多 3 条；再用一句话说清这些做法分别是什么。篇数来自 `去重样本数`。
- 「作用解读」用简单直白的话解释这些做法为什么可能在这个环节起作用，只解释原理，不宣布实际效果，不写「不能下的结论」。
- 只写出现过的做法，禁止罗列没出现的标签。某个机制下一条做法都没有时，「观察到的事实」写「这一层没有可统计的做法」，「作用解读」写「暂无」。
- 不要求和、不要算占比：一个标签可以同时挂几个机制，跨机制相加会重复计数。
- 机制属性只表示「这个做法在哪个环节起作用」，不得写成效果归因。

#### 2.3 小结

只写一句话，概括这个账号的打法（句式参考：「口语直给，开头先给结果，正文分点讲，靠亲身经历解释建立信任，全程不引导互动。」）。

不写厚薄分析，不写「他老这么干和这么干有用是两件事」之类的提醒。

### 第 3 节 表现比较

四组内容必须照抄准备结果的 `markdown`：`### 账号通常使用`、`### 先看：选哪类内容`、`### 数据好的内容更常用`、`### 数据差的内容更常用`。子标题、共性说明、每张表的行、每行的条数与比例都不能改；机器没有生成的前两组可以整体省略。

- `### 数据好的内容更常用` 和 `### 数据差的内容更常用` 必须保留：本轮没有对应做法时，只照抄表头和分隔线，不补任何标签行，也不另写行动建议。
- 「结论」列可以在机器判定后面接着写自己的补充，但判定词本身不能改、不能缩写。
- 不得增删标签行，不得自己造一个机器没有的标签，也不得在第 3 节里另加表格。这一节的补充说明一律写成段落或列表。
- 表格前写固定口径，数字全部来自 `rank_comparison.account` 与 `high/middle/low_content_count`：
  1. 怎么分的档：账号里一共有多少条内容取到了互动数（`account.content_total`）、账号内中位数是多少（`account.median`）；
  2. 三档各几条（`high_content_count` / `middle_content_count` / `low_content_count`），并说明「其中 N 条已经做完特征识别（`table_content_count`），三档表格只统计这 N 条」；
  3. 分档规则照抄 `rank_rule`；
  4. 这是账号内部的相对排名，不是跟别的账号比；
  5. 低档条数少时，一条内容就会明显改变比例，所以下面的结论只是线索；
  6. `warnings` 非空时如实写出「样本不足」，不要硬凑高低档结论。
- 读表规则只写这几句：先比较高档和低档的使用率，不直接比较条数。使用率相差达到 20 个百分点、做法总共至少出现 3 次且较多的一档至少有 2 条，才判为这一档更常用；其余为区分不出。覆盖 80% 以上内容的做法归入「账号通常使用」，不判断好坏；中档只展示，不参与判定。
- 所有表格后都不写行动建议，不写任何我方应该怎么做的建议。
- 末尾单独写一句边界：做法和互动表现同时出现，不等于因果，也不能证明成交效果。

面向用户的文字要简单直白。不展示字段名、执行命令、临时路径或结构化状态词。

## 4. 硬约束

- 报告标题必须是 `# 账号内容规律分析`，全篇只出现一次。
- 节名、顺序不得改，只有 3 节；子标题不得改字（`### 账号通常使用`、`### 先看：选哪类内容` 整组为空时，对应子标题可以不出现；`### 数据好的内容更常用`、`### 数据差的内容更常用` 不得省略）。
- 不写学习启发、内容方向、代表作品、正文补充，不出现行动建议。
- `生成时间`、`分析范围`、`纳入内容数`、`规律数量` 四项必须写成 `- 标签：值`，且各自只出现一次。
- 第 3 节表格里的共性占比、三档条数与比例、判定词必须与机器输出逐字一致，改一个数就会被保存执行器拒绝。
- 本轮没有规律时，第 2 节按「当前没有可统计的做法」如实写，不删节、不跳号。
