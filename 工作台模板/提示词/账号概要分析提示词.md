# 账号概要分析提示词

## 1. 任务

根据上游流程准备的材料，生成 `概要分析.md` 候选稿。本次只做账号初筛，不展开完整的模式层、内容层和账号层。

## 2. 处理规则

- 账号基础信息、图片说明、内容列表证据摘要和人工先验说明用于判断对标账号
- 内容范围只用于说明本次证据覆盖情况
- `内容范围` 逐字复制上游执行单元返回的 `evidence_scope`，不计算数字、不改写措辞
- 上游提供的内容列表完整性只允许原样写入，不得根据内容数量自行猜测。取值只能是 `完整` / `可能未抓全` / `未知` 三者之一，且必须与上游判据按建档报告算出的真值一致：把枚举菜单原样抄进报告会被正式化执行器以 `content_list_completeness_invalid` 拒绝，与真值不一致会以 `content_list_completeness_mismatch` 拒绝
- `我方当前概要` 只用于适配判断，不得反向改写对标账号事实
- 材料缺失时保守判断，并在 `当前判断边界` 中说明
- 写数据边界时必须归因：字段整体为空时，要分清是「本阶段材料里没有」还是「内容本身没有」。属于详细数据阶段明细接口负责补齐的字段（例如视频的发布时间、各类媒介的收藏数／分享数／评论数）时，只能写「本阶段材料不可用，详细数据阶段可补」，不得写成内容缺失，也不得据此推断更新节奏或时效性

### 成稿规则

- 直接输出正式 Markdown，不写前言、不追问、不提出补资料操作
- 只保留影响初筛的关键结论，不能写成压缩版详细报告
- 每个判断写明最关键的依据，不能把待验证线索写成事实
- 固定枚举：
  - `质量判断`：`值得研究` / `一般` / `可放弃`
  - `适配判断`：`高适配` / `中适配` / `低适配` / `不能判断`
  - `深挖建议`：`建议深入` / `暂不建议深入`
- `我方当前概要` 不可用时，`适配判断` 固定为 `不能判断`
- 严格使用以下结构，不增加其他章节

## 3. 输出格式

```markdown
# <昵称>账号概要分析

## 1. 账号速览

- 主要对象：
- 内容主线：
- 账号角色：
- 商业承接：

## 2. 关键观察

写 2 至 4 条当前最影响研究价值的观察。每条包含“初步判断”和“主要依据”。

## 3. 研究价值

- 质量判断：值得研究 / 一般 / 可放弃
- 质量依据：
- 适配判断：高适配 / 中适配 / 低适配 / 不能判断
- 适配依据：

## 4. 深挖建议

- 深挖建议：建议深入 / 暂不建议深入
- 判断理由：
- 建议验证方向：写 1 至 3 个具体方向；暂不建议深入时写“无”

## 5. 当前判断边界

- 内容范围：<逐字复制执行单元返回的 evidence_scope>
- 内容列表完整性：<按上游判据从建档报告得出的值逐字填入，只能是 完整、可能未抓全、未知 三者之一>
- 其他判断边界：最多写 3 条；没有时写“暂无明显边界”。
```
