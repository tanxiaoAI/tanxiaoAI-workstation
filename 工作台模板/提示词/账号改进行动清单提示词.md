# 账号改进行动清单提示词

## 1. 任务

根据已经正式保存的《自我账号详细诊断》，生成 1 到 3 条当前最值得执行的账号改进行动。

这份清单只回答：**现在先做什么、具体怎么做、做完看什么。** 每条行动都写成接下来要执行的动作和步骤，不写成对过去内容的编号指认。不重新写一遍诊断，也不生成选题任务或发布排期。

动作不限内容整改。定位、主页、对标、选题、开头与结构、案例、发布节奏、补数据、验证复盘，只要当前最值得做，都可以成为行动。

## 2. 处理规则

### 2.1 输入与依据

输入包括：

- 正式诊断的「综合诊断」「目标与实际」「关键问题」「阶段变化」「本轮依据与边界」；
- 本轮正式诊断第 5 节写明的判断基准（调查问卷 / 我方自媒体规划）；不得自行重新优先选规划；`我方资料/我方当前概要.md` 仅作背景参考；
- 本轮创作者中心、评论和上一版《账号改进行动清单》（如有）；
- 本轮《行动参考候选》：由 `执行单元/行动参考候选检索.py` 从 `沉淀结论/内容特征实例.csv` 检索生成，只包含已分析、数据较好的对标做法。

行动依据按以下顺序取用：

1. 诊断里的「关键问题」；
2. 「目标与实际」中判定为「不一致」、但尚未升级为关键问题的维度；
3. 「本轮依据与边界」里明确写出的证据缺口；
4. 本轮判断基准里明确的本阶段重点、目标或待验证事项。

不新增诊断里没有的问题，不把猜测写成行动依据。没有可用依据时不生成行动，不硬凑。

### 2.2 动作方向库

先判断问题属于哪一层，再从对应方向里选择或组合动作。方向只是候选范围和这条动作的属性标签，不是切分动作的依据，不要按方向各写一条，也不限制只写示例里的动作。

| 方向 | 解决的问题 | 可生成的动作示例 |
|---|---|---|
| 定位与内容主线 | 账号实际走向与规划不一致 | 收紧目标用户；明确只解决哪类问题；调整各内容线比例；明确现阶段不做什么 |
| 主页与账号介绍 | 用户进入主页后看不懂账号价值 | 重写账号简介；统一昵称头像与定位表达；调整主页说明顺序；置顶一条代表内容 |
| 对标账号与参考系 | 缺少可借鉴的做法或样本不足 | 新增同用户、同方向的账号；按开头、结构、案例分别建立专项对标；剔除不再适配的账号；重新分析已有对标 |
| 新增内容与选题 | 内容供给不足或主线缺失 | 补一条缺失的内容线；围绕一个真实业务问题连做一组；把已有经验转成内容；减少泛流量选题；建立稳定选题来源 |
| 开头与标题封面 | 有曝光但留不住人 | 改前 2 秒；结果前置；先展示成品；删除背景铺垫；标题改成用户问题；封面突出结果或冲突 |
| 正文结构与表达 | 内容看完没有判断和收获 | 改成「问题—判断—步骤—结果」；一条只讲一个问题；增加真实过程；减少功能罗列；补证据；调整详略 |
| 案例与信任建设 | 只有观点，没有可信证据 | 把客户经历整理成案例；补「问题—判断—动作—结果」；展示真实工作过程；补失败与边界说明；减少无证据观点 |
| 发布节奏与系列化 | 内容零散，形不成认知 | 固定一条主线连续发布；把零散内容组成系列；稳定发布节奏；避免频繁换主题；同一方法做多个案例 |
| 数据补采与证据完善 | 当前材料不足，无法判断 | 补创作者中心数据；补重点作品的正文证据；补评论；记录咨询与成交；补发布记录 |
| 验证复盘与做法放大 | 不知道改动是否有效 | 设定观察周期；一次只改一个变量；建立指标记录；按结果决定保留或停止；复用已验证结构；把高表现单条扩展成系列 |

选择方向时优先解决上游问题：定位不清先定方向，主页说不清先改介绍，没有内容供给先补内容，再处理开头、标题这类单条表现问题。

### 2.3 动作切分（先于筛选）

- **一个动作 = 一件能独立做完、能单独打勾的事。** 写完自问：不依赖其他动作，今天能不能开始、做完能不能算完成？不能，就合并进别的动作，或降级为那条动作的一个步骤。
- **一件动作只装一次动手的量。** 默认 1 条内容、1 个案例、1 个账号、1 处改动。需要发多条才能看出效果时，动作写「发 1 条」，把「按同口径再发一条做对比」放进 `验证指标`，不在标题里写「发 2 条」「连做一组」。
- **同一篇新内容只对应一条动作。** 选题、开头、标题封面、正文结构、结尾引导都是这一篇内容的写法，必须合并进「发布这条内容」的动作，写进「具体怎么做」，不得拆成多条并列动作。
- **写法类问题不单独占动作位。** 开头留不住人、标题不吸引、结构混乱这类问题，动作不是「改开头」「改结构」，而是「按这些要求发下一条内容」，写法要求作为该动作的步骤。
- **只有不依赖新内容、彼此独立的事才各占一条。** 例如公开已有案例、取舍未公开内容、改简介与置顶、补对标、补数据。
- 合并后再按 2.4 筛选排序；合并后只剩 1 条时，不为了凑数重新拆开。

### 2.4 筛选规则

先按 2.2 穷举候选，再按 2.3 切分合并，最后按下面顺序筛选，最终只保留当前最值得做的 1 到 3 条：

1. **影响大小**：是否影响定位、内容供给、留存、信任或咨询承接等核心结果。
2. **紧急程度**：问题是否还在持续，越晚处理成本是否越高。
3. **证据强度**：是否有诊断、数据或真实反馈支撑，不把猜测变成行动。
4. **当前可执行**：一个人现在就能开始，不需要等待外部条件。
5. **动作杠杆**：一个动作能否解决关键矛盾，而不是只修饰细节。
6. **依赖顺序**：需要先定方向、先补证据、先补对标的，不能跳过前置直接改表现。
7. **去重合并**：同类动作合并，不把同一件事拆成多条凑数。

排序后仍无法判断哪条更重要时，选能解决更上游问题的那条。

### 2.5 数量规则

- **1 条**：没有关键问题，或关键问题还撑不起一件能当天动手的事时，写 1 条维持型行动——按现有方向继续做，写清看哪个指标、第几天回看，不包装成整改。这是最少的情况，不写 0 条，清单不许空。
- **2 到 3 条**：存在关键问题时，按 2.4 排序取前几条；能挂到关键问题上的动作不到 2 条时就写 1 条，不凑数。

一个问题可以由多条动作一起解决，一条动作也可以同时承接多个问题（例如一条新内容同时解决选题偏离和开头留不住人）；两边都不限数量，但对应关系必须按 2.6 的格式写清。**每条动作都必须挂到关键问题上**：只有证据缺口或规划重点、但挂不上任何关键问题的，不生成动作，宁可少写一条。本轮没有任何动作覆盖的关键问题，要在 `本轮依据` 里写明这轮先不动它的理由，不让它悬着。

### 2.6 每条行动必须写清

**每个字段只用一句话回答字段名问的那一件事，不铺开。** 写完逐句自检：这句话是不是在解释别的字段？是就删掉，换个地方写或者直接不写。整条动作读下来应该像一张便签，不像一段分析。

- `方向`：取自 2.2 的方向名，不自定义新分类。
- `对应问题`：只写关键问题的原文标题，不跟数据、不跟解释。
  - **每条动作必须至少挂到一条关键问题上**，写成 `《关键问题的原文标题》`，逐字取自诊断，不改写、不缩写、不合并。承接多个问题时逐个列出，用「；」隔开。
  - **挂不上任何关键问题的动作，不写进清单。** 不要用「不对应任何关键问题，依据是…」之类的写法把它放进来——一条动作如果连诊断认定的问题都对不上，它就不是这轮该做的事，宁可少写一条。
  - 数据不写在这里。关键问题的具体数值、样本范围在诊断的 `关键问题` 里已经写过，再抄一遍只会让卡片变长、让人以为在讲新东西。
  - 唯一例外：按 2.5 写的维持型行动（没有关键问题，或关键问题撑不起一件能动手的事）。它的 `对应问题` 统一写 `本轮不针对关键问题，这条是维持型`。
- `动作`：一个动词带一个对象，只说做什么，不说用什么做法做。这一行就是用户今天要动手的那件事。
  - **只做一件事**：标题里不得用「和」「、」「并」「先……再……」把两个以上对象或阶段并进来。出现了就拆成两条动作，或者只留当前最该先做的那一件，其余降级为 `具体怎么做` 里的后续步骤。
  - **不写做法**：「选题、开头和结构一起按下面的要求写」这类内容属于 `具体怎么做`，不进标题。
  - **不写目的和理由**：「为了验证转化」「按诊断要求」这类话属于 `优先原因`，不进标题。
  - **长度**：常规不超过 14 个字；超过就说明还没切到位，回去重切。
  - 正例：`发 1 条讲判断的新内容`、`把简介改成一句话说清帮谁解决什么`、`补 5 条对标内容的评论原文`。
  - 反例：`整理已发布但未公开的内容：先公开室内设计案例，再决定其余内容哪些放回公开`（两件事加做法说明）、`发 2 条讲判断的新内容，选题、开头和结构一起按下面的要求写`（数量是 2、做法占了一半）。
- `具体怎么做`：2 到 4 步，能当天开始。每步一句话，只写动作，不写理由和背景；常规一步不超过 25 个字。「做完的标志」放在最后一步末尾。
- `优先原因`：一句话，说清为什么先做这条，不重复 `对应问题` 里已经说过的问题和数据。
- `参考做法`：只能从本轮《行动参考候选》里选 1 条，优先与这条动作方向相同、数据水平更高的候选。写法固定为 `[《标题》](链接) 的做法：<做法说明>`，没有链接时写 `《标题》（未公开） 的做法：<做法说明>`；`做法说明` 只能基于候选里的 `实例证据`，说清这条特征在这条动作里怎么用，不补候选之外的结构、机制或效果。不得使用候选之外的作品，也不得把两条作品并列堆在一起。候选为空、没有对得上的方向或候选里的证据不足以支撑这条动作时，写 `无`，不得编造。
- `验证指标`：只写一个判断信号，一句话，常规不超过 25 个字。判断这条动作有没有效，看这一个数就够了。
  - 不写回看时间——时间写进最后一步。
  - 不写对照数值——对照值在 `对应问题` 里已经写过一次。
  - 不写「样本少」「只作同口径观察」「不据此断言因果」这类边界说明——统一写在 `本轮依据` 的「本轮限制」，不在这里重复。
  - 确实需要两个数才能判断时，最多并列两个，且必须是同一个判断；不把不同层面的事情凑在一句里。
  - 反例：`发布后第 7 天回看：这条的 2 秒退出率能否低于 56%（两条旧内容分别是 62.5% 和 56%），观看数能否过 100；主页讲判断的内容是否从 1 条变成 2 条。样本少，只作同口径观察，不据此断言因果。`
  - 正例：`2 秒退出率低于 56%。`

具体动作要落到可执行粒度：

- 涉及新增对标账号时，写清补什么类型、解决什么问题，不写「多看几个账号」。
- 涉及重写账号介绍时，写清改哪几处、改成什么方向，不写「优化简介」。
- 涉及新增内容时，写清主题和结构，数量按 2.3 的默认量只写 1 条，不写「多发内容」；最后一步要写清做完的标志，不再单列「完成标准」。
- 涉及补数据时，写清补哪一项、补到什么范围，不写「完善数据」。

### 2.7 动作对象

行动必须作用在还能改变的地方：

- 可以作用对象：尚未发布的新内容；可以直接调整的账号资产（简介、昵称、头像、置顶、主页展示）。
- **不建议把未公开的内容改成公开。** 用户没公开它，是他自己的判断；系统只看过标题和形式，没有正文级证据，推翻用户的判断没有依据。
- 不能作用对象：已经发布内容的开头、标题、封面、正文、发布时间。这些发布后改不了，只能作为问题样本、参考做法或对比基线，不能写成「把某条已发布内容改成什么」。
- 涉及开头、标题、封面、正文结构这类发布后不可改的要素时，动作必须写成「下一条新内容怎么做」，并说明参考哪条已发布内容、对比哪个指标；这些写法要求并入这条新内容的动作步骤，不单独列成动作。
- 动作写完后自检一遍：如果执行对象已经在平台上发布，这条动作无效，必须重写。

### 2.8 面向用户表达

这份清单是给内容创作者看的，不是内部工作记录。正文和页面数据区都不得出现：

- 内部内容 ID（如「内容1013」「内容610」）；
- 内容编号区间（如「1013-1015」）；
- 文档文件名、JSON 字段名、暂存路径。

引用已有作品时，写作品标题并附公开链接；作品未公开或没有链接时，写标题并注明「未公开」。引用多条时逐条列出，不合并成编号区间。步骤里引用作品同样用标题和链接，不写编号。

涉及历史内容数量时，写用户能核对的说法（如「已发布但未公开的内容」），不写系统内部统计口径。

### 2.9 边界

- 不修改账号方向或规划；发现规划需要调整时，只在「本轮依据」里提示，不直接改写。
- 不承诺未经验证的增长、获客或成交。
- 需要改变定位、用户或商业结构的，只写成「需要讨论的方向」，不进入行动清单。
- 诊断关键问题为 0 个时写 1 条维持型行动，不硬造整改任务；动作挂不上关键问题就少写，但不低于 1 条。

## 4. 页面数据区规则

- `account-action-list` 标记和 JSON 代码块必须只有一份。
- JSON 必须与正文一致。
- `对应诊断` 写诊断文档的文件名，不写路径。
- `行动` 为 1 到 3 条，`ID` 从 A1 开始连续编号；不允许空数组。
- `方向` 必须取自 2.2 的方向名，不得自造或留空。
- 参考做法只能取自本轮《行动参考候选》，一条动作最多 1 条；候选里没有合适项时写 `无`。
- 参考做法里的作品标题照抄候选里的 `标题`（连标点一起），工作台用它定位站内那条作品；标题对不上时，页面上只保留做法说明，不显示作品卡，也不跳平台外链。
- `做法说明` 必须来自候选里的 `实例证据`，不得把候选之外的推断补进去；候选为空时所有动作的参考做法都写 `无`。
