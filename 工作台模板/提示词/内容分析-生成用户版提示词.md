# 内容分析-生成用户版提示词

## 1. 任务

依据当前分析输入快照中的正文、封面、互动数据和已存档评论，一次性写出完整的 `内容分析.md`。

报告按「用户拿它做内容」的需要组织，不按分析方法组织：先写这条内容最值得学什么，再还原内容定位与内容框架，然后说明观众在评论里反馈了什么，最后给出可借鉴与不能照搬的判断。表现、动作、策略、内核、验收链路和数据校正只用来支撑这些结论，不单独成节，也不把分层术语写进标题。

## 2. 处理规则

不读取或使用 `我方当前概要.md`。本报告只分析对标内容本身。

当前分析输入快照中的原始标题、正文证据、正文获取状态和可用封面信息是判断的直接证据。不得依赖模型在上一轮中可能保留的上下文、历史暂存文件或外部资料。

### 成稿规则

- 初判提供分析骨架，但不是必须照抄的正文。
- 数据只用于支持、削弱或限制判断，不把高数据直接等同于高质量。
- 数据缺失时写 `无法验证`，不得补造数字或反馈。
- 封面可用不等于已经读图。只有在当前任务中实际读取封面后，才能写封面中的文字、人物、场景、信息层级和可观察钩子；应先读图，再写这些视觉判断。
- 不能读图、读图工具失败、模型不支持或封面不可用时，正文和数据分析继续，但必须明确“视觉未参与结论”。此时不得根据文件路径、标题、旧上下文或猜测补写任何具体视觉细节；只把视觉相关判断降级为 `信息不足`。
- `正文获取状态 = 确认无正文` 时，基础信息如实写明；正文状态标记不是作者正文。只能基于标题、已实际读取的可用封面和互动数据做有限分析；未实际读图时视觉不参与结论。正文结构、表达、价值兑现等无法得到证据的判断写 `信息不足`。
- `数据校正` 只写真正影响结论的部分，不逐项制造形式化对比。
- 正式结论必须前后一致，不能一处说成立、另一处无解释地否定。
- 四维借鉴判断只分析对标内容本身，不判断是否适合我方当前阶段。
- 对标内容无法确认作者原始目标，不判断 `主目标侧重`；我方内容生产仍按原规则在 `流量 / 涨粉 / 交易` 中确定。
- `内容定位` 的主题、核心命题、切口、目标用户、核心痛点和收益承诺必须逐项填写且各出现一次；证据有限时写清判断边界，不能删掉字段。
- 每个维度的结论只能是 `值得借鉴` 或 `不值得借鉴`，允许在结论后补充解释；可借鉴内容缺失时由程序写入 `待补充` 并告警。
- 四维借鉴必须逐维独立判断：每一维都必须有独立的内容证据，不能因为一个优点或同一条笼统证据就推出四维全正；证据不足时如实写 `不值得借鉴`，并在总体结论说明边界。
- 四维判断与表现数据存在冲突时，必须解释冲突、降低结论确定性并复核内容证据，不得静默忽略。普通或缺失数据只降低确定性，不能自动推出 `不值得借鉴`。
- 四项均为 `值得借鉴` 前，必须逐维复核证据与数据校正是否一致；充分独立证据支持时允许四项全正，不得为了形式制造负面结论。
- 不生成优先级，不把四维判断再压成一至三个动作。
- 不输出优化方案、我方行动建议或过程说明。
- 只写读者能直接看懂的结论和做法；不使用 `表现层 / 动作层 / 策略层 / 内核层` 这类分层术语当标题，也不复述分析过程。
- `内容框架` 与内容生产的框架用**同一套划分**：进入 / 主体 / 结尾。第一行是 `进入`，最后一行是 `结尾`，中间是主体，逐段写成 `第 N 段｜功能名称`；功能名称压成一个短词（2～4 个字，如「立信任」「举证」「给替代」「接反对」「收束」），只写这一段在整条内容里承担的任务，不写话题名，也不写「拍摄计划与全流程收束」这种把几个动作连起来的长短语，最多 6 个字。
- `模块` 列只写 `进入 / 第 N 段｜功能名称 / 结尾`，不写这一段讲了什么，也不写怎么设计；可观察的内容事实写在 `讲了什么`，写法、顺序和举证方式写在 `怎么设计的`。
- 主体按**职责**切，不按话题或句子切：一段只承担一个职责并给出新信息；同一职责里的多个小步骤（例如「反问 → 举例 → 立主张」同属「拆前提」）写在同一段里，不各占一行。判据沿用内容生产的成立标准——**每段有独立职责和新信息，不能任意调换顺序**；两段职责相同、可以互换，就合并成一段。
- 自检：如果某一段的 `怎么设计的` 只能写出一句话，通常是拆多了，把它并进相邻段。
- 段数随内容本身变化，不预设：口播、对谈这类自由推进的内容，主体通常只有三到五段；按理论层或模块逐层展开的长内容才可能到八段以上。不要为了「拆得细」而加段。
- `讲了什么` 只写可观察的内容事实：标题、封面、开场句、例子、数据、结论；不复述设计意图，也不写作用判断。
- `怎么设计的` 必须写可观察的写法，不重复 `讲了什么`：进入要写清它怎么把观众拉进来（先给什么、门槛压到什么程度、有没有铺垫背景或自我介绍）；主体每段要写清它怎么举证、怎么递进（先给框架还是先给例子、例子怎么用、有没有把结论落成能直接拿去用的东西）；结尾要写清收束和动作是怎么设计的。
- `作用与前后衔接` 写这一段对用户起什么作用（愿意点开 / 愿意继续看 / 愿意相信 / 真的拿到 / 留下印象或动作），以及承接上一段什么、给下一段留下什么。
- 这两列都不能写「先讲背景再讲重点」「承上启下」这类放到任何内容里都成立的空话；写不出具体做法就写 `信息不足`。
- 框架只写可观察的做法，不推断作者意图、不做效果归因（不写「这样写很有效」「因为用户喜欢」）。

### 评论分析规则

- 评论证据只来自当前输入快照给出的已存档评论文件；没有评论文件、文件不可读或评论数与文件不一致时，第 5 节写「本次没有可用的评论样本」，不得凭空概括观众反馈。
- 只统计一级评论；文件里记录的回复随原评论一并看，不单独计数。
- 按评论主要在说什么归并成方向，方向数量按实际内容决定，不为凑数拆分或合并；每个方向写清条数、这一组在说什么，并用一条最短的代表原话作证据。
- 条数只统计本次样本内明确属于该方向的评论；估算、跨方向重复计数一律不允许。
- 样本只是部分评论时，必须写明「本次样本 N 条 / 平台声明 M 条，占比按样本算」，不把样本结论说成全量结论。
- 评论里的事实（例如「求链接」「报自己在第几层」）可以直接引用；观众动机、真实感受等推断必须标明是推断。
- 没有足够信息形成任何方向时，第 5 节只保留样本说明并写「有效反馈不足」，不硬凑方向。

## 3. 输出格式

严格按下面结构直接输出正文：

```markdown
# 内容分析

> 依据：<一行说明本次判断依据的资料范围，以及哪些信息未经核验>

## 1. 基础信息

- 内容ID：
- 标题：
- 平台：
- 媒介形式：
- 正文获取状态：已获取 / 确认无正文
- 关键数据：点赞 / 收藏 / 分享 / 评论
- 数据水平：

## 2. 这条内容最值得学什么

**<一句话写出这条内容最值得学的那一点>**

<用一两句说明原作具体怎么做的，把判断落到看得见的做法上。>

**优先借鉴：<值得优先学什么>**

<说明不该优先学什么，避免把说法、口令或表面动作当成价值。>
```
