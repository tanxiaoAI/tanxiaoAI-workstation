# 自我账号诊断成稿提示词

## 1. 任务

根据我方规划（或回退的调查问卷）、账号实际证据、创作者中心数据、评论原文、上一版诊断和上一次行动清单，生成可直接保存的完整账号诊断正文。当前概要只是规划摘要，可用于快速了解背景，不作为目标判断基准。

诊断回答的不是“这个账号是什么样”，而是：**我原本想做成什么、现在实际做成了什么、最关键的问题是什么。**下一步怎么改由《账号改进行动清单》承接，本文不写行动方案。

## 2. 处理规则

### 表达要求（全篇强制）

- 用普通内容创作者能直接听懂的大白话，像当面告诉用户“现在怎么样、问题在哪里、为什么”。不要写成咨询报告、研究摘要或内部黑话。
- 每句尽量写清“谁做了什么或没做什么，带来了什么结果”，一句只讲一件事；不要把多层意思压缩成抽象名词。
- 用户可见正文不得使用“主矛盾、内容资产、放量、判断主线、连续供给、转化证据、承接、公开面、存量、内容线、判断线、闭环、抓手、链路”等内部或咨询化词语。必须换成具体的人、内容、动作和结果，例如把“旧内容资产仍在放量”写成“以前发的《[标题]》到现在还有人点赞收藏”。
- 平台指标名可以保留，如“2 秒退出率”“完播率”，但要紧接着说明它代表什么，例如“很多人点进来不到 2 秒就离开了”。
- `综合诊断.文本` 只写三句，每句不超过 25 个字，三句合计不超过 60 个字：
  - 第一句：现在最该改的那一个问题；
  - 第二句：这个问题最直接的原因，只放一个最硬的数字、日期或事实；
  - 第三句：接下来最该做的那一个动作。
- 三句都只留结论：不写背景、不复述数据、不解释为什么这么判断。第二句必须直接解释第一句，不许换话题、不许罗列其他指标；第三句要能直接照着做，不写“加强”“优化”“多注意”。
- `综合诊断.重点短语` 写 2 到 3 个，必须逐字摘自综合诊断文本，单独拿出来也能看懂；不得重复“问题类型”，不得使用抽象概括。
- 其他章节同样使用大白话，不得只把综合诊断写得直白，后文继续堆术语。
- `目标与实际` 不得用内容编号或 ID 指代内容，必须写可识别的《内容标题》；标题过长时可保留关键部分，同名内容用发布日期区分。内容编号只能留在最后的数据依据中，不得出现在这一节的结论、原因和建议里。
- `目标与实际` 的每个维度都要说清“原本想要什么、现在实际是什么、具体差在哪里”；建议要直接说哪些旧内容保留、转私密或删除，以后哪类内容要增加或减少，不写“连续供给”“让内容承担定位”这类空话。
- 输出前逐句自检：不了解本系统、没读过规划原文的人如果看不懂或无法复述，就必须重写。

错误示例（只有抽象名词，看不出谁做了什么、结果是什么）：旧内容资产仍在放量，新的判断主线没有形成连续供给。

正确示例（只给句式，不填具体结论）：这个账号的《[标题]》《[标题]》到现在还在带来互动，但最近发的是 [哪一类]，不是 [规划要求的那一类]；新访客打开主页先看到 [这几条代表的方向]，会把账号当成 [什么账号]。

> 上面两行只用来对照「说人话还是说黑话」，示例里的具体判断**不得当成本轮结论套用**。综合诊断第一句只留一个这个账号才有的事实，不并列。上面那条长句只示范怎么把黑话换成事实，**不是综合诊断的长度样板**。

**三句对得上（强制）**：综合诊断的三句是一条线，不是三件互不相干的事，而且每句都只到结论为止。

- 错误示例（第二、三句换了话题）：第一句说「新内容没能持续发」，后面却在讲「只有一条在讲判断」「点进来的人平均只看 2 秒多」——第一句说的是发的频率和连续性，后两句讲的是内容类型和观看时长，谁都没解释为什么发不出来。
- 错误示例（啰嗦）：第一句写成「主页上 7 条公开内容里只有 1 条在讲判断，新访客看到的多是工具演示和『我做了这套工作台』的自述」——一句塞了三层意思，后半截还替读者解释了一遍。
- 正确示例（只给句式，照这个长度写）：
  - 现在最该改的是［哪件事］没做到。
  - 最近一条发在［日期］，之后［多少天］没更新。
  - 下一条就写［哪一个具体卡点］，［什么时候］发出来。

**反模板自检（强制）**：第二句和第三句必须带这个账号才有的东西——具体日期、具体数字、具体内容标题；把这些去掉之后还照常成立，就是空话，要重写。第一句是概括，可以不写数字，但不能用「执行不足」「需要加强运营」「优化内容方向」这类换个账号也一样的空词。

### 判断基准

目标基准按账号是否有历史正式诊断分两档：

1. 该账号没有历史正式诊断（首次诊断）：默认用 `我方资料/调查问卷.md` 的原始回答，`我方资料/我方自媒体规划.md` 不参与本轮目标判断；如果本轮指令明确说明规划刚刚按同一份新问卷更新，并要求以新规划为判断基准，则改用 `我方资料/我方自媒体规划.md`。
2. 该账号已有正式诊断（新一轮诊断）：优先 `我方资料/我方自媒体规划.md`；规划不存在或不可用时，回退 `我方资料/调查问卷.md` 的原始回答。

- `我方资料/我方当前概要.md` 只是规划的摘要，不是独立判断基准，也不参与回退。
- 不得把规划和问卷拼成两套并行目标；本轮用了哪一份，就在第 5 节如实写明。
- 规划和问卷都不可用时，写 `判断基准不足`，按通用账号诊断继续，但不得把通用判断写成个人适配结论。
- **判断基准与账号实际方向完全不一致不是停止条件**：必须照常生成完整诊断，`目标与实际` 三个维度写 `不一致`，问题类型归入 `方向偏差`，并继续保存。只有账号、内容证据或基准文件本身不可用（读不到、样本不足、身份不一致）时才停止。

### 样本口径

- **目标与实际看当前公开面全量**：使用诊断输入快照里的 `public_face`（全部公开内容的标题、发布时间、互动分布），不只看最近几条。历史存量内容只给处置建议（转私密 / 删除 / 保留），不在每轮重复分析它的问题。
- **这段时间的变化只看新增内容**：使用 `new_since_previous_diagnosis_ids`，即上次正式诊断日之后发布的公开内容。没有历史诊断时，写 `首次诊断`。
- **指标只看新增**：互动、完播、2 秒退出等指标只统计上次诊断后新增的公开内容，不混入历史内容，也不展示全量基线；新增少于 3 条时明确写样本不足，不据此外推趋势。
- **指标对比看同口径**：判断改善或恶化时，上期和本轮必须是同一指标、同一统计范围；上一版诊断没有同口径数据时，写“这次第一次看到”，不判断方向。
- 公开面全量只用于定位判断，不等同于正文级证据；正文级判断仍只使用本轮通过校验的原文案证据。

### 证据使用

- 账号资料、内容列表、已读取正文、创作者中心数据、评论原文、用户补充反馈都可以作为证据。
- 创作者中心账号级数据只代表平台实际统计周期；内容级数据只代表本轮可见笔记。缺失时写 `未获取`，不得写 0，也不得用公开页数据替代。
- 评论文本只来自正式 `评论.md` / `评论.json`；评论数为 0、评论为空、抓取失败要分别说明，不能互相替代。
- 单条高互动内容不能证明方向正确；单条低数据也不能直接证明方向错误。
- 没有正文级证据的内容，只能根据标题、形式和互动数据判断表层分布，不能推断其观点、结构和表达质量。
- 封面、主页和视觉风格只能使用当前实际读取的图片；未读图时写 `视觉未参与结论`。
- 没有咨询、私信、成交记录时，不能判断真实转化成立或失败。

### 问题分类

只使用三类：

- `方向偏差`：实际账号正在走向与判断基准（规划或调查问卷）不同的方向。
- `执行不足`：方向正确，但内容结构、发布节奏、表达或承接没有做到位。
- `证据不足`：当前材料无法支持稳定结论。

### 这段时间的变化

这一段只回答一个问题：**跟上一次比，是变好了、变差了，还是没变；没变的话，现在到底处在什么水平。** 不记录用户自己就知道的发布事实，也不做没有判断的数据对比。

- 必须同时看三样东西：上一版正式诊断（上次认定的问题）、上一次《账号改进行动清单》（上次让你做的事）、上次诊断日之后新增的公开内容及其指标。缺哪一样，就在对应位置写明看不出来的部分。
- 上一版诊断只用来判断“上次的问题这次还在不在”，不得复述它的句子、复用它的小标题；写出来的每一句都要用本轮数据重新支撑。
- 本轮行动清单在诊断之后才生成，不能拿来当这段变化的依据。
- 写 2 到 4 条，每条只讲一个方面。每条先给 `结论`，取值为 `变好`、`变差`、`没变`、`仍然差`、`无法比较` 之一；再用 `文案` 写一段完整的话，先说结论，再用最关键的证据说清为什么。
- 结论必须明确说好还是坏。不允许只写“公开内容从 5 条变成 7 条”“新增了 2 条”这类事实却不给判断，用户自己发了什么自己知道。
- `文案` 只保留支撑判断的证据：关键条数、具体内容标题、发布时间或同口径指标数值。不罗列完整清单，也不把上一轮和这一轮的全部数据重抄一遍。
- 说变好或变差时，必须同时给上次和这次的同口径数值。上次没有同口径数据时，`结论` 只能写 `无法比较`，文案里写清当前实际水平，例如“目前开头留不住人，但上次没有这项数据，不能判断是不是这段时间变差的”。
- 数据和内容要一起看：数据变好不能单独证明做法有效，数据变差也不能单独证明方向错了。
- 上次诊断后新增内容少于 3 条时，只描述这几条，不往外推成趋势。
- 区分“新发生”和“新发现”：这次才拿到的数据暴露的问题写“这次第一次看到”，不能写成这段时间新出现的问题。
- 没变化、也不值得单独说的方面直接不写，不按“改善了 / 还在 / 新增了”凑齐。
- 不写「上次行动核对」小节，也不逐个核对上一次行动清单执行到哪一步；上次行动清单只用于判断问题有没有变化。

### 收束规则

- 关键问题取 0 到 3 个，不罗列所有小问题。
- 账号方向正确、执行正常、当前没有值得优先处理的问题时，`关键问题` 写空数组，并在正文明确写“当前未发现需要优先处理的关键问题，按现有方向继续发布并观察”，不得为了凑结构硬造问题。
- 本诊断只回答问题是什么，不写行动方案；具体动作由《账号改进行动清单》承接。
- 这段时间的变化只和上一版诊断、上一次行动清单比较；没有历史时写 `首次诊断`。

## 4. 页面数据区规则

- `self-account-diagnosis-summary` 标记和 JSON 代码块必须只有一份，位置固定在标题之后。
- JSON 必须与正文一致；正文写不出的字段不得在 JSON 里补造。
- `账号ID`、`账号名` 必须与输入一致。
- `关键问题` 允许 0 到 3 条；0 条时正文必须明确写“当前未发现需要优先处理的关键问题”。
- `这段时间的变化` 的 `总体` 只是概括标签，必须由 `变化` 支撑；`变化` 为空只能用于 `首次诊断`。
- 不是首次诊断时，`变化` 写 2 到 4 条，`方面`、`结论`、`文案` 三项必填，`结论` 只能取 `变好`、`变差`、`没变`、`仍然差`、`无法比较` 之一。
- 首次诊断时，`变化` 写空数组，正文不写变化小节。
- 正文第 3 节的小节标题必须和 `变化` 一一对应，顺序为「变化 N：[方面]」；每个变化小节下只写一段完整描述，不再拆成「哪里变了 / 证据 / 说明什么」三行。
- 第 3 节不写「上次行动核对」，JSON 里也不写 `上次行动核对` 字段。
- `目标与实际` 固定三个维度：目标用户、账号定位、内容主线；每个维度只写 `结论`、`原因`、`建议`，不写证据。
- `本轮依据与边界` 十项必须齐全；判断基准只能写调查问卷、我方自媒体规划或判断基准不足；首次诊断必须写调查问卷；`已获取内容` 和 `公开与私密范围` 必须写明公开面条数，以及其中上次诊断后新增的条数。
- 没有足够内容证据时，`结论` 写 `暂无法判断`，不得强行写 `一致` 或 `不一致`。
- 不写 `优先行动`、`一句话结论`、`账号与内容表现` 这三个字段；原始数据归账号概览，行动归《账号改进行动清单》。
